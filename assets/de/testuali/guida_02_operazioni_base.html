1. LADEN VON DATENSÄTZEN - EINGABEFORMATE

────────────────────────────────────────────────────────────────────────────────

📥 EINGABESTRUKTUR UND UNTERSTÜTZTE PORTALE

ATK-Pro akzeptiert Eingabedateien in einem spezifischen, auf PAAREN basierenden Format: Für JEDEN zu verarbeitenden Datensatz gib Modus + URL an.

Unterstützte Portale: Kopiere die öffentliche URL der Seite, des Viewers, des Manifests oder der kompatiblen PDF-Datei und füge sie ein. ATK-Pro erkennt das Portal und wendet den entsprechenden technischen und vorsichtigen Modus an.

Unterstützt bezeichnet eine verifizierte technische Kompatibilität, keine uneingeschränkte Genehmigung zum Download. Die Ressource muss öffentlich zugänglich sein, und der Benutzer muss Rechte, Lizenzen, Nutzungsbedingungen und Beschränkungen des jeweiligen Portals beachten. ATK-Pro umgeht keine Logins, institutionellen Zugänge, Paywalls oder Markierungen nodownload.

Antenati (Italien), Gallica (Frankreich), DigiVatLib (Vatikan), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Südtirol), e-codices/e-rara/e-manuscripta (Schweiz), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo und Internet Archive.

1. ZEILE 1: Modus + Name (optional)

  • D = Einzeldokument (ein einzelnes Bild/eine einzelne Seite)
  • R = Register (vollständige Sammlung von Seiten/Dokumenten)

2. ZEILE 2: Öffentliche URL des Datensatzes oder der Ressource

Beispiel für eine korrekte Datei input.txt:

# Kommentare beginnen mit #

DATENSATZ 1 (Zeilenpaar):
D - Wichtiger Brief
https://biblioteca.example.org/iiif/doc123/manifest.json

DATENSATZ 2 (Zeilenpaar):
R - Verwaltungsregister 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

DATENSATZ 3 (Zeilenpaar):
D - Einzelnes Foto
https://collections.example.org/iiif/foto789/manifest.json

📝 REGELN FÜR DAS EINGABEFORMAT:

  • Leerzeilen: werden ignoriert (du kannst sie zur besseren Lesbarkeit verwenden)
  • Zeilen mit #: werden als Kommentare ignoriert
  • Modus D/d oder R/r: ist obligatorisch; Groß- und Kleinschreibung sind gleichwertig
  • Dateiname: optional nach dem Modus (z. B. "D - Name" oder nur "D")
  • URL: muss mit http:// oder https:// beginnen
  • Paare: Modus + URL müssen in aufeinanderfolgenden Zeilen stehen

⚙️ SO WIRD DIE EINGABE GELADEN - 3 OPTIONEN IM MENÜ:

OPTION 1: Eingabebeispiel anzeigen ──────────────────────────────────────

1. Klicke auf Menü → "Eingabedatei" → "Eingabebeispiel"

2. Es öffnet sich ein Fenster, das die lokalisierte Beispieldatei anzeigt

3. Du kannst den Inhalt als Vorlage für deine Eingabedatei kopieren

4. Beispieldatei: assets/[lingua]/testuali/input_link_base.txt

Hinweis zum Dateinamen: Die mitgelieferte Datei heißt input_link_base.txt. Der Name wurde in v3 vereinheitlicht, um Verweise auf frühere Versionen zu vermeiden; das Format bleibt mit dem Laden von IIIF-Datensätzen kompatibel.

OPTION 2: Vorbereitete Eingabedatei öffnen ──────────────────────────────────────

1. Klicke auf Menü → "Eingabedatei" → "Eingabe öffnen"

2. Ein Dialog zur Dateiauswahl wird geöffnet

3. Wähle deine Datei input.txt aus (sie muss dem Paarformat entsprechen)

4. ATK-Pro lädt die Datei automatisch und liest alle Datensätze ein

5. Die Anzahl der geladenen und zur Verarbeitung bereiten Datensätze wird angezeigt

OPTION 3: Bereits geladene Eingabe bearbeiten ──────────────────────────────────────────

1. Nachdem du eine Eingabedatei geladen hast (OPTION 2)

2. Klicke auf Menü → "Eingabedatei" → "Eingabe bearbeiten"

3. Ein Texteditor mit der aktuell geladenen Datei wird geöffnet

4. Bearbeite die Paare (hinzufügen, entfernen, URL ändern)

5. Klicke auf "Speichern", um die zu verarbeitenden Datensätze zu aktualisieren

6. Das Programm interpretiert die aktualisierte Datei neu

📌 UNTERSCHIED ZWISCHEN D UND R:

  • D (Dokument): Verarbeitet ein einzelnes Bild/eine einzelne Seite
  • → Ausgabe: eine einzelne Datei für das Dokument
  • R (Register): Verarbeitet mehrseitige Sammlungen
  • → Ausgabe: Ordner mit organisierten Seiten + PDF (wenn vom Benutzer angefordert)

✅ VALIDIERUNG DER DATENSÄTZE

Nach dem Laden prüft das Programm:

  • ✓ URL ist zugänglich und erreichbar
  • ✓ Kompatible Ressource: IIIF-v2/v3-Manifest, unterstützte Seite, Bild oder direkte PDF-Datei je nach Portal
  • ✓ Anzahl der verfügbaren Bilder und Canvas
  • ✓ Metadaten (Titel, Autor, Datum)

❌ HÄUFIGE FEHLER

  • "Ungültige URL": Kopieren/Einfügen der URL überprüfen
  • "Manifest nicht gefunden (404)": Die URL ist abgelaufen oder falsch
  • "IIIF-Format nicht unterstützt": Der Server verwendet kein standardkonformes IIIF
  • "Zeitüberschreitung bei der Verbindung": Internetverbindung langsam/nicht vorhanden

💾 SPEICHERN DER DATENSÄTZE

Nach dem Laden des Manifests speichert das Programm die IIIF-Metadaten automatisch. WO: Im von dir gewählten Ausgabeordner (siehe Abschnitt 2, SCHRITT 2) ORDNERSTRUKTUR NACH DEM LADEN (vor der Verarbeitung):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Originales IIIF-Manifest (Hauptebene)
 └─ [nome]/                            ← Unterordner NUR für Metadaten
    ├─ [nome]_genealogico.json        ← Extrahierte genealogische Metadaten
    └─ [nome]_tecnico.json            ← Technische Metadaten (Canvas-ID, Seitenanzahl)

NACH DER VERARBEITUNG (wenn du auf Menü → Ausgabe → Verarbeiten klickst): Auf der Hauptebene werden die verarbeiteten Dateien hinzugefügt:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Originales IIIF-Manifest
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Aus IIIF-Tiles rekonstruierte Bilder (eines pro Seite)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (Format hängt von der Auswahl ab)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = Gesamtanzahl der Seiten/Canvas)
 ├─ [nome].json                        ← JSON-Sidecar für jedes Bild (EXIF-Metadaten)
 └─ [nome].pdf                         ← Vollständige PDF-Datei (siehe Erläuterung unten)

Die Metadaten verbleiben im Unterordner [nome]/, so wie sie beim Laden gespeichert wurden.

WICHTIGER HINWEIS: Dateiorganisation

  • IIIF-Manifest: Hauptebene des Ausgabeordners
  • Bilder (Canvas), PDF, JSON-Sidecar: Hauptebene des Ausgabeordners
  • NUR technische und genealogische Metadaten: im Unterordner [nome]/ gespeichert
  • Die temporären Ordner (tiles_canvas_X/) werden nach Abschluss automatisch gelöscht
  • Diese Struktur ermöglicht es, mehrere Datensätze ohne Verwechslungen im selben Ordner zu verwalten

Beispiel: Wenn du "Register1" verarbeitest, findest du:

  • manifest_[ID1]_Registro1.json (Hauptebene)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (Hauptebene)
  • Registro1.pdf (Hauptebene)
  • Registro1/ (Unterordner NUR mit genealogischen und technischen Metadaten)

2. VERARBEITUNG UND BILDDOWNLOAD

────────────────────────────────────────────────────────────────────────────────

🎯 VERARBEITUNGSABLAUF

Der Verarbeitungsworkflow umfasst 3 Schritte:

SCHRITT 1: BILDFORMATE AUSWÄHLEN

─────────────────────────────────────

1. Lade eine Eingabedatei (Eingabedatei → Eingabe öffnen): Das Fenster zur Formatauswahl wird automatisch geöffnet

2. Alternativ: Klicke auf Menü → "Einstellungen" → "Bildformate auswählen"

3. Ein Dialogfenster mit 3 Optionen wird geöffnet:

☐ PNG → Verlustfreies Format (lossless), beste Qualität, größere Dateien

☐ JPG → Komprimiertes Format (lossy), guter Kompromiss zwischen Qualität und Dateigröße

☐ TIFF → Archivformat, höchste Qualität, sehr große Dateien

PDF-Dokument

☐ PDF → Erstellt zusätzlich zu den ausgewählten Bildformaten eine vollständige PDF-Datei mit allen Seiten des Registers oder Dokuments (oder als einzige Ausgabe, wenn kein Bildformat ausgewählt ist)

4. Wähle mindestens ein Bildformat oder PDF aus (du kannst mehrere auswählen)

5. Klicke auf "Bestätigen"

✅ Die ausgewählten Formate werden gespeichert und beim nächsten Start des Programms automatisch vorausgewählt.

📝 EMPFEHLUNGEN:

  • Für Vorschau/Konsultation: JPG (schnell zu öffnen, geringerer Speicherbedarf)
  • Für die archivische Langzeitaufbewahrung: PNG (lossless, guter Kompromiss beim Speicherbedarf) oder TIFF (höchste Qualität)
  • Für beides: sowohl PNG als auch TIFF auswählen
  • Für PDF: PDF zusammen mit einem oder mehreren Bildformaten auswählen oder nur PDF auswählen, um ausschließlich das PDF-Dokument ohne separate Bilddateien zu erstellen

SCHRITT 2: AUSGABEORDNER AUSWÄHLEN

──────────────────────────────────────

1. Das Ordnerfenster öffnet sich automatisch nach der Auswahl der Formate (wenn du eine Eingabedatei lädst)

2. Alternativ: Klicke auf Menü → "Einstellungen" → "Ausgabeordner auswählen"

3. Wähle den MODUS für die Organisation der Ordner:

⬤ Ein Ordner für alle → ein einziger Ordner für alle Datensätze (Dokumente und Register)

⬤ Separate Ordner für Dok./Reg. → ein Ordner für alle Dokumente, einer für alle Register

⬤ Ordner für jeden Datensatz → ein eigener Ordner für jeden Datensatz in der Eingabedatei

4. Wähle nach der Auswahl des Modus die erforderlichen Ordner aus (1, 2 oder N Dialogfenster)

5. Am Ende wird eine Zusammenfassung der ausgewählten Ordner angezeigt

✅ Modus und Ordner werden gespeichert. Beim nächsten Öffnen einer Eingabedatei werden sie automatisch wiederhergestellt, sofern sie mit der Anzahl der Datensätze kompatibel sind.

⚠️ Wenn die neue Eingabedatei eine andere Anzahl von Dokumenten/Registern als die gespeicherten Ordner aufweist, wird ein Hinweis angezeigt und die Auswahl zurückgesetzt, damit neue Ordner ausgewählt werden können.

🛡️ Vorabprüfung der Pfade: Bevor Ordner oder Dateien erstellt werden, überprüft ATK-Pro die vorgesehenen Namen und Pfade. Mit Windows inkompatible Namen und übermäßig lange Pfadsegmente blockieren nur den jeweils betroffenen Datensatz; Kompatibilitätshinweise werden in der abschließenden Zusammenfassung angezeigt.

☁️ OneDrive/SharePoint wird nicht als Standardziel angenommen. Die entsprechenden Beschränkungen werden nur angewendet, wenn sich der ausgewählte Ordner tatsächlich unterhalb eines OneDrive-Stammverzeichnisses befindet. Bei anderen Pfaden wird die historische Windows-Grenze von 260 Zeichen als vorsorglicher Hinweis und nicht als automatische Sperre behandelt.

📌 ZUSAMMENFASSUNG DER MODI:

  • Ein Ordner: Einfach, alles an einem Ort. Geeignet für schnelle Verarbeitungen oder Tests
  • Separate Dok./Reg.: Organisation nach Typ. Standard: output/doc/ und output/reg/
  • Für jeden Datensatz: Maximale Flexibilität. Du kannst verschiedene Laufwerke, NAS oder benutzerdefinierte Ordner verwenden

SCHRITT 3: VERARBEITUNG STARTEN

─────────────────────────────

1. Klicke auf Menü → "Ausgabe" → "Verarbeiten"

2. Prüfe, dass:

✓ Mindestens 1 Bildformat ausgewählt ist

✓ Mindestens 1 Datensatz geladen ist

Wenn diese Voraussetzungen nicht erfüllt sind, erscheint eine Fehlermeldung:

❌ "Kein Format ausgewählt" → Gehe zu SCHRITT 1

❌ "Kein Datensatz geladen" → Gehe zu Eingabe laden (Abschnitt 1)

📺 VERARBEITUNGSFENSTER

Sobald du auf "Verarbeiten" klickst, öffnet sich ein modales Fenster mit:

📊 SICHTBARE ELEMENTE:

1️⃣ FENSTERTITEL: "Verarbeitung läuft"

  • Bleibt im Vordergrund, bis die Verarbeitung abgeschlossen ist
  • Du kannst nicht mit dem übrigen Teil der GUI interagieren

2️⃣ FORTSCHRITTSANZEIGE: "Datensatz wird verarbeitet: 2/5 — Dateiname"

  • Zeigt: aktuell verarbeiteter Datensatz (2) von insgesamt (5)
  • Zeigt außerdem den Namen der gerade verarbeiteten Datei/des Registers
  • Wird während der Verarbeitung der Datensätze in Echtzeit aktualisiert
  • Bsp.: "Datensatz wird verarbeitet: 1/3 — Heiratsregister 1850"

3️⃣ FORTSCHRITTSBALKEN: Visuelle Fortschrittsanzeige

  • Numerisches Format: "2/5" (aktuelle Anzahl / Gesamtanzahl)
  • Farbbalken, der sich von links nach rechts füllt
  • Erreicht bei Abschluss 100 % (maximale Breite)
  • Zeigt KEINE Prozentzahl, sondern nur die Anzahl

4️⃣ SCHALTFLÄCHE [ABBRECHEN]

  • Während der Verarbeitung anklickbar
  • Fordert den Abbruch des gesamten Batches an und schließt das Fortschrittsfenster
  • Der Abbruch erfolgt kooperativ: Möglicherweise wird noch der Abschluss einer bereits laufenden einzelnen Netzwerkanfrage abgewartet
  • Keine Ausgabe der abgebrochenen Sitzung wird im ausgewählten Ordner veröffentlicht; bereits vorhandene Dateien bleiben unverändert

🔄 WÄHREND DER VERARBEITUNG

Das Programm führt im Hintergrund Folgendes aus:

├─ Lädt Bilder von IIIF-Servern herunter
├─ Liest das Manifest für die Canvas-ID
├─ Rekonstruiert Tiles zu vollständigen Bildern
├─ Konvertiert in die ausgewählten Formate (PNG, JPG, TIFF)
└─ Speichert in den ausgewählten Ordnern

Die GUI zeigt den Fortschritt in Echtzeit an:

  • Alle 2-3 Sekunden wird die Anzahl der Datensätze aktualisiert
  • Kein Blockieren: Die Benutzeroberfläche bleibt reaktionsfähig
  • Du kannst jederzeit abbrechen

⚠️ VERHALTEN BEIM KLICKEN AUF ABBRECHEN:

1. Der kooperative Abbruch des gesamten Batches wird angefordert

2. Alle vom abgebrochenen Batch erzeugten temporären Ausgaben werden gelöscht

3. Dateien, die sich bereits vor dem Start in den Ausgabeordnern befanden, bleiben unverändert

4. Du kannst über Menü → Ausgabe → Verarbeiten erneut beginnen

📋 PDF — AUTOMATISCHE ERSTELLUNG WÄHREND DER VERARBEITUNG

Wenn du PDF in der Maske zur Formatauswahl (SCHRITT 1) ausgewählt hast, wird die PDF-Datei nach Abschluss des Downloads jedes Registers oder Dokuments automatisch erstellt, ohne zusätzliches Bestätigungsfenster.

📌 VERHALTEN:

  • ✅ PDF in der Formatmaske ausgewählt: Die PDF-Datei wird nach Abschluss des Downloads automatisch erstellt; es wird keine zusätzliche Bestätigung verlangt
  • ❌ PDF nicht ausgewählt: nur die Bilder in den ausgewählten Formaten, keine PDF-Datei

Merkmale der erzeugten PDF-Datei:

  • Dateiname: [nome].pdf, ohne zusätzliche Suffixe (z. B. Registro Matrimoni 1920.pdf)
  • Im ausgewählten Ausgabeordner gespeichert, auf derselben Ebene wie die Bilder
  • Seiten in aufsteigender numerischer Reihenfolge (Canvas 1 → Canvas 2 → … → Canvas N)
  • Wenn ein Canvas nicht heruntergeladen werden kann, wird eine placeholder -Seite in der ausgewählten Sprache mit direktem Link zum ursprünglichen Canvas auf Antenati eingefügt
  • Nach Abschluss der Erstellung verbleiben keine temporären Dateien im Ausgabeordner

⚠️ WAS DU WÄHREND DER VERARBEITUNG NICHT TUN SOLLTEST:

  • ❌ Das Programm nicht schließen (Teildateien gehen verloren)
  • ❌ Externes Laufwerk nicht trennen (Speicherfehler)
  • ❌ PC/Laptop nicht ausschalten
  • ❌ Internetverbindung nicht trennen (Download wird gestoppt)

✅ WAS DU TUN KANNST:

  • ✓ Warten, bis der Vorgang abgeschlossen ist (dies ist das normale Verfahren)
  • ✓ Bei Bedarf auf Abbrechen klicken
  • ✓ Den PC normal für andere Aufgaben verwenden (nur das Fenster minimieren)

🎉 VERARBEITUNG ABGESCHLOSSEN

Wenn alle Datensätze verarbeitet wurden:

1. Das Fortschrittsfenster schließt sich automatisch

2. Eine Meldung erscheint: "Vorgang abgeschlossen"

3. Klicke auf OK, um die Meldung zu schließen

4. Das Fortschrittsfenster verschwindet vollständig

Danach:

  • Zeige die Ausgabedateien in den Ordnern an, die du in SCHRITT 2 ausgewählt hast
  • Jedes Dokument/Register hat einen eigenen Unterordner innerhalb des von dir ausgewählten Ordners
  • Die Bilder sind einsatzbereit (Anzeige, Druck, Archivierung, PDF)

✅ ERZEUGTE AUSGABE:

Für jeden verarbeiteten Datensatz findest du:

  • Bilder in den ausgewählten Formaten (PNG, JPG, TIFF)
  • manifest_[ID]_[nome].json → Originales IIIF-Manifest mit strukturierten Metadaten
  • [nome]_genealogico.json → Genealogische Metadaten (Daten, Orte, Namen, Gemeinden, Provinzen)
  • [nome]_tecnico.json → Technische Metadaten (Anzahl der Canvas, Liste der Canvas-IDs, Rechte, erzeugte Dateien)
  • [nome].json → JSON-Sidecar für jedes Bild (eingebettete EXIF-Metadaten)

📝 HINWEIS ZU DEN DATEINAMEN:

  • Der Basis-[nome] wird direkt aus der Datei input.txt übernommen (Benutzerzeile)
  • Wenn du in die Eingabedatei "Registro Matrimoni 1920" schreibst, lauten die Dateien:
    • Registro Matrimoni 1920_canvas_1.jpg
    • Registro Matrimoni 1920_genealogico.json
    • Registro Matrimoni 1920_tecnico.json
  • Die JSON-Suffixe bleiben aus Kompatibilitätsgründen auf EN (_genealogico, _tecnico)
  • Du kannst in der Eingabedatei Namen in jeder Sprache verwenden (IT, EN, gemischt)

3. PDF FÜR REGISTER UND DOKUMENTE

────────────────────────────────────────────────────────────────────────────────

SO AKTIVIERST DU DIE PDF-ERSTELLUNG

Die PDF-Erstellung wird durch Aktivieren des Kontrollkästchens PDF in der Maske zur Formatauswahl aktiviert (Menü → Einstellungen → "Bildformate auswählen").

Du kannst PDF mit einem oder mehreren Bildformaten kombinieren (z. B. PDF + PNG) oder nur PDF auswählen, um ausschließlich das Dokument ohne separate Bilddateien zu erhalten.

📄 MERKMALE DER ERZEUGTEN PDF-DATEI

  • Dateiname: Die PDF-Datei wird einfach [nome].pdfgenannt, ohne zusätzliche Suffixe — zum Beispiel Registro Matrimoni 1920.pdf
  • Speicherort: im ausgewählten Ausgabeordner gespeichert, auf derselben Ebene wie die Bilder: [cartella_scelta]\[nome].pdf
  • Seitenreihenfolge: Die Seiten befinden sich immer in aufsteigender numerischer Reihenfolge (Canvas 1 → Canvas 2 → … → Canvas N), unabhängig von der Reihenfolge, in der die Tiles heruntergeladen werden
  • Placeholder-Seiten: Wenn ein Canvas nicht verfügbar ist (Netzwerkfehler oder Ressource vorübergehend nicht erreichbar), wird an seiner Stelle automatisch eine placeholder -Seite in der ausgewählten Sprache eingefügt. Die Placeholder-Seite enthält:
    • Einen lokalisierten Hinweistext (z. B. "Bild nicht verfügbar")
    • Den direkten Link zum ursprünglichen Canvas auf Antenati (https://antenati.cultura.gov.it/ark:/…), damit die Quelle einfach aufgerufen werden kann
    Auf diese Weise wird die PDF-Datei immer erstellt und enthält alle erforderlichen Informationen, um sie bei nicht heruntergeladenen Bildern vervollständigen zu können.
  • Automatische Bereinigung: Die für die PDF-Erstellung verwendeten temporären Dateien werden nach Abschluss des Vorgangs automatisch gelöscht. Im Ausgabeordner verbleiben nur die Bilder in den ausgewählten Formaten, die endgültige PDF-Datei, die Manifeste und die Metadaten

🚫 Wenn PDF nicht ausgewählt ist:

  • Es werden nur die Bilder in den ausgewählten Formaten heruntergeladen
  • Keine PDF-Datei wird erstellt

4. 📌 VERFÜGBARE FUNKTIONEN

Das Menü “Dienste” enthält die operativen Funktionen von v3: KI-gestützte Suche, Bildanzeige, Anzeige von JSON-Metadaten, Erweiterte OCR, OCR-Übersetzung und GEDCOM-Export.

1️⃣ KI-GESTÜTZTE SUCHE ✅

Assistent zum Erstellen genealogischer Suchstrategien:

  • Wandelt Nachnamen, Orte, Zeiträume und Ziele in Rechercheansätze um
  • Schlägt Portale, Filter und Beispielabfragen zur manuellen Überprüfung vor
  • Unterstützt italienische, italienischsprachige, migrationsbezogene und internationale Szenarien
  • Ermöglicht persönliche Notizen, Multi-Provider-Vergleiche und das Speichern der Ergebnisse

Status: ✅ Verfügbar – Siehe Anleitung zur KI-gestützten Suche

2️⃣ BILDANZEIGE ✅

Integrierter Viewer für genealogische Bilder:

  • Unterstützte Formate: JPG, PNG, TIFF (einschließlich mehrseitiger TIFF-Dateien mit Vor-/Zurück-Navigation)

5. AUSGABEORDNER UND -DATEIEN

📂 AUSGABESTRUKTUR

Wenn du einen IIIF-Datensatz verarbeitest, speichert ATK-Pro die Dateien in dem Ordner, den du in SCHRITT 2 ausgewählt hast (Ausgabeordner auswählen).

NACH DATENSATZ ORGANISIERTE STRUKTUR:

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Originales IIIF-Manifest
├─ [nome]_canvas_1.jpg/.png/.tif     ← Rekonstruierte Bilder (eines pro Seite)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = Gesamtanzahl der Seiten/Canvas)
├─ [nome].json                       ← JSON-Sidecar für jedes Bild (EXIF)
├─ [nome].pdf                        ← Vollständige PDF-Datei (nur wenn angefordert)
└─ [nome]/                           ← Unterordner NUR für Metadaten
   ├─ [nome]_genealogico.json        ← Genealogische Metadaten
   └─ [nome]_tecnico.json            ← Technische Metadaten

MEHRERE DATENSÄTZE IM SELBEN ORDNER:

Wenn du 3 Datensätze im selben Ordner verarbeitest, sieht die Struktur folgendermaßen aus:

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (Sidecar)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (Sidecar)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (Sidecar)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

📌 HINWEISE ZUR STRUKTUR:

  • IIIF-Manifest, Bilder, PDF, JSON-Sidecar: auf der Hauptebene
  • NUR technische und genealogische Metadaten: in Unterordnern [nome]/ (einer pro Datensatz)
  • Die temporären Ordner (tiles_canvas_X/) und die für die PDF-Erstellung verwendeten temporären Dateien werden nach Abschluss der Verarbeitung automatisch gelöscht: Im Ausgabeordner verbleiben keine temporären Arbeitsdateien
  • Diese Organisation ermöglicht die Verwaltung mehrerer Datensätze im selben Ordner, ohne dass Dateien verwechselt werden

  • Manifest: manifest_[ID]_[nome].json
  • Bilder: [nome]_canvas_1, [nome]_canvas_2, ... [nome]_canvas_N
  • JSON-Metadaten: [nome]_genealogico.json, [nome]_tecnico.json
  • Bild-JSON: [nome].json (für jeden Canvas)
  • PDF: [nome].pdf
