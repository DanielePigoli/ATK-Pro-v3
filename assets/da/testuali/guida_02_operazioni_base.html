1. INDLÆSNING AF POSTER - INPUTFORMATER

────────────────────────────────────────────────────────────────────────────────

📥 INPUTSTRUKTUR OG UNDERSTØTTEDE PORTALER

ATK-Pro accepterer inputfiler i et specifikt format baseret på PAR: For HVER post, der skal behandles, skal du angive Tilstand + URL.

Understøttede portaler: kopiér og indsæt den offentlige URL til siden, fremviseren, manifestet eller den kompatible PDF. ATK-Pro genkender portalen og anvender den relevante tekniske og forsigtige metode.

Understøttet angiver verificeret teknisk kompatibilitet, ikke en ubegrænset tilladelse til download. Ressourcen skal være offentligt tilgængelig, og brugeren skal overholde rettigheder, licenser, brugsvilkår og begrænsninger for den enkelte portal. ATK-Pro omgår ikke login, institutionsadgang, paywalls eller markører nodownload.

Antenati (Italia), Gallica (Francia), DigiVatLib (Vaticano), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Südtirol), e-codices/e-rara/e-manuscripta (Svizzera), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo og Internet Archive.

1. LINJE 1: Tilstand + Navn (valgfrit)

  • D = Enkelt dokument (ét enkelt billede/en enkelt side)
  • R = Register (komplet samling af sider/dokumenter)

2. LINJE 2: Offentlig URL til posten eller ressourcen

Eksempel på en korrekt input.txt-fil:

# Kommentarer begynder med #

POST 1 (linjepar):
D - Vigtigt brev
https://biblioteca.example.org/iiif/doc123/manifest.json

POST 2 (linjepar):
R - Administrativt register 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

POST 3 (linjepar):
D - Enkelt fotografi
https://collections.example.org/iiif/foto789/manifest.json

📝 REGLER FOR INPUTFORMAT:

  • Tomme linjer: ignoreres (du kan bruge dem for bedre læsbarhed)
  • Linjer med #: ignoreres som kommentarer
  • Tilstand D/d eller R/r: er obligatorisk; store og små bogstaver behandles ens
  • Filnavn: valgfrit efter tilstanden (f.eks. "D - Navn" eller kun "D")
  • URL: skal begynde med http:// eller https://
  • Par: tilstand + URL skal stå på to på hinanden følgende linjer

⚙️ SÅDAN INDLÆSES INPUT - 3 MULIGHEDER FRA MENUEN:

MULIGHED 1: Vis inputeksempel ──────────────────────────────────────

1. Klik på Menu → "Inputfil" → "Inputeksempel"

2. Der åbnes et vindue, som viser den lokaliserede eksempelfil

3. Du kan kopiere indholdet og bruge det som skabelon til din inputfil

4. Eksempelfil: assets/[lingua]/testuali/input_link_base.txt

Bemærkning om filnavnet: den distribuerede fil hedder input_link_base.txt. Navnet er blevet normaliseret i v3 for at undgå henvisninger til tidligere versioner; formatet er fortsat kompatibelt med indlæsning af IIIF-poster.

MULIGHED 2: Åbn en færdig inputfil ──────────────────────────────────────

1. Klik på Menu → "Inputfil" → "Åbn input"

2. Der åbnes en dialogboks til valg af fil

3. Vælg din input.txt-fil (den skal følge parformatet)

4. ATK-Pro indlæser automatisk filen og læser alle poster

5. Viser antallet af indlæste poster, som er klar til behandling

MULIGHED 3: Rediger allerede indlæst input ──────────────────────────────────────────

1. Efter at have indlæst en inputfil (MULIGHED 2)

2. Klik på Menu → "Inputfil" → "Rediger input"

3. Der åbnes en teksteditor med den aktuelt indlæste fil

4. Rediger parrene (tilføj, fjern eller ændr URL)

5. Klik på "Gem" for at opdatere de poster, der skal behandles

6. Programmet fortolker den opdaterede fil på ny

📌 FORSKELLEN MELLEM D OG R:

  • D (Dokument): Håndterer ét enkelt billede/en enkelt side
  • → Output: én enkelt fil for dokumentet
  • R (Register): Håndterer samlinger med flere sider
  • → Output: mappe med organiserede sider + PDF (hvis brugeren ønsker det)

✅ VALIDERING AF POSTER

Efter indlæsning kontrollerer programmet:

  • ✓ At URL'en er tilgængelig og kan nås
  • ✓ Kompatibel ressource: IIIF v2/v3-manifest, understøttet side, billede eller direkte PDF afhængigt af portalen
  • ✓ Antal tilgængelige billeder og canvasser
  • ✓ Metadata (titel, forfatter, dato)

❌ ALMINDELIGE FEJL

  • "Ugyldig URL": Kontrollér den kopierede/indsatte URL
  • "Manifest ikke fundet (404)": URL'en er udløbet eller forkert
  • "IIIF-format understøttes ikke": Serveren bruger ikke standard-IIIF
  • "Forbindelsestimeout": Internetforbindelsen er langsom eller mangler

💾 LAGRING AF POSTER

Efter indlæsning af manifestet gemmer programmet automatisk IIIF-metadataene. HVOR: I den outputmappe, du vælger (se Afsnit 2, TRIN 2) MAPPESTRUKTUR EFTER INDLÆSNING (før behandling):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Oprindeligt IIIF-manifest (øverste niveau)
 └─ [nome]/                            ← Undermappe KUN til metadata
    ├─ [nome]_genealogico.json        ← Udtrukne genealogiske metadata
    └─ [nome]_tecnico.json            ← Tekniske metadata (canvas-ID, antal sider)

EFTER BEHANDLING (når du klikker på Menu → Output → Behandl): På øverste niveau tilføjes de behandlede filer:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Oprindeligt IIIF-manifest
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Billeder rekonstrueret fra IIIF-tiles (ét pr. side)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (formatet afhænger af det valgte)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = samlet antal sider/canvasser)
 ├─ [nome].json                        ← JSON-sidecar for hvert billede (EXIF-metadata)
 └─ [nome].pdf                         ← Komplet PDF (se forklaringen nedenfor)

Metadataene forbliver i undermappen [nome]/, som de blev gemt ved indlæsningen.

VIGTIG BEMÆRKNING: Filorganisering

  • IIIF-manifest: øverste niveau i outputmappen
  • Billeder (canvas), PDF, JSON-sidecar: øverste niveau i outputmappen
  • KUN tekniske og genealogiske metadata: gemmes i undermappen [nome]/
  • Midlertidige mapper (tiles_canvas_X/) slettes automatisk, når behandlingen er afsluttet
  • Denne struktur gør det muligt at håndtere flere poster i samme mappe uden forvirring

Eksempel: Hvis du behandler "Registro1", finder du:

  • manifest_[ID1]_Registro1.json (øverste niveau)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (øverste niveau)
  • Registro1.pdf (øverste niveau)
  • Registro1/ (undermappe KUN med genealogiske og tekniske metadata)

2. BEHANDLING OG DOWNLOAD AF BILLEDER

────────────────────────────────────────────────────────────────────────────────

🎯 BEHANDLINGSFORLØB

Behandlingsworkflowet består af 3 trin:

TRIN 1: VÆLG BILLEDFORMATER

─────────────────────────────────────

1. Indlæs en inputfil (Inputfil → Åbn input): formatvinduet åbnes automatisk

2. Alternativt: Klik på Menu → "Indstillinger" → "Vælg billedformater"

3. Der åbnes en dialogboks med 3 muligheder:

☐ PNG → Tabsfrit format (lossless), bedste kvalitet, større filer

☐ JPG → Komprimeret format (lossy), godt kompromis mellem kvalitet og filstørrelse

☐ TIFF → Arkivformat, højeste kvalitet, meget store filer

PDF-dokument

☐ PDF → Genererer en komplet PDF med alle sider i registeret eller dokumentet ud over de valgte billedformater (eller som eneste output, hvis der ikke er valgt noget billedformat)

4. Vælg mindst ét billedformat eller PDF (du kan vælge flere)

5. Klik på "Bekræft"

✅ De valgte formater gemmes og forhåndsvælges automatisk, næste gang programmet åbnes.

📝 ANBEFALINGER:

  • Til forhåndsvisning/konsultation: JPG (hurtig at åbne, mindre pladsforbrug)
  • Til bevaringsarkiv: PNG (lossless, godt kompromis med hensyn til plads) eller TIFF (højeste kvalitet)
  • Til begge formål: vælg både PNG og TIFF
  • Til PDF: vælg PDF sammen med ét eller flere billedformater, eller vælg kun PDF for udelukkende at generere PDF-dokumentet uden separate billedfiler

TRIN 2: VÆLG OUTPUTMAPPER

──────────────────────────────────────

1. Mappevinduet åbnes automatisk efter valg af formater (når du indlæser en inputfil)

2. Alternativt: Klik på Menu → "Indstillinger" → "Vælg outputmapper"

3. Vælg TILSTANDEN for organisering af mapper:

⬤ Én fælles mappe til alle → én fælles mappe til alle poster (dokumenter og registre)

⬤ Separate mapper til dok./reg. → én mappe til alle dokumenter og én til alle registre

⬤ Én mappe for hver post → en separat mappe til hver post i inputfilen

4. Når tilstanden er valgt, skal du vælge de nødvendige mapper (1, 2 eller N dialogvinduer)

5. Til sidst vises en oversigt over de valgte mapper

✅ Tilstand og mapper gemmes. Næste gang en inputfil åbnes, gendannes de automatisk, hvis de er kompatible med antallet af poster.

⚠️ Hvis den nye inputfil har et andet antal Dokumenter/Registre end de gemte mapper, vises en advarsel, og valget nulstilles, så der kan vælges nye mapper.

🛡️ Forhåndskontrol af stier: før der oprettes mapper eller filer, kontrollerer ATK-Pro de planlagte navne og stier. Navne, der er inkompatible med Windows, og segmenter, der er for lange, blokerer kun den berørte post; kompatibilitetsadvarsler vises i den afsluttende oversigt.

☁️ OneDrive/SharePoint antages ikke at være standarddestination. De tilhørende begrænsninger anvendes kun, når den valgte mappe faktisk ligger under en OneDrive-rod. På andre stier behandles Windows' historiske grænse på 260 tegn som en forsigtighedsadvarsel og ikke som en automatisk blokering.

📌 OVERSIGT OVER TILSTANDE:

  • Fælles mappe: Enkelt, alt samlet ét sted. Velegnet til hurtige behandlinger eller test
  • Separate dok./reg.: Organisering efter type. Standard: output/doc/ og output/reg/
  • For hver post: Maksimal fleksibilitet. Du kan bruge forskellige drev, NAS og brugerdefinerede mapper

TRIN 3: START BEHANDLING

─────────────────────────────

1. Klik på Menu → "Output" → "Behandl"

2. Kontrollér, at:

✓ Mindst 1 billedformat er valgt

✓ Mindst 1 post er indlæst

Hvis disse krav ikke er opfyldt, vises en fejlmeddelelse:

❌ "Intet format valgt" → Gå til TRIN 1

❌ "Ingen post indlæst" → Gå til Indlæsning af input (Afsnit 1)

📺 BEHANDLINGSVINDUE

Så snart du klikker på "Behandl", åbnes et modalt vindue med:

📊 SYNLIGE ELEMENTER:

1️⃣ VINDUESTITLE: "Behandling i gang"

  • Forbliver i forgrunden, indtil behandlingen er afsluttet
  • Du kan ikke interagere med resten af GUI'en

2️⃣ FREMSKRIDTSETIKET: "Behandler post: 2/5 — Filnavn"

  • Viser: den post, der behandles i øjeblikket (2), ud af det samlede antal (5)
  • Viser også navnet på den fil/det register, der behandles
  • Opdateres i realtid, efterhånden som posterne behandles
  • Fx: "Behandler post: 1/3 — Vielsesregister 1850"

3️⃣ FREMSKRIDTSLINJE: Visuel fremdrift

  • Numerisk format: "2/5" (aktuelt nummer / samlet antal)
  • Farvet bjælke, der bevæger sig fra venstre mod højre
  • Når 100 % (maksimal bredde), når behandlingen er fuldført
  • Viser IKKE procent, kun nummer

4️⃣ KNAPPEN [ANNULLER]

  • Kan klikkes under behandlingen
  • Anmoder om at afbryde hele batchen og lukker fremskridtsvinduet
  • Stoppet er kooperativt: det kan afvente afslutningen af den enkelte netværksanmodning, der allerede er i gang
  • Intet output fra den annullerede session offentliggøres i den valgte mappe; eksisterende filer forbliver uændrede

🔄 UNDER BEHANDLINGEN

Programmet arbejder i baggrunden:

├─ Downloader billeder fra IIIF-servere
├─ Læser manifester for canvas-ID
├─ Rekonstruerer tiles til komplette billeder
├─ Konverterer til de valgte formater (PNG, JPG, TIFF)
└─ Gemmer i de valgte mapper

GUI'en viser fremskridt i realtid:

  • Opdaterer antallet af poster hvert 2.-3. sekund
  • Ingen blokering: brugerfladen forbliver responsiv
  • Du kan annullere når som helst

⚠️ HVAD DER SKER, HVIS DU KLIKKER PÅ ANNULLER:

1. Der anmodes om et kooperativt stop af hele batchen

2. Alle midlertidige outputfiler, der er oprettet af den annullerede batch, slettes

3. Filer, der allerede fandtes i outputmapperne før starten, forbliver uændrede

4. Du kan starte igen fra Menu → Output → Behandl

📋 PDF — AUTOMATISK GENERERING UNDER BEHANDLING

Hvis du har valgt PDF i dialogboksen til valg af formater (TRIN 1), genereres PDF-filen automatisk, når download af hvert register eller dokument er afsluttet, uden yderligere bekræftelsesvindue.

📌 FUNKTION:

  • ✅ PDF valgt i dialogboksen til valg af formater: PDF-filen genereres automatisk, når download er afsluttet; der anmodes ikke om yderligere bekræftelse
  • ❌ PDF ikke valgt: kun billeder i de valgte formater, ingen PDF

Egenskaber for den genererede PDF:

  • Filnavn: [nome].pdf, uden yderligere suffikser (fx Registro Matrimoni 1920.pdf)
  • Gemmes i den valgte outputmappe på samme niveau som billederne
  • Sider i stigende numerisk rækkefølge (canvas 1 → canvas 2 → … → canvas N)
  • Hvis et canvas ikke kan downloades, indsættes en placeholder lokaliseret med direkte link til det oprindelige canvas på Antenati
  • Ingen midlertidige filer forbliver i outputmappen, når genereringen er afsluttet

⚠️ HVAD DU IKKE SKAL GØRE UNDER BEHANDLINGEN:

  • ❌ Luk ikke programmet (delvise filer går tabt)
  • ❌ Frakobl ikke en ekstern disk (fejl ved lagring)
  • ❌ Sluk ikke PC/laptop
  • ❌ Afbryd ikke internetforbindelsen (download stopper)

✅ HVAD DU KAN GØRE:

  • ✓ Vente på, at processen afsluttes (det er den normale procedure)
  • ✓ Klikke på Annuller, hvis det er nødvendigt
  • ✓ Bruge PC'en normalt til andre ting (minimer blot vinduet)

🎉 BEHANDLING AFSLUTTET

Når alle poster er blevet behandlet:

1. Fremskridtsvinduet lukkes automatisk

2. Der vises en meddelelse: "Handling fuldført"

3. Klik på OK for at lukke meddelelsen

4. Fremskridtsvinduet forsvinder helt

Derefter:

  • Se outputfilerne i de mapper, du valgte i TRIN 2
  • Hvert dokument/register har sin egen undermappe i den mappe, du har valgt
  • Billederne er klar til brug (visning, udskrivning, arkivering, PDF)

✅ GENERERET OUTPUT:

For hver behandlet post finder du:

  • Billeder i de valgte formater (PNG, JPG, TIFF)
  • manifest_[ID]_[nome].json → Oprindeligt IIIF-manifest med strukturerede metadata
  • [nome]_genealogico.json → Genealogiske metadata (datoer, steder, navne, kommuner, provinser)
  • [nome]_tecnico.json → Tekniske metadata (antal canvas, liste over canvas-ID'er, rettigheder, genererede filer)
  • [nome].json → JSON-sidecar for hvert billede (indlejrede EXIF-metadata)

📝 BEMÆRKNING OM FILNAVNE:

  • Grundnavnet [nome] hentes direkte fra filen input.txt (brugerens linje)
  • Hvis du skriver "Registro Matrimoni 1920" i inputfilen, bliver filerne:
    • Registro Matrimoni 1920_canvas_1.jpg
    • Registro Matrimoni 1920_genealogico.json
    • Registro Matrimoni 1920_tecnico.json
  • JSON-suffikserne forbliver på EN (_genealogico, _tecnico) af hensyn til kompatibilitet
  • Du kan bruge navne på ethvert sprog i inputfilen (IT, EN, blandet)

3. PDF FOR REGISTRE OG DOKUMENTER

────────────────────────────────────────────────────────────────────────────────

SÅDAN AKTIVERES PDF-GENERERING

PDF-generering aktiveres ved at markere feltet PDF i dialogboksen til valg af formater (Menu → Indstillinger → "Vælg billedformater").

Du kan kombinere PDF med et eller flere billedformater (fx PDF + PNG) eller kun vælge PDF for udelukkende at få dokumentet uden separate billedfiler.

📄 EGENSKABER FOR DEN GENEREREDE PDF

  • Filnavn: PDF-filen får ganske enkelt navnet [nome].pdf, uden yderligere suffikser — for eksempel Registro Matrimoni 1920.pdf
  • Placering: gemmes i den valgte outputmappe på samme niveau som billederne: [cartella_scelta]\[nome].pdf
  • Siderækkefølge: siderne er altid i stigende numerisk rækkefølge (canvas 1 → canvas 2 → … → canvas N), uanset i hvilken rækkefølge tiles downloades
  • Placeholder-sider: hvis et canvas ikke er tilgængeligt (netværksfejl eller ressource midlertidigt utilgængelig), indsættes der automatisk en placeholder lokaliseret på det valgte sprog. Placeholder-siden indeholder:
    • En lokaliseret advarselstekst (fx "Billede ikke tilgængeligt")
    • Det direkte link til det oprindelige canvas på Antenati (https://antenati.cultura.gov.it/ark:/…), så kilden nemt kan konsulteres
    På denne måde genereres PDF-filen altid med alle de oplysninger, der er nødvendige for at færdiggøre den, hvis nogle billeder ikke blev downloadet.
  • Automatisk oprydning: de midlertidige filer, der bruges til PDF-generering, slettes automatisk ved processens afslutning. I outputmappen forbliver kun billederne i de valgte formater, den endelige PDF, manifesterne og metadataene

🚫 Hvis PDF ikke er valgt:

  • Kun billederne downloades i de valgte formater
  • Ingen PDF genereres

4. 📌 TILGÆNGELIGE FUNKTIONER

Menuen “Tjenester” indeholder de operationelle funktioner i v3: AI-assisteret søgning, billedvisning, visning af JSON-metadata, Avanceret OCR, OCR-oversættelse og GEDCOM-eksport.

1️⃣ AI-ASSISTERET SØGNING ✅

Assistent til opbygning af genealogiske søgestrategier:

  • Omsætter efternavne, steder, perioder og mål til søgespor
  • Foreslår portaler, filtre og eksempler på forespørgsler, der skal kontrolleres manuelt
  • Understøtter italienske, italiensksprogede, migrationsrelaterede og internationale scenarier
  • Muliggør personlige noter, sammenligning mellem flere udbydere og lagring af resultater

Status: ✅ Tilgængelig – Se vejledningen til AI-assisteret søgning

2️⃣ BILLEDVISNING ✅

Integreret fremviser til genealogiske billeder:

  • Understøttede formater: JPG, PNG, TIFF (inklusive flersidede TIFF-filer med frem/tilbage-navigation)
  • Zoom med musehjulet og dedikerede knapper
  • Panorering ved at trække med musen
  • Tilstandene “Tilpas til vindue” og “1:1 pixel”
  • JSON-sidecar vist ved siden af billedet (EXIF og tekniske metadata)

Status: ✅ Tilgængelig – Se vejledningen til billedvisning

3️⃣ VISNING AF JSON-METADATA ✅

Trævisning til strukturerede metadata:

  • Direkte åbning af filer _genealogico.json og _tecnico.json
  • Udvidelig trævisning
  • Sektioner: genealogiske data, tekniske metadata, EXIF fra billeder
  • Forhåndsvisning af det tilknyttede billede ved siden af metadatapanelet

Status: ✅ Tilgængelig – Se vejledningen til visning af JSON-metadata

4️⃣ AVANCERET OCR ✅

Avanceret OCR-behandling via LLM Vision:

  • Tekstudtræk fra historiske dokumenter (herunder håndskrifter på italiensk fra 1800-tallet og latin)
  • Bevarelse af struktur og layoutreferencer (TEI XML)
  • Automatisk genkendelse og oprydning af strukturerede data (fx tabeller, roller)
  • Udtræk af entiteter (navne, datoer, relationer) i navigerbart JSON-format

Status: ✅ Tilgængelig – Se vejledningen til Avanceret OCR

5️⃣ OCR-OVERSÆTTELSE ✅

Kontekstbaseret oversættelse af udtrukne eller transskriberede tekster:

  • Oversættelse af OCR-tekster, manuelle transskriptioner og TXT-filer
  • Brug af dokumenttyper, ordliste og kontekst
  • Konfigurerbar AI-udbyder, valgfri model og nøgleboks
  • Output som TXT eller redigerbar DOCX

Status: ✅ Tilgængelig – Se vejledningen til OCR-oversættelse

6️⃣ GEDCOM-EKSPORT ✅

Assisteret genealogisk analyse og GEDCOM-eksport:

  • Universelt input med metoden Auto-Discovery, Vision IA eller Refinery LLM
  • Mulighed for at udvide en eksisterende GEDCOM- eller CSV-base
  • Palæografiske noter og dokumenttyper til at styre udtrækket
  • Generering af en fil genealogia_*.ged der skal kontrolleres før brug

Status: ✅ Tilgængelig – Se GEDCOM-vejledningen

5. OUTPUTMAPPER OG -FILER

────────────────────────────────────────────────────────────────────────────────

📂 OUTPUTSTRUKTUR

Når du behandler en IIIF-post, gemmer ATK-Pro filerne i den mappe, du valgte i TRIN 2 (Vælg outputmappe).

STRUKTUR ORGANISERET EFTER POST:

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Oprindeligt IIIF-manifest
├─ [nome]_canvas_1.jpg/.png/.tif     ← Rekonstruerede billeder (ét pr. side)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = samlet antal sider/canvas)
├─ [nome].json                       ← JSON-sidecar for hvert billede (EXIF)
├─ [nome].pdf                        ← Komplet PDF (kun hvis ønsket)
└─ [nome]/                           ← Undermappe KUN til metadata
   ├─ [nome]_genealogico.json        ← Genealogiske metadata
   └─ [nome]_tecnico.json            ← Tekniske metadata

📌 BEMÆRKNINGER OM STRUKTUREN:

  • IIIF-manifest, billeder, PDF, JSON-sidecar: på hovedniveauet
  • KUN tekniske og genealogiske metadata: i undermapperne [nome]/ (én pr. post)
  • De midlertidige mapper (tiles_canvas_X/) og de midlertidige filer, der bruges til PDF-genereringen, slettes automatisk, når behandlingen er afsluttet: der forbliver ingen mellemliggende arbejdsfiler i outputmappen
  • Denne organisering gør det muligt at håndtere flere poster i samme mappe uden forveksling mellem filerne

  • Metadata-JSON: [nome]_genealogico.json, [nome]_tecnico.json
  • Billed-JSON: [nome].json (for hvert canvas)
  • PDF: [nome].pdf
