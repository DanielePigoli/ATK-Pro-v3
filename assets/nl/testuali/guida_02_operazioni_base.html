1. RECORDS LADEN - INVOERFORMATEN

────────────────────────────────────────────────────────────────────────────────

📥 INVOERSTRUCTUUR EN ONDERSTEUNDE PORTALEN

ATK-Pro accepteert invoerbestanden met een specifiek formaat op basis van PAREN: geef voor ELK te verwerken record Modus + URL op.

Ondersteunde portalen: kopieer en plak de openbare URL van de pagina, viewer, manifest of compatibele PDF. ATK-Pro herkent het portaal en past de bijbehorende technische en voorzorgsmodus toe.

Ondersteund duidt op geverifieerde technische compatibiliteit, niet op een onbeperkte toestemming om te downloaden. De bron moet openbaar toegankelijk zijn en de gebruiker moet rechten, licenties, gebruiksvoorwaarden en beperkingen van het afzonderlijke portaal naleven. ATK-Pro omzeilt geen login, toegang via aangesloten instellingen, paywalls of markeringen nodownload.

Antenati (Italië), Gallica (Frankrijk), DigiVatLib (Vaticaan), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Südtirol), e-codices/e-rara/e-manuscripta (Zwitserland), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo en Internet Archive.

1. REGEL 1: Modus + Naam (optioneel)

  • D = Afzonderlijk document (één afbeelding/pagina)
  • R = Register (volledige collectie van pagina's/documenten)

2. REGEL 2: Openbare URL van het record of de bron

Voorbeeld van een correct input.txt-bestand:

# Opmerkingen beginnen met #

RECORD 1 (paar regels):
D - Belangrijke brief
https://biblioteca.example.org/iiif/doc123/manifest.json

RECORD 2 (paar regels):
R - Administratief register 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

RECORD 3 (paar regels):
D - Afzonderlijke foto
https://collections.example.org/iiif/foto789/manifest.json

📝 REGELS VOOR HET INVOERFORMAAT:

  • Lege regels: worden genegeerd (je kunt ze gebruiken voor de leesbaarheid)
  • Regels met #: worden als opmerkingen genegeerd
  • Modus D/d of R/r: is verplicht; hoofdletters en kleine letters zijn gelijkwaardig
  • Bestandsnaam: optioneel na de modus (bijv. "D - Naam" of alleen "D")
  • URL: moet beginnen met http:// of https://
  • Paren: modus + URL moeten op opeenvolgende regels staan

⚙️ DE INVOER LADEN - 3 OPTIES IN HET MENU:

OPTIE 1: Voorbeeldinvoer weergeven ──────────────────────────────────────

1. Klik op Menu → "File input" → "Esempio input"

2. Er wordt een venster geopend waarin het gelokaliseerde voorbeeldbestand wordt weergegeven

3. Je kunt de inhoud kopiëren als sjabloon voor je invoerbestand

4. Voorbeeldbestand: assets/[lingua]/testuali/input_link_base.txt

Opmerking over de bestandsnaam: het meegeleverde bestand heet input_link_base.txt. De naam is in v3 genormaliseerd om verwijzingen naar eerdere versies te voorkomen; het formaat blijft compatibel met het laden van IIIF-records.

OPTIE 2: Klaar invoerbestand openen ──────────────────────────────────────

1. Klik op Menu → "File input" → "Apri input"

2. Er wordt een dialoogvenster voor bestandsselectie geopend

3. Kies je bestand input.txt (dit moet het paarformaat volgen)

4. ATK-Pro laadt automatisch alle records en leest ze in

5. Toont het aantal geladen records dat gereed is voor verwerking

OPTIE 3: Reeds geladen invoer wijzigen ──────────────────────────────────────────

1. Nadat je een invoerbestand hebt geladen (OPTIE 2)

2. Klik op Menu → "File input" → "Modifica input"

3. Er wordt een teksteditor geopend met het momenteel geladen bestand

4. Wijzig de paren (toevoegen, verwijderen, URL wijzigen)

5. Klik op "Salva" om de te verwerken records bij te werken

📌 VERSCHIL TUSSEN D EN R:

  • D (Document): verwerkt één afbeelding/pagina
  • → Uitvoer: één bestand voor het document
  • R (Register): verwerkt collecties met meerdere pagina's
  • → Uitvoer: map met georganiseerde pagina's + PDF (indien door de gebruiker gevraagd)

✅ RECORDVALIDATIE

Na het laden controleert het programma:

  • ✓ URL toegankelijk en bereikbaar
  • ✓ Compatibele bron: IIIF v2/v3-manifest, ondersteunde pagina, afbeelding of directe PDF afhankelijk van het portaal
  • ✓ Aantal beschikbare afbeeldingen en canvassen
  • ✓ Metadata (titel, auteur, datum)

❌ VEELVOORKOMENDE FOUTEN

  • "Ongeldige URL": controleer het kopiëren/plakken van de URL
  • "Manifest niet gevonden (404)": URL is verlopen of onjuist
  • "IIIF-formaat niet ondersteund": de server gebruikt geen standaard-IIIF
  • "Verbindingstime-out": internetverbinding is traag of afwezig

💾 RECORDS OPSLAAN

Na het laden van het manifest slaat het programma de IIIF-metadata automatisch op. WAAR: in de uitvoermap die je kiest (zie Sectie 2, STAP 2) MAPSTRUCTUUR NA HET LADEN (vóór de verwerking):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Origineel IIIF-manifest (hoofdniveau)
 └─ [nome]/                            ← Submap ALLEEN voor metadata
    ├─ [nome]_genealogico.json        ← Geëxtraheerde genealogische metadata
    └─ [nome]_tecnico.json            ← Technische metadata (canvas ID, aantal pagina's)

NA DE VERWERKING (wanneer je klikt op Menu → Output → Elabora): op het hoofdniveau worden de verwerkte bestanden toegevoegd:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Origineel IIIF-manifest
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Afbeeldingen gereconstrueerd uit IIIF-tiles (één per pagina)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (formaat is afhankelijk van de gemaakte keuze)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = totaal aantal pagina's/canvassen)
 ├─ [nome].json                        ← JSON-sidecar voor elke afbeelding (EXIF-metadata)
 └─ [nome].pdf                         ← Volledige PDF (zie uitleg hieronder)

De metadata blijven in de submap [nome]/ zoals ze bij het laden zijn opgeslagen.

BELANGRIJKE OPMERKING: Bestandsorganisatie

  • IIIF-manifest: hoofdniveau van de uitvoermap
  • Afbeeldingen (canvas), PDF, JSON-sidecar: hoofdniveau van de uitvoermap
  • ALLEEN technische en genealogische metadata: opgeslagen in submap [nome]/
  • De tijdelijke mappen (tiles_canvas_X/) worden aan het einde automatisch verwijderd
  • Met deze structuur kunnen meerdere records zonder verwarring in dezelfde map worden beheerd

Voorbeeld: Als je "Registro1" verwerkt, vind je:

  • manifest_[ID1]_Registro1.json (hoofdniveau)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (hoofdniveau)
  • Registro1.pdf (hoofdniveau)
  • Registro1/ (submap ALLEEN met genealogische en technische metadata)

2. AFBEELDINGEN VERWERKEN EN DOWNLOADEN

────────────────────────────────────────────────────────────────────────────────

🎯 VERWERKINGSWORKFLOW

De verwerkingsworkflow bestaat uit 3 stappen:

STAP 1: AFBEELDINGSFORMATEN SELECTEREN

─────────────────────────────────────

1. Laad een invoerbestand (File input → Apri input): het venster met formaten wordt automatisch geopend

2. Of: klik op Menu → "Impostazioni" → "Seleziona formati immagine"

3. Er wordt een dialoogvenster geopend met 3 opties:

☐ PNG → Formaat zonder kwaliteitsverlies (lossless), beste kwaliteit, grotere bestanden

☐ JPG → Gecomprimeerd formaat (lossy), goed compromis tussen kwaliteit en bestandsgrootte

☐ TIFF → Archiveringsformaat, maximale kwaliteit, zeer grote bestanden

PDF-document

☐ PDF → Genereert een volledige PDF met alle pagina's van het register of document, naast de geselecteerde afbeeldingsformaten (of als enige uitvoer als geen afbeeldingsformaat is geselecteerd)

4. Selecteer ten minste één afbeeldingsformaat of PDF (je kunt er meerdere kiezen)

5. Klik op "Conferma"

✅ De gekozen formaten worden onthouden en bij de volgende start van het programma automatisch vooraf geselecteerd.

📝 AANBEVELINGEN:

  • Voor voorbeeldweergave/raadpleging: JPG (snel te openen, minder opslagruimte)
  • Voor duurzame archivering: PNG (lossless, goed compromis qua opslagruimte) of TIFF (maximale kwaliteit)
  • Voor beide: selecteer zowel PNG als TIFF
  • Voor PDF: selecteer PDF samen met een of meer afbeeldingsformaten, of selecteer alleen PDF om uitsluitend het PDF-document te genereren zonder afzonderlijke afbeeldingsbestanden

STAP 2: UITVOERMAPPEN SELECTEREN

──────────────────────────────────────

1. Het mappenvenster wordt automatisch geopend nadat de formaten zijn gekozen (wanneer je een invoerbestand laadt)

2. Of: klik op Menu → "Impostazioni" → "Seleziona cartelle output"

3. Kies de MODUS voor het organiseren van de mappen:

⬤ Eén map voor alles → één map voor alle records (documenten en registers)

⬤ Afzonderlijke mappen doc/reg → één map voor alle documenten en één voor alle registers

⬤ Eén map per record → een afzonderlijke map voor elk record in het invoerbestand

4. Selecteer na het kiezen van de modus de vereiste mappen (1, 2 of N dialoogvensters)

5. Aan het einde wordt een overzicht van de gekozen mappen weergegeven

✅ Modus en mappen worden onthouden. Bij het volgende openen van een invoerbestand worden ze automatisch hersteld als ze compatibel zijn met het aantal records.

⚠️ Als het nieuwe invoerbestand een ander aantal Documenten/Registers bevat dan waarvoor de mappen zijn opgeslagen, wordt een waarschuwing weergegeven en wordt de selectie gewist zodat nieuwe mappen kunnen worden gekozen.

🛡️ Voorafgaande controle van paden: voordat mappen of bestanden worden aangemaakt, controleert ATK-Pro de verwachte namen en paden. Namen die niet compatibel zijn met Windows en buitensporig lange padsegmenten blokkeren alleen het betreffende record; compatibiliteitswaarschuwingen worden in het eindoverzicht weergegeven.

☁️ OneDrive/SharePoint wordt niet als standaardbestemming verondersteld. De bijbehorende beperkingen worden alleen toegepast wanneer de geselecteerde map zich daadwerkelijk onder een OneDrive-root bevindt. Voor andere paden wordt de historische Windows-limiet van 260 tekens als voorzorgswaarschuwing behandeld en niet als automatische blokkering.

📌 OVERZICHT VAN DE MODI:

  • Eén map: Eenvoudig, alles op één plaats. Geschikt voor snelle verwerkingen of tests
  • Afzonderlijk doc/reg: Organisatie per type. Standaard: output/doc/ en output/reg/
  • Per record: Maximale flexibiliteit. Je kunt verschillende drives, NAS en aangepaste mappen gebruiken

STAP 3: VERWERKING STARTEN

─────────────────────────────

1. Klik op Menu → "Output" → "Elabora"

2. Controleer of:

✓ Ten minste 1 afbeeldingsformaat is geselecteerd

✓ Ten minste 1 record is geladen

Als niet aan deze vereisten is voldaan, verschijnt een foutmelding:

❌ "Geen formaat geselecteerd" → Ga naar STAP 1

❌ "Geen record geladen" → Ga naar Invoer laden (Sectie 1)

📺 VERWERKINGSVENSTER

Zodra je op "Elabora" klikt, wordt een modaal venster geopend met:

📊 ZICHTBARE ELEMENTEN:

1️⃣ VENSTERTITEL: "Verwerking bezig"

  • Blijft op de voorgrond totdat de verwerking is voltooid
  • Je kunt niet met de rest van de GUI werken

2️⃣ VOORTGANGSLABEL: "Records verwerken: 2/5 — Bestandsnaam"

  • Toont: momenteel verwerkt record (2) van totaal (5)
  • Toont ook de naam van het bestand/register dat wordt verwerkt
  • Wordt in realtime bijgewerkt naarmate de records worden verwerkt
  • Bijv.: "Records verwerken: 1/3 — Huwelijksregister 1850"

3️⃣ VOORTGANGSBALK: Visuele voortgang

  • Numerieke indeling: "2/5" (huidig nummer / totaal)
  • Gekleurde balk die van links naar rechts voortschrijdt
  • Bereikt 100% (maximale breedte) wanneer voltooid
  • Toont GEEN percentage, alleen het nummer

4️⃣ KNOP [ANNULEREN]

  • Klikbaar tijdens de verwerking
  • Vraagt om de volledige batch te stoppen en sluit het voortgangsvenster
  • Het stoppen verloopt coöperatief: mogelijk wordt gewacht tot het afzonderlijke netwerkverzoek dat al bezig is, is voltooid
  • Er wordt geen uitvoer van de geannuleerde sessie gepubliceerd in de gekozen map; reeds bestaande bestanden blijven ongewijzigd

🔄 TIJDENS DE VERWERKING

Het programma voert op de achtergrond het volgende uit:

├─ Downloadt afbeeldingen van IIIF-servers
├─ Leest manifests voor canvas ID
├─ Reconstrueert tiles tot volledige afbeeldingen
├─ Converteert naar de geselecteerde formaten (PNG, JPG, TIFF)
└─ Slaat ze op in de gekozen mappen

De GUI toont de voortgang in realtime:

  • Werkt elke 2-3 seconden het aantal records bij
  • Geen blokkering: de interface blijft responsief
  • Je kunt op elk moment annuleren

⚠️ GEDRAG WANNEER JE OP ANNULEREN KLIKT:

1. Er wordt gevraagd om de volledige batch coöperatief te stoppen

2. Alle tijdelijke uitvoer die door de geannuleerde batch is geproduceerd, wordt verwijderd

3. Bestanden die vóór de start al in de uitvoermappen aanwezig waren, blijven ongewijzigd

4. Je kunt opnieuw beginnen via Menu → Output → Verwerken

📋 PDF — AUTOMATISCHE GENERATIE TIJDENS DE VERWERKING

Als je PDF hebt geselecteerd in het venster voor formaatkeuze (STAP 1), wordt de PDF automatisch gegenereerd nadat het downloaden van elk register of document is voltooid, zonder extra bevestigingsvenster.

📌 GEDRAG:

  • ✅ PDF geselecteerd in het venster voor formaatkeuze: de PDF wordt automatisch gegenereerd nadat het downloaden is voltooid; er wordt geen extra bevestiging gevraagd
  • ❌ PDF niet geselecteerd: alleen de afbeeldingen in de gekozen formaten, geen PDF

Kenmerken van de gegenereerde PDF:

  • Bestandsnaam: [nome].pdf, zonder extra achtervoegsels (bijv. Registro Matrimoni 1920.pdf)
  • Opgeslagen in de gekozen uitvoermap, op hetzelfde niveau als de afbeeldingen
  • Pagina's in oplopende numerieke volgorde (canvas 1 → canvas 2 → … → canvas N)
  • Als een canvas niet kan worden gedownload, wordt een placeholder pagina ingevoegd, gelokaliseerd, met een directe link naar het oorspronkelijke canvas op Antenati
  • Na het genereren blijven er geen tijdelijke bestanden achter in de uitvoermap

⚠️ WAT JE NIET MOET DOEN TIJDENS DE VERWERKING:

  • ❌ Sluit het programma niet af (gedeeltelijke bestanden gaan verloren)
  • ❌ Koppel de externe schijf niet los (opslagfout)
  • ❌ Schakel de pc/laptop niet uit
  • ❌ Verbreek de internetverbinding niet (stopt het downloaden)

✅ WAT JE WEL KUNT DOEN:

  • ✓ Wachten tot het proces is voltooid (dit is de normale procedure)
  • ✓ Op Annuleren klikken als dat dringend nodig is
  • ✓ De pc normaal voor andere dingen gebruiken (minimaliseer alleen het venster)

🎉 EINDE VERWERKING

Wanneer alle records zijn verwerkt:

1. Het voortgangsvenster wordt automatisch gesloten

2. Er verschijnt een bericht: "Bewerking voltooid"

3. Klik op OK om het bericht te sluiten

4. Het voortgangsvenster verdwijnt volledig

Daarna:

  • Bekijk de uitvoerbestanden in de mappen die je bij STAP 2 hebt geselecteerd
  • Elk document/register heeft een eigen submap binnen de door jou gekozen map
  • De afbeeldingen zijn klaar voor gebruik (weergave, afdrukken, archivering, PDF)

✅ GEGENEREERDE UITVOER:

Voor elk verwerkt record vind je:

  • Afbeeldingen in de geselecteerde formaten (PNG, JPG, TIFF)
  • manifest_[ID]_[nome].json → Oorspronkelijk IIIF-manifest met gestructureerde metadata
  • [nome]_genealogico.json → Genealogische metadata (datums, plaatsen, namen, gemeenten, provincies)
  • [nome]_tecnico.json → Technische metadata (aantal canvas, lijst met canvas ID, rechten, gegenereerde bestanden)
  • [nome].json → JSON-sidecar voor elke afbeelding (ingesloten EXIF-metadata)

📝 OPMERKING OVER BESTANDSNAMEN:

  • De basis-[nome] wordt rechtstreeks overgenomen uit het bestand input.txt (gebruikersregel)
  • Als je in het inputbestand "Registro Matrimoni 1920" schrijft, worden de bestanden:
    • Registro Matrimoni 1920_canvas_1.jpg
    • Registro Matrimoni 1920_genealogico.json
    • Registro Matrimoni 1920_tecnico.json
  • De JSON-achtervoegsels blijven in EN (_genealogico, _tecnico) voor compatibiliteit
  • Je kunt namen in elke taal gebruiken in het inputbestand (IT, EN, gemengd)

3. PDF VOOR REGISTERS EN DOCUMENTEN

────────────────────────────────────────────────────────────────────────────────

PDF-GENERATIE ACTIVEREN

De PDF-generatie wordt geactiveerd door het selectievakje PDF te selecteren in het venster voor formaatkeuze (Menu → Instellingen → "Afbeeldingsformaten selecteren").

Je kunt PDF combineren met een of meer afbeeldingsformaten (bijv. PDF + PNG), of alleen PDF selecteren om uitsluitend het document te verkrijgen zonder afzonderlijke afbeeldingsbestanden.

📄 KENMERKEN VAN DE GEGENEREERDE PDF

  • Bestandsnaam: de PDF krijgt eenvoudigweg de naam [nome].pdf, zonder extra achtervoegsels — bijvoorbeeld Registro Matrimoni 1920.pdf
  • Locatie: opgeslagen in de gekozen uitvoermap, op hetzelfde niveau als de afbeeldingen: [cartella_scelta]\[nome].pdf
  • Paginavolgorde: de pagina's staan altijd in oplopende numerieke volgorde (canvas 1 → canvas 2 → … → canvas N), ongeacht de volgorde waarin de tiles worden gedownload
  • Placeholderpagina's: als een canvas niet beschikbaar is (netwerkfout of bron tijdelijk niet bereikbaar), wordt op die plaats automatisch een placeholder pagina ingevoegd die is gelokaliseerd in de geselecteerde taal. De placeholderpagina bevat:
    • Een gelokaliseerde waarschuwingstekst (bijv. "Afbeelding niet beschikbaar")
    • De directe link naar het oorspronkelijke canvas op Antenati (https://antenati.cultura.gov.it/ark:/…), zodat de bron eenvoudig kan worden geraadpleegd
    Op deze manier wordt de PDF altijd gegenereerd, met alle informatie die nodig is om deze aan te vullen wanneer afbeeldingen niet zijn gedownload.
  • Automatische opschoning: de tijdelijke bestanden die voor het genereren van de PDF worden gebruikt, worden aan het einde van het proces automatisch verwijderd. In de uitvoermap blijven alleen de afbeeldingen in de gekozen formaten, de definitieve PDF, de manifests en de metadata over

🚫 Als PDF niet is geselecteerd:

  • Alleen de afbeeldingen worden gedownload in de geselecteerde formaten
  • Geen PDF gegenereerd

Assistent voor het opzetten van genealogische zoekstrategieën:

Status: ✅ Beschikbaar – Zie Handleiding AI-ondersteund zoeken

Geïntegreerde viewer voor genealogische afbeeldingen:

Status: ✅ Beschikbaar – Zie Handleiding Weergave van JSON-metadata

4️⃣ GEAVANCEERDE OCR ✅

Status: ✅ Beschikbaar – Zie Handleiding Geavanceerde OCR

5️⃣ OCR-VERTALING ✅

5. UITVOERMAPPEN EN -BESTANDEN

📂 UITVOERSTRUCTUUR

Wanneer je een IIIF-record verwerkt, slaat ATK-Pro de bestanden op in de map die je bij STAP 2 hebt gekozen (Uitvoermap selecteren).

PER RECORD GEORGANISEERDE STRUCTUUR:

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Oorspronkelijk IIIF-manifest
├─ [nome]_canvas_1.jpg/.png/.tif     ← Gereconstrueerde afbeeldingen (één per pagina)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = totaal aantal pagina's/canvas)
├─ [nome].json                       ← JSON-sidecar voor elke afbeelding (EXIF)
├─ [nome].pdf                        ← Volledige PDF (alleen indien aangevraagd)
└─ [nome]/                           ← Submap ALLEEN voor metadata
   ├─ [nome]_genealogico.json        ← Genealogische metadata
   └─ [nome]_tecnico.json            ← Technische metadata

MEERDERE RECORDS IN DEZELFDE MAP:

Als je 3 records in dezelfde map verwerkt, wordt de structuur:

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (sidecar)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (sidecar)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (sidecar)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

📌 OPMERKINGEN OVER DE STRUCTUUR:

  • IIIF-manifest, afbeeldingen, PDF, JSON-sidecar: op het hoofdniveau
  • ALLEEN technische en genealogische metadata: in submappen [nome]/ (één per record)
  • De tijdelijke mappen (tiles_canvas_X/) en de tijdelijke bestanden die voor het genereren van de PDF worden gebruikt, worden aan het einde van de verwerking automatisch verwijderd: er blijven geen tussenliggende werkbestanden achter in de uitvoermap
  • Met deze indeling kunnen meerdere records zonder verwarring tussen bestanden in dezelfde map worden beheerd

  • Manifest: manifest_[ID]_[nome].json
  • Afbeeldingen: [nome]_canvas_1, [nome]_canvas_2, ... [nome]_canvas_N
  • JSON-metadata: [nome]_genealogico.json, [nome]_tecnico.json
  • JSON-afbeeldingen: [nome].json (voor elk canvas)
  • PDF: [nome].pdf
