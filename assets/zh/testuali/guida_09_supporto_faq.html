3. 解决问题和问题

────────────────────────────────────────────────────────────────────────────────

常见问题

🔵 问：程序在加载清单时卡住怎么办？

尔: 通常是网络超时。 检查 :

  1. 请检查date=中的日期值 (帮助) 互联网连接通过在浏览器中打开一个可靠的页面来工作 。
  2. 在浏览器中打开 URL IIIF,再从地址栏复制.
  3. 检查防火墙或安全软件允许ATK-Pro连接.
  4. 如果使用代理网络,请检查操作系统网络配置.

如果问题持续存在, 请尝试使用不同的 URL 测试 IIIF 连接

🔵 问：“未找到文件（404）”是什么意思？

尔: 海报 URL 无法访问 。 原因:

  • URL 过期(仓库未更新)
  • 仓库离线
  • 错误的 URL 参数( 错误的列表 ID)

解决方案：粘贴到 ATK-Pro 之前先在浏览器中验证 URL

🔵 问：下载很慢或中断怎么办？

尔: 尝试 :

  1. 检查Wi-Fi网络的稳定性,或在可用的情况下使用有线连接.
  2. 尝试另一个 公共 IIIF URL 以查看减速是否取决于服务器 。
  3. 通过选择资源配置来减少负载 轻量.
  4. 如果问题只涉及一个门户,则信任并再次尝试:远程服务可能拥挤或暂时无法使用.

🔵 问：图像重建很慢，如何加速？

尔: 速度主要取决于IIIF服务器的反应,图像大小,连接和计算机上可用的资源.

  • 使用配置文件 轻量 减少资源消耗或 快速 只有适当的系统。
  • 如果内存或网络受到压力,每次处理日志的页面会减少.
  • 记住,某些门户无论选择的配置为何,都强制进行顺序访问.

🔵 问：输出 PDF 已损坏或无法打开怎么办？

尔: 尝试 :

  1. 保存诊断的有用副本,然后删除或重命名不完整的PDF.
  2. 从 文件输入 ~ 打开输入 并重生PDF.
  3. 确保目的地可写,并有足够的处理空间.
  4. 检查生成的单个图像, 看看这个问题是否只涉及 PDF 。

🔵 问：如何使用 TIFF 文件进行归档？

尔: TIFF是无损格式,适合存储 :

  1. 在图像格式中选择 TIFF 。
  2. ATK-Pro用无损压缩LZW节省TIFF.
  3. 将副本存储在单独的支持上,并定期核查备份的完整性。
  4. 随着时间的推移,存储还取决于媒体、副本和完整性检查,而不仅仅是格式。

🔵 问：可以同时（并行）处理多条记录吗？

尔: 一批记录按顺序处理. 在单一记录中,页面和瓷砖可以根据门户和资源简介平行处理.

  1. 编写一个包含所有支持记录的输入文件,一个接一个.
  2. 从 文件输入 ~ 打开输入.
  3. 开始一次 产出-埃拉布拉.
  4. ATK-Pro自动续作后续记录.

示例:如果输入包含5个记录,ATK-Pro进程会自动:

  • 记录 1 (下载 + 重建)
  • 记录2(下载 + 重建)
  • 最高记录5

结果保存在已配置的文件夹中; 您不需要手动重新启动每个记录的处理 。

🔵 问：文件具体保存在哪里？

尔: 默认路径 :

  • 标准安装 : 文件夹 ATK-Pro/output 在用户文档中。
  • 可移植模式 : 文件夹 output 在可执行文件旁边。

你可以从 设置 — 选择输出文件夹的默认文件夹。

🔵 问：ATK-Pro 为什么会警告或阻止某个输出路径？

尔: 在创建文件之前,ATK-Pro控制为记录规划的最长路线. 最后摘要区分了两种情况:

  • 块错误 : 名称中包含不允许的字符,使用保留的 Windows 名称,以空格或点结尾,或者一段超过支持的限度。 只有受影响的记录被停止,相对的工作手册没有创建.
  • 兼容性通知 : 路径接近一个谨慎的阈值,或者可以在Windows应用较少的情况下造成困难。 处理可以继续进行,但最好选择较短的目的地.

简介 OneDrive/共享点 仅在选定的文件夹实际位于根下时才应用 OneDrive 或 OneDrive - Organizzazione。如果出错,请缩短记录名称,或选择更靠近驱动器根的目的地文件夹;不需要重命名或移动其他处理已经生成的文件。

🔵 问：处理后可以移动输出文件吗？

尔: 是, 最终文件可以在处理后移动 。

完成后:

  1. 将记录文件夹移至新目的地 。
  2. 最终的 PDF 是自主的;如果图像和元数据是您工作存档的一部分,它也会保存它们 。
  3. 如果您希望重做记录,请保留海报和其他源文件.

(掌声) (掌声) @ @P:崩溃突然——怎么办?

尔: 程序是否崩溃 :

  1. 检查 atkpro.log 或者,在积极的扩展诊断中, atkpro_debug.log。位置取决于安装的类型:在可执行文件旁边或应用程序工作目录中搜索。
  2. 复制错误消息或抓取截图 。
  3. 重新启动程序并重复操作.
  4. 如果错误重复发生,请尝试另一个IIIF记录来区分一个一般问题和一个特定的表.

E 常见错误和解决办法

错误 大小写 解决方案
"网络超时" 服务器 IIIF 慢/下行 尝试不同的 URL
"无效IIIF格式" URL 不是 IIIF 清单 在浏览器中检查 URL
"磁盘空间满" 磁盘空间不足 单位空闲空间
"拒绝" 保护文件夹/ 只读 选择属于您的用户的文件夹, 并验证其是否可写入; 避免系统文件夹或保护 。
"没有找到" IIIF 清单已过期 在门户中检查 ID
"窗口没有回应" 处理缓慢/繁重 等待或点击取消

🔵 问：门户已被识别，但下载被拒绝，为什么？

尔: 技术兼容性并不能消除准入条件。 ATK-Pro拒绝或限制需要子公司登录或访问的资源,不暴露稳定的公共端点,被标记为 nodownload 或没有与所需操作相符的权利。 打开主题的公开页面,检查许可证和使用条件,并仅在支持官方URL的情况下尝试.

P:我能收回中断的OCR批次吗?

尔: 检查 OCR 文件的文件夹 *_trascrizione_parziale.txt 及其元数据。 它们包含了逐步节省下来的工作,在考虑确定之前检查和完成。
