保存記録

ポスターをロードした後、プログラムはIIIFメタデータを自動的に保存します。 保存場所：選択した出力フォルダ（セクション 2 の「手順 2」参照） 車の構造(処理の前に):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale (livello principale)
 └─ [nome]/                            ← Sottocartella SOLO per metadati
    ├─ [nome]_genealogico.json        ← Metadati genealogici estratti
    └─ [nome]_tecnico.json            ← Metadati tecnici (canvas ID, numero pagine)

処理後（メニュー → 出力 → 処理をクリックしたとき）： 処理されたファイルがメインレベルで追加されます。

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Immagini ricostruite dai tile IIIF (una per pagina)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (formato dipende da quello selezionato)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = numero totale di pagine/canvas)
 ├─ [nome].json                        ← Sidecar JSON per ogni immagine (metadati EXIF)
 └─ [nome].pdf                         ← PDF completo (vedi spiegazione sotto)

メタデータは、読み込み時に保存されたサブフォルダ [nome]/ に残ります。

注意: ファイル組織

  • マニフェストIIIF:出力フォルダの主なレベル
  • イメージ(キャンバス)、PDF、サイドカーJSON:出力フォルダの主なレベル
  • 技術メタデータと家系メタデータのみ：サブフォルダ [nome]/ に保存
  • 暫定フォルダ(タイルキャンバスX/)は自動的に終了時に削除されます
  • この構造により、混乱することなく複数のレコードを同じフォルダに管理できます。

例: "Register1" を処理すると、次のようになります。

  • ポスター [ID1]_Registro1.json (主要なレベル)
  • Registro1_canvas_1.jpg、Registro1_canvas_2.jpg、... (主要なレベル)
  • Registro1.pdf (主要なレベル)
  • 登録1/(遺伝子・技術メタデータを含むSOLOフォルダ)

2.画像の処理とダウンロード

────────────────────────────────────────────────────────────────────────────────

ダイ処理の流れ

処理ワークフローには3つのステップが含まれます。

ステップ1:画像形式を選択

─────────────────────────────────────

1. 入力ファイルをアップロード(ファイル入力→オープン入力):フォーマットウィンドウが自動的に開きます

2. または「メニュー」→「設定」→「画像形式の選択」をクリック

3。 ダイアログボックスを3つのオプションで開きます。

◀ PNG → 無損失のフォーマット(無光沢)、よりよい質、より大きいファイル

◀ JPG →圧縮されたフォーマット(光沢のある)、よい妥協の質/次元

◀ TIFF → アーカイブ形式、高品質、非常に大きなファイル

PDFドキュメント

◀ PDF → PDFは、選択した画像フォーマットに加えて、レジストリまたは文書のすべてのページで完了します(または画像形式が選択されていない場合にのみ出力)

4. 少なくとも1つのイメージのフォーマットかPDFを選んで下さい(複数の1つを選ぶことができます)

5. 「確認」をクリック

✅ 選択したフォーマットが保存されます 次のプログラムの開口部で自動的に選択します。

: ヒント:

  • プレビュー/コンサルティング用: JPG (高速で開く、より少ないスペース)
  • 保守的なアーカイブ:PNG(ロスレス、スペース妥協)またはTIFF(最高品質)
  • 両方のために: PNG および TIFF 両方を選んで下さい
  • PDF の場合: PDF を 1 つ以上の画像形式とともに選択するか、PDF のみを選択して、画像ファイルなしで別の PDF ドキュメントを作成する

ステップ2:出力フォルダを選択します

──────────────────────────────────────

1。 フォルダウィンドウは、フォーマットを選択すると自動的に開きます(入力ファイルをアップロードする場合)

2. あるいは、メニュー→「設定」→「出力フォルダの選択」をクリック

3. フォルダ組織MODEを選択してください:

❷ すべてのシングルフォルダ → すべてのレコードの単一のフォルダ(ドキュメントとレコード)

2.00 別のフォルダー doc/reg → すべての文書のフォルダー、すべてのログの 1 つ

各レコードのフォルダごと → 入力ファイル内の各レコードの別のフォルダ

4。 モードを選択した後、必要なフォルダ(1、2またはNダイアログボックス)を選択します。

5. 最後に、選択したフォルダの要約が表示されます

✅ モードとフォルダが保存されます. 入力ファイルの次の開口部では、レコード番号と互換性のある場合に自動的に復元されます。

⚠️ 新しい入力ファイルが保存されたフォルダよりも異なる数の Documents/Register がある場合、アラートが表示され、選択が新しいフォルダーを要求するようにリセットされます。

🛡️ 予防的なルート制御: フォルダやファイルを作成する前に、ATK-Pro は、予想される名前とパスを検証します。 Windowsおよび過度に長いセグメントとの互換性のない名前は、影響を受けるレコードのみをブロックします。 互換性のアラートは、最終的な要約に表示されます。

☁️ OneDrive/SharePoint は既定の宛先と仮定しません。 その制限は、選択したフォルダが実際にOneDriveのルートの下にある場合にのみ適用されます。 他のルートでは、260文字の歴史的なWindowsのしきい値がプルーデンシャル警告として扱われ、自動ブロックではありません。

: 要約モード:

  • シングルフォルダ: シンプルで、ひとつひとつの場所で。 速い処理かテストのために適した
  • 別の文書/reg: 種類別組織 デフォルト: output/doc/ そして、 output/reg/
  • 各レコードについて: 最高の柔軟性。 異なるドライブ、NAS、カスタムフォルダを使用できます

COMPORTAMENTO の動作:

  • ✅ フォーマットマスクで選択されたPDF: PDFはダウンロードの最後に自動的に生成されます。追加確認は必要ありません
  • ❌ PDFは選択されていません: 選択したフォーマットの画像のみ、PDF

生成されるPDFの特徴:

  • ファイル名: [nome].pdf, 追加のサフィックスなし (例えば. Registro Matrimoni 1920.pdf)
  • 選択した出力フォルダに保存され、画像と同じレベルで
  • 数値順に成長するページ (canvas 1 → キャンバス 2 → ... → キャンバス N)
  • キャンバスがダウンロードできない場合は、ページを入力 プレースホルダー Antenatiのオリジナルキャンバスに直接リンク
  • 生成終了時に出力フォルダに一時ファイルが残らない

: 処理中に何をすべきか:

  • 〇 外部ディスク(保存エラー)を外さない
  • PC/ラップトップをオフにしないでください
  • 〇インターネットを外さない(リスタのダウンロード)

✅ できること:

  • ✓ PCを他のもののために普通使用して下さい(ちょうど窓を最小にして下さい)

生成PDFを活性化する方法

PDFの生成は箱を選ぶことによって活動化させます PDF フォーマット選択マスク(メニュー→設定→「画像サイズの選択」)

PDFを1つ以上の画像フォーマット(例:PDF + PNG)と組み合わせたり、PDFだけを選択して、別々の画像ファイルなしで文書のみ入手できます。

生成されるPDFのデルの特徴

  • ファイル名: PDFは単に呼ばれます [nome].pdf, 追加の接尾辞なし - 例えば Registro Matrimoni 1920.pdf
  • 所在地: 選択した出力フォルダに保存され、画像と同じレベルで保存します。 [cartella_scelta]\[nome].pdf
  • ページの注文: タイルがダウンロードされる注文に関係なく、ページは常に数値順(canvas 1 → canvas 2 → Canvas N)を成長させています。
  • ページのプレースホルダー: キャンバスが利用できない場合(ネットワークのエラーや一時的に利用できないリソース)、その場所にページが自動入力されます。 プレースホルダー 選択された言語にある。 プレースホルダーページには以下が含まれます。
    • ローカライズされた警告テキスト(例:「イメージが利用できない」)
    • Antenatiのオリジナルキャンバスへの直接リンク(https://antenati.cultura.gov.it/ark:/…)、従って源を容易に相談できます
    このようにして、PDFは常に生成され、アンロードされた画像の場合に必要なすべての情報がすべて生成されます。
  • 自動クリーニング: PDFの生成に使用される一時的なファイルは、プロセスの最後に自動的に削除されます。 出力フォルダでは、画像のみが選択した形式で残っている、最終的なPDF、ポスターやメタデータ

PDFが選択されていない場合:

  • 選択したフォーマットでのみ画像をダウンロード
  • 生成されるPDF無し

5. フォルダと出力ファイル

────────────────────────────────────────────────────────────────────────────────

出力形態の構造

IIIF レコードを処理すると、ATK-Pro は手順 2 で選択したフォルダ（出力フォルダ）にファイルを保存します。

記録のための組織構造:

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale
├─ [nome]_canvas_1.jpg/.png/.tif     ← Immagini ricostruite (una per pagina)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = numero totale pagine/canvas)
├─ [nome].json                       ← Sidecar JSON per ogni immagine (EXIF)
├─ [nome].pdf                        ← PDF completo (solo se richiesto)
└─ [nome]/                           ← Sottocartella SOLO per metadati
   ├─ [nome]_genealogico.json        ← Metadati genealogici
   └─ [nome]_tecnico.json            ← Metadati tecnici

同じフォルダにあるマルチレコード:

同じフォルダに3レコードを処理すると、構造は次のようになります。

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (sidecar)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (sidecar)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (sidecar)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

:構造のノート:

  • マニフェストIIIF、画像、PDF、サイドカーJSON:メインレベルで
  • 技術メタデータと家系メタデータのみ：サブフォルダ [nome]/ (レコードごとの1つ)
  • 仮フォルダ(tiles_canvas_X/) PDFの生成に使用される一時的なファイルは、処理終了時に自動的に削除されます。中間作業ファイルは出力フォルダに残らない
  • この組織は、ファイル間で混乱することなく、同じフォルダに複数のレコードを管理することができます

ディ・ネーミング・コンベンション:

  • マニフェスト: マニフェスト [ID] [名前]. jsonの特長
  • 画像：[nome]_canvas_1、[nome]_canvas_2、…[nome]_canvas_N
  • JSONメタデータ: [名前]_genealogico.json, [名前]_tecnico.json
  • JSON イメージ: [名前]. json(各キャンバス用)
  • PDF: [名前]. pdfの特長
