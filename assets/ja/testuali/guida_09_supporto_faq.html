ATK-PROを閉じる方法

  1. 選択する 設定 → 閉じる;
  2. タイトルバーの最後のボタンを使用します。
  3. Windowsでは、標準的なショートカットを使用します アルト+F4.

閉じるときにオプションのウィンドウが表示されます プロジェクトを支援する.

3. トラブルシューティングとFAQ

────────────────────────────────────────────────────────────────────────────────

よくある質問

P:プログラムはマニフェストのローディングに固執しますか?

R: 通常はネットワークタイムアウトです。 チェック:

  1. お使いのブラウザの信頼できるページを開くことで、インターネット接続が機能していることを確認してください。
  2. ブラウザでURL IIIFを開き、アドレスバーから再度コピーします。
  3. ファイアウォールやセキュリティソフトウェアがATK-Pro接続を許可していることを確認してください。
  4. プロキシネットワークを使用する場合は、オペレーティングシステムのネットワーク設定を確認してください。

問題が主張したら、URL をテストするために別のテストして下さい IIIF の関係を試みて下さい

P: "File not found (404)" - どういう意味ですか?

R: ポスターのURLは到達できません。 原因:

  • URLが期限切れ(リポジトリが更新されていない)
  • リポジトリ オフライン
  • URLパラメータ(誤ったマニフェストID)

ソリューション:ATK-Proで接着する前にブラウザでURLをチェック

P:非常に遅いか、割込みますか?

R: 試してみましょう:

  1. Wi-Fiネットワークの安定性をチェックするか、利用可能な場合は有線接続を使用してください。
  2. 別のパブリックURL IIIFを試して、減速がサーバーに依存しているかどうかを確認します。
  3. リソースプロファイルを選択することにより、負荷を減らす 軽量.
  4. 問題が 1 つのポータルだけに懸念する場合, 信頼し、再試行: リモートサービスは混雑または一時的に利用できなくなることがあります。.

P:Reconstructionの遅いイメージ - 加速する方法?

R: 通信速度は、主にIIIFサーバ、画像サイズ、接続、コンピュータ上で利用可能なリソースの応答に依存します。

  • プロフィールの使用 軽量 資源消費量を減らすため 高速 適切なシステムのみ。
  • メモリやネットワークが圧力下にある場合、ページ数が少ないプロセスログ。
  • 選択したプロファイルに関係なく、いくつかのポータルは順次アクセスを課すことを忘れないでください。

P: PDFの出力は破損していますか、または開いていませんか?

R: 試してみましょう:

  1. 診断の有用なコピーを保ち、その後、不完全なPDFを削除または名前を変更します。
  2. レコードをリロードする ファイル入力 → 入力を開く PDFを再生成します。
  3. 宛先が書けやすく、処理に十分なスペースがあることを確認してください。
  4. 問題がPDFを懸念しているかどうかを確認するために生成された個々の画像を確認してください。

P:アーカイブ用のTIFFファイルを使用するにはどうすればよいですか?

R: TIFFは貯蔵のために完全な無損失のフォーマットです:

  1. 画像フォーマット間でTIFFを選択します。
  2. ATK-Proは、TIFFをロスレス圧縮LZWで保存します。
  3. 異なるサポートでコピーを保存し、定期的にバックアップの完全性を確認します。
  4. 時間の経過とともにストレージは、フォーマットだけでなく、メディア、コピー、整合性チェックにも依存します。

P:複数のレコードを同時に処理できますか?

R: バッチレコードは順番で処理されます。 単一のレコード内では、ポータルとリソースプロファイルに応じて、ページやタイルを並行して処理することができます。

  1. サポートされているすべてのレコードで入力ファイルを準備します。
  2. から選ぶ ファイル入力 → 入力を開く.
  3. 1回のスタート 出力 → Elabora.
  4. ATK-Proは、その後のレコードで自動的に継続します。

例: 入力に 5 レコードが含まれている場合、ATK-Pro は自動的に処理します。

  • レコード1(ダウンロード+再構築)
  • レコード2(ダウンロード+再構築)
  • ... 記録まで 5

結果は、設定されたフォルダに保存されます。各レコードの処理を手動で再起動する必要はありません。

P: ファイルが保存されますか?

R: デフォルトパス:

  • 標準的な取付け: フォルダ ATK-Pro/output ユーザー文書
  • ポータブルモード: フォルダ output 実行可能です。

目的地を変更できます 設定 → 出力フォルダの選択. デフォルトフォルダは自動的に作成されます。

P: なぜ ATK-Pro 信号は出力パスをブロックしますか?

R: ファイルを作成する前に、ATK-Proはレコードの最長のルートを制御します。 最終的な要約は2つの状況を区別します。

  • ブロックエラー: 名前には、許可されていない文字が含まれていて、予約名 Windows を使用して、スペースまたはポイントで終了し、またはセグメントは、サポートされている制限を超える。 影響を受けるレコードが止まり、相対的なワークブックが作成されていない。
  • 互換性の通知: パスは、プルーデンシャルのしきい値に近いか、最近のWindowsアプリケーションで困難を作成することができます。 処理は続行できますが、より短い目的地を選ぶのが最善です。

プロフィール OneDrive/シェアポイント 選択したフォルダが実際にルート下にある場合にのみ適用されます OneDrive または OneDrive - Organizzazione。 エラーの場合、レコード名を短くするか、ドライブルートに近いコピー先フォルダを選択します。 他の処理で既に生成されたファイルを名前を変更したり、移動する必要はありません。

P: 処理後に出力ファイルを移動できますか?

R: はい、処理後に最終ファイルを移動させることができます。

完了後:

  1. レコードフォルダを新しい宛先に移動します。
  2. 最終的なPDFは自律的です。それはまたあなたの仕事のアーカイブの一部である場合イメージおよびメタデータを保ちます。
  3. レコードを再作業すると、ポスターやその他のソースファイルを保存します。

P: 突然クラッシュ - 何をするか?

R: プログラムがクラッシュするかどうか:

  1. チェックイン atkpro.log または、活動的な延長診断と、 atkpro_debug.log. 場所は、インストールの種類によって異なります:実行可能またはアプリケーション作業ディレクトリの横にある検索。
  2. エラーメッセージをコピーするか、スクリーンショットを撮る。
  3. プログラムを再起動し、操作を繰り返します。
  4. エラーが繰り返された場合、別のIIIFレコードを試して、特定のマニフェストから一般的な問題を区別します。

E 一般的なエラーとソリューション

エラー 導入事例 ソリューション
「ネットワークタイムアウト」 サーバー IIIF の遅い/オフライン 別のURLと再度試みて下さい
「無効なIIIFフォーマット」 URLはマニフェストIIIFではないです お使いのブラウザでURLをチェック
「ディスクスペースフル」 不十分なディスクスペース ユニットの空きスペース
「許可拒否」 保護されたフォルダ/読み取り専用 ユーザーに属するフォルダを選択し、書き込み可能であることを確認します。システムフォルダや保護を避けます。
「URLが見つかりません」 マニフェスト IIIF 期限切れ ポータルでIDをチェック
「風に反応しない」 スロー/重い処理 待ってからキャンセルをクリック

P:ポータルは認識されますが、ダウンロードは拒否されます。 なぜ?

R: 技術的な互換性はアクセス条件を除去しません。 ATK-Proは、アフィリエイトログインまたはアクセスを必要とするリソースを拒否または制限し、安定した公開エンドポイントを公開しない、マークされている nodownload または必要な操作と互換性がない。 対象の公開ページを開き、ライセンスと使用条件を確認し、公式のURLでのみテストします。

P: 壊れたOCRのバッチを回復できますか?

R: OCRファイルの選択したフォルダをチェックする *_trascrizione_parziale.txt メタデータ。 これらは、その決定を検討する前に、作業が進行的に保存され、確認し、完了する。
