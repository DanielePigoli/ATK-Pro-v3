Поддерживаемый паспорт

ATK-Pro принимает входные файлы с определенным форматом на основе COPPIE: для обработки записей OGNI предоставьте режим + URL.

Поддерживаемые порталы: копировать и вставлять публичный URL страницы, зрителя, плаката или совместимого PDF. ATK-Pro распознает портал и применяет его технический и пруденциальный режим.

Поддерживаемый указывает проверенную техническую совместимость, а не неизбирательное разрешение на загрузку. Ресурс должен быть общедоступным, и пользователь должен соблюдать права, лицензии, условия использования и ограничения индивидуального портала. ATK-Pro не обходит логины, аффилированные доступы, платные сети или маркеры. nodownload.

2. RIGA 2: URL публичная запись или ресурс

Пример правильного файла input.txt:

# Commenti iniziano con #

RECORD 1 (coppia di righe):
D - Lettera Importante
https://biblioteca.example.org/iiif/doc123/manifest.json

RECORD 2 (coppia di righe):
R - Registro Amministrativo 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

RECORD 3 (coppia di righe):
D - Fotografia Singola
https://collections.example.org/iiif/foto789/manifest.json

Формированные правила:

  • Прозрачные строки: игнорируются (вы можете использовать их для читаемости)
  • Строки, начинающиеся с #: игнорируются как комментарии
  • D/d или R/r режимы: обязательны; верхние и нижние регистры эквивалентны
  • Имя файла: необязательно после режима (например, "D - Name" или только "D")
  • URL: должен начинаться с http:// или https://
  • Пары: режим + URL должен оставаться на последовательных рядах

ВАЛИДАЦИОННЫЙ ПРИЗНАК

После загрузки программа проверяет:

  • URL доступен и доступен
  • Совместимые ресурсы: IIIF v2/v3, поддерживаемая страница, изображение или PDF прямой согласно порталу
  • Количество доступных изображений и холстов
  • Метаданные (название, автор, дата)

ОРИ КОММОН Ошибка

  • "URL недействительный": Контрольная копия/вставка URL
  • «Манифест не найден (404)»: URL истек или ошибся
  • IIIF не поддерживается: Сервер не использует стандарт IIIF
  • «Подключение к тайм-ауту»: медленное/медленное подключение к Интернету

💾 СОХРАНЕНИЕ ЗАПИСИ

После загрузки плаката программа автоматически сохраняет метаданные IIIF. Где: в папке вывода вы выбираете (см. Раздел 2, ШАГ 2) CARTELLE STRUCTURE (до обработки):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale (livello principale)
 └─ [nome]/                            ← Sottocartella SOLO per metadati
    ├─ [nome]_genealogico.json        ← Metadati genealogici estratti
    └─ [nome]_tecnico.json            ← Metadati tecnici (canvas ID, numero pagine)

ПОСЛЕ ОБРАБОТКИ (при нажатии меню → Выход → Обработка): На основном уровне добавляются обработанные файлы:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Immagini ricostruite dai tile IIIF (una per pagina)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (formato dipende da quello selezionato)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = numero totale di pagine/canvas)
 ├─ [nome].json                        ← Sidecar JSON per ogni immagine (metadati EXIF)
 └─ [nome].pdf                         ← PDF completo (vedi spiegazione sotto)

Метаданные остаются в подпапке [имя]/ как сохраненные до загрузки.

Примечание: Файловая организация

  • Манифест IIIF: основной уровень выходной папки
  • Изображения (канвас), PDF, Sidecar JSON: основной уровень выходной папки
  • Только технические и генеалогические метаданные: сохранены в подпапке
  • Временные папки (фрагменты холста X/) автоматически удаляются в конце
  • Эта структура позволяет управлять несколькими записями в одной папке без путаницы.

Пример: Если вы обрабатываете «Регистр 1», вы найдете:

  • Постер [ID1]_Registro1.json (основной уровень)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (основной уровень)
  • Registro1.pdf (основной уровень)
  • Register1/ (папка SOLO с генеалогическими и техническими метаданными)

Процесс обработки включает в себя 3 этапа:

ШАГ 1: ВЫБЕРИТЕ ФОРМАТЫ ИЗОБРАЖЕНИЙ

─────────────────────────────────────

1.Загрузить входной файл (ввод файла → Открытый ввод): окно формата открывается автоматически

2. Альтернативно: Нажмите Меню → «Настройки» → «Выбрать форматы изображений»

3.Открывает диалоговое окно с 3 вариантами:

PNG Формат без потерь (lossless), лучшее качество, большие файлы

JPG Сжатый формат (потерянный), хорошее компромиссное качество/измерение

TIFF Архивный формат, высокое качество, очень большие файлы

PDF-документ

PDF Создает PDF в комплекте со всеми страницами реестра или документа, в дополнение к выбранным форматам изображений (или в качестве единственного вывода, если не выбран формат изображения)

4.Выберите хотя бы один формат изображения или PDF (вы можете выбрать более одного)

5. Нажмите "Подтвердить"

✅ Выбранные форматы хранятся и автоматически выбираются при открытии следующей программы.

📝 СОВЕТЫ:

  • Для предварительного просмотра / консультации: JPG (быстро открывается, меньше места)
  • Для консервативного архива: PNG (без потерь, компромисс пространства) или TIFF (максимальное качество)
  • Выберите PNG и TIFF
  • Для PDF: выберите PDF вместе с одним или несколькими форматами изображений либо выберите только PDF, чтобы создать исключительно PDF-документ без отдельных файлов изображений.

ШАГ 2: ВЫБЕРИТЕ ПАПКИ ВЫВОДА

──────────────────────────────────────

1.Окно папок открывается автоматически после выбора форматов (при загрузке файла ввода)

2. Альтернативно: Нажмите Меню → «Настройки» → «Выберите папки вывода»

3.Выберите организацию папки MODE:

Одиночная папка для всех Единая папка для всех записей (доков и записей)

Отдельные папки doc/reg → папка для всех документов, одна для всех журналов

Для каждой пластинки Отдельная папка для каждой записи во входном файле

4.Выбрав режим, выберите необходимые папки (1, 2 или N диалоговых коробок)

5. В конце показано резюме выбранных папок

✅ Режимы и папки хранятсяПри следующем открытии входного файла они автоматически восстанавливаются, если они совместимы с номером записи.

Если новый вводный файл имеет другое количество Документов/Регистров, чем сохраненные папки, отображается оповещение и выбор сбрасывается для запроса новых папок.

🛡️ Профилактический контроль маршрута: Перед созданием папок или файлов ATK-Pro проверяет ожидаемые имена и пути. Несовместимые имена с Windows и чрезмерно длинные сегменты блокируют только затронутую запись; оповещения о совместимости показаны в итоговой сводке.

☁️ OneDrive/SharePoint не считается местом назначения по умолчанию. Его ограничения применяются только тогда, когда выбранная папка фактически находится под корнем OneDrive. В других маршрутах исторический порог Windows в 260 символов рассматривается как пруденциальное предупреждение, а не как автоматический блок.

РЕПЛОГИРОВАНИЕ:

  • Единая папка: Все просто, в одном месте. Подходит для быстрой обработки или тестирования
  • Отдельный документ/регистрация: Организация по типу. По умолчанию: output/doc/ и output/reg/
  • Для каждой записи: Максимальная гибкость. Вы можете использовать различные диски, NAS, пользовательские папки

Ди Лабур Финестер

Как только вы нажмете «Работа», откроется модальное окно с:

Видимые элементы:

"В прогрессе"

  • Оставайтесь на переднем крае, пока обработка не закончится
  • Вы не можете взаимодействовать с остальной частью GUI.

2: ETICHETTA PROGRESS: "Обработка записей: 2/5 - Файловое имя"

  • Шоу: в настоящее время обработанная запись (2) из общего числа (5)
  • Он также показывает имя файла / регистра при обработке.
  • Он обновляется в режиме реального времени при обработке записей
  • Es: "Обработка записей: 1/3 - Свадебный регистр 1850"

3 DI ПРОГРЕСС БАРРА: визуальный прогресс

  • Численный формат: "2/5" (текущее/общее число)
  • Цветная полоса, продвигающаяся слева направо
  • Достичь 100% (максимальная ширина) при завершении
  • Не показывает процент, только число

4️⃣ КНОПКА [ОТМЕНА]

  • Кликабельность во время обработки
  • Требует прерывания всей партии и закрывает окно прогресса
  • Арест носит кооперативный характер: он может ждать завершения уже идущего односетевого запроса.
  • Ни один вывод удаленной сессии не публикуется в выбранной папке; существующие файлы остаются неизменными.

"Дюранте Лелаборационе"

Базовая программа:

├─ Scarica immagini dai server IIIF
├─ Legge manifest per canvas ID
├─ Ricostruisce tile in immagini complete
├─ Converte nei formati selezionati (PNG, JPG, TIFF)

Выставка GUI проходит в режиме реального времени:

  • Каждые 2-3 секунды обновляется рекордное число
  • Нет блока: интерфейс остается реактивным
  • Вы можете отменить в любое время

⚠️ ЧТО ПРОИСХОДИТ ПРИ НАЖАТИИ «ОТМЕНА»:

1. Требуется совместный арест всей партии

2. Все временные выходы, произведенные отмененной партией, удаляются

3. Файлы, уже присутствующие в выходных папках до запуска, остаются неизменными.

4.Вы можете начать снова из меню → Выход

PDF - ДУРАНТНАЯ АВТОМАТическая ЭНЕРГИЯ

Если вы выбрали PDF В маске выбора формата (ШАГ 1) PDF автоматически генерируется в конце загрузки каждого регистра или документа без дополнительного окна подтверждения.

:Компорт:

  • ✅ PDF выбран в маске формата: PDF автоматически генерируется в конце загрузки; дополнительное подтверждение не требуется.
  • ❌ PDF не выбран: Только изображения в выбранных форматах, без PDF

Основные характеристики PDF:

  • Имя файла: [nome].pdfбез дополнительных суффиксов (например, Registro Matrimoni 1920.pdf)
  • Сохранены в выбранной выходной папке, на том же уровне, что и изображения
  • Страницы в численном порядке растут (canvas 1 → canvas 2 → ... → canvas N)
  • Если холст не загружается, вставляется страница держатель расположен с прямой ссылкой на оригинальное полотно на Antenati
  • Никакие временные файлы не остаются в выходной папке в конце поколения.

  • Оригинальное название: _tecnico.json Технические метаданные (номер холста, идентификатор холста списка, права, сгенерированные файлы)
  • [имя]. json → Sidecar JSON для каждого изображения (встроенные методы EXIF)

ПРИМЕЧАНИЕ НА НОМИ ФИЛЬ:

  • База [имя] взята непосредственно из файла input.txt (логи пользователя)
  • Если вы напишете во входном файле «Зарегистрировать свадьбу 1920», файлы будут:
    • Свадебный регистр 1920_canvas_1.jpg
    • Свадебный регистр 1920_genealogico.json
    • Свадебный регистр 1920_tecnico.json
  • Суффиксы JSON остаются в EN (генеалогическом, техническом)
  • Вы можете использовать имена на любом языке во входном файле (IT, EN, mixed)

3. PDF Для регистров и документов

────────────────────────────────────────────────────────────────────────────────

Как действовать

Поколение PDF активируется путем выбора коробки. PDF в маске выбора формата (Menu → Настройки → «Выбрать размер изображения»).

Вы можете объединить PDF с одним или несколькими форматами изображений (например, PDF + PNG) или выбрать только PDF, чтобы получить только документ без отдельных файлов изображений.

DEL PDF ГЕНЕРАТИЧЕСКАЯ ХАРАКТЕРИСТИКА

  • Имя файла: PDF называется просто [nome].pdfбез дополнительных суффиксов, например Registro Matrimoni 1920.pdf
  • Местонахождение: сохранены в выбранной выходной папке, на том же уровне, что и изображения: [cartella_scelta]\[nome].pdf
  • Заказ страницы: страницы всегда находятся в растущем численном порядке (canvas 1 → canvas 2 → canvas N), независимо от того, в каком порядке загружаются плитки;
  • Заполнитель страниц: Если холст недоступен (ошибка сети или временно недоступный ресурс), страница автоматически вставляется на свое место. держатель Находится на выбранном языке. Страница Placeholder содержит:
    • Локализованный текст предупреждения (например, "Изображение недоступно")
    • Прямая ссылка на оригинальное полотно на Antenatihttps://antenati.cultura.gov.it/ark:/…), так что вы можете легко проконсультироваться с источником
    Таким образом, PDF всегда генерируется со всей информацией, необходимой для его завершения в случае незагруженных изображений.
  • Автоматическая чистка: Временные файлы, используемые для генерации PDF, автоматически удаляются в конце процесса. В выходной папке остаются только изображения в выбранных форматах, итоговый PDF, афиши и метаданные.

Если PDF не выбран:

  • Только изображения загружаются в выбранных форматах.
  • PDF не генерируется

5. ПАПКИ И ВЫХОДНЫЕ ФАЙЛЫ

────────────────────────────────────────────────────────────────────────────────

TURA OUTPUT STRUCTURE

При обработке записи IIIF ATK-Pro сохраняет файлы в выбранной вами папке ШАГ 2.

ОРГАНИЗАЦИОННАЯ СТРУКТУРА ДЛЯ ПРИЗНАНИЯ:

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale
├─ [nome]_canvas_1.jpg/.png/.tif     ← Immagini ricostruite (una per pagina)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = numero totale pagine/canvas)
├─ [nome].json                       ← Sidecar JSON per ogni immagine (EXIF)
├─ [nome].pdf                        ← PDF completo (solo se richiesto)
└─ [nome]/                           ← Sottocartella SOLO per metadati
   ├─ [nome]_genealogico.json        ← Metadati genealogici
   └─ [nome]_tecnico.json            ← Metadati tecnici

НЕСКОЛЬКО ЗАПИСЕЙ В ОДНОЙ ПАПКЕ:

Если вы обрабатываете 3 записи в одной папке, структура становится:

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (sidecar)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (sidecar)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (sidecar)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

Заметки о структуре:

  • Манифест IIIF, Изображения, PDF, Sidecar JSON: в основном уровне
  • ТОЛЬКО технические и генеалогические метаданные: в подпапках [название]/ (по одному на запись)
  • Временные папки (tiles_canvas_X/) и временные файлы, используемые для генерации PDF, автоматически удаляются в конце обработки: в выходной папке не остается промежуточных рабочих файлов.
  • Эта организация позволяет управлять несколькими записями в одной папке без путаницы между файлами.

Конвенция о деноминации:

  • Манифест: явный [ID] [имя]. json
  • Изображения: [имя] холст 1, [имя] холст 2, ... [имя] холст N
  • Метаданные JSON: [имя] _genealogico.json, [имя] _tecnico.json
  • Изображения JSON: [имя]. json (для каждого холста)
  • PDF: [имя]. pdf
