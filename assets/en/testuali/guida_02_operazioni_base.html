1. LOADING RECORDS - INPUT FORMATS

────────────────────────────────────────────────────────────────────────────────

📥 INPUT STRUCTURE AND SUPPORTED PORTALS

ATK-Pro accepts input files in a specific PAIR-based format: For EACH record to be processed, provide Mode + URL.

Supported portals: copy and paste the public URL of the compatible page, viewer, manifest, or PDF. ATK-Pro recognizes the portal and applies the appropriate technical and precautionary mode.

Supported indicates verified technical compatibility, not indiscriminate authorization to download. The resource must be publicly accessible, and the user must comply with the rights, licenses, terms of use, and limitations of each portal. ATK-Pro does not bypass logins, affiliate access, paywalls, or markers nodownload.

Antenati (Italy), Gallica (France), DigiVatLib (Vatican), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Südtirol), e-codices/e-rara/e-manuscripta (Switzerland), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo, and Internet Archive.

1. LINE 1: Mode + Name (optional)

  • D = Single document (a single image/page)
  • R = Register (complete collection of pages/documents)

2. LINE 2: Public URL of the record or resource

Example of a correctly formatted input.txt file:

# Comments begin with #

RECORD 1 (pair of lines):
D - Important Letter
https://biblioteca.example.org/iiif/doc123/manifest.json

RECORD 2 (pair of lines):
R - Administrative Register 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

RECORD 3 (pair of lines):
D - Single Photograph
https://collections.example.org/iiif/foto789/manifest.json

📝 INPUT FORMAT RULES:

  • Blank lines: ignored (you may use them for readability)
  • Lines starting with #: ignored as comments
  • D/d or R/r mode: required; uppercase and lowercase are treated as equivalent
  • File name: optional after the mode (e.g., "D - Name" or simply "D")
  • URL: must begin with http:// or https://
  • Pairs: the mode and URL must appear on consecutive lines

⚙️ HOW TO LOAD THE INPUT — 3 MENU OPTIONS:

OPTION 1: View Input Example ──────────────────────────────────────

1. Click Menu → "Input file" → "Input example"

2. A window opens showing the localized example file

3. You can copy the content and use it as a template for your input file

4. Example file: assets/[language]/testuali/input_link_base.txt

Note on the file name: the distributed file is named input_link_base.txt. The name was normalized in v3 to avoid references to previous versions; the format remains compatible with loading IIIF records.

OPTION 2: Open a Prepared Input File ──────────────────────────────────────

1. Click Menu → "Input file" → "Open input"

2. A file selection dialog opens

3. Select your input.txt file (it must follow the pair format)

4. ATK-Pro automatically loads and reads all records

5. Displays the number of records loaded and ready for processing

OPTION 3: Edit Previously Loaded Input ──────────────────────────────────────────

1. After loading an input file (OPTION 2)

2. Click Menu → "Input file" → "Edit input"

3. A text editor opens with the currently loaded file

4. Edit the pairs (add, remove, or change URLs)

5. Click "Save" to update the records being processed

6. The program reinterprets the updated file

📌 DIFFERENCE BETWEEN D AND R:

  • D (Document): Handles a single image/page
  • → Output: a single file for the document
  • R (Register): Handles multi-page collections
  • → Output: a folder with organized pages + PDF (if requested by the user)

✅ RECORD VALIDATION

After loading, the program checks:

  • ✓ URL is accessible and reachable
  • ✓ Compatible resource: IIIF v2/v3 manifest, supported page, image, or direct PDF, depending on the portal
  • ✓ Number of available images and canvases
  • ✓ Metadata (title, author, date)

❌ COMMON ERRORS

  • "Invalid URL": Check the copied/pasted URL
  • "Manifest not found (404)": The URL has expired or is incorrect
  • "Unsupported IIIF format": The server does not use standard IIIF
  • "Connection timeout": Slow or unavailable Internet connection

💾 SAVING RECORDS

After loading the manifest, the program automatically saves the IIIF metadata. WHERE: In the output folder you select (see Section 2, STEP 2) FOLDER STRUCTURE AFTER LOADING (before processing):

[output_folder]/
 ├─ manifest_[ID]_[name].json         ← Original IIIF manifest (top level)
 └─ [name]/                            ← Subfolder for metadata ONLY
    ├─ [name]_genealogico.json        ← Extracted genealogical metadata
    └─ [name]_tecnico.json            ← Technical metadata (canvas ID, number of pages)

AFTER PROCESSING (when you click Menu → Output → Process): The processed files are added at the top level:

[output_folder]/
 ├─ manifest_[ID]_[name].json         ← Original IIIF manifest
 ├─ [name]_canvas_1.jpg/.png/.tif     ← Images reconstructed from IIIF tiles (one per page)
 ├─ [name]_canvas_2.jpg/.png/.tif       (format depends on the selected option)
 ├─ [name]_canvas_N.jpg/.png/.tif       (N = total number of pages/canvases)
 ├─ [name].json                        ← JSON sidecar for each image (EXIF metadata)
 └─ [name].pdf                         ← Complete PDF (see explanation below)

The metadata remains in the [name]/ subfolder, as saved during loading.

IMPORTANT NOTE: File organization

  • IIIF manifest: top level of the output folder
  • Images (canvases), PDF, JSON sidecars: top level of the output folder
  • Technical and genealogical metadata ONLY: saved in the [name]/ subfolder
  • Temporary folders (tiles_canvas_X/) are automatically deleted upon completion
  • This structure makes it possible to manage multiple records in the same folder without confusion

Example: If you process "Register1", you will find:

  • manifest_[ID1]_Register1.json (top level)
  • Register1_canvas_1.jpg, Register1_canvas_2.jpg, ... (top level)
  • Register1.pdf (top level)
  • Register1/ (subfolder containing ONLY genealogical and technical metadata)

2. IMAGE PROCESSING AND DOWNLOAD

────────────────────────────────────────────────────────────────────────────────

🎯 PROCESSING WORKFLOW

The processing workflow consists of 3 steps:

STEP 1: SELECT IMAGE FORMATS

─────────────────────────────────────

1. Load an input file (Input File → Open Input): the format window opens automatically

2. Alternatively: Click Menu → "Settings" → "Select Image Formats"

3. A dialog box opens with 3 options:

☐ PNG → Lossless format, best quality, larger files

☐ JPG → Compressed (lossy) format, good balance between quality and file size

☐ TIFF → Archival format, highest quality, very large files

PDF Document

☐ PDF → Generates a complete PDF containing all pages of the register or document, in addition to the selected image formats (or as the sole output if no image format is selected)

4. Select at least one image format or PDF (you may select more than one)

5. Click "Confirm"

✅ The selected formats are saved and automatically preselected the next time the program is opened.

📝 TIPS:

  • For previewing/consultation: JPG (quick to open, uses less space)
  • For preservation archiving: PNG (lossless, moderate file size) or TIFF (highest quality)
  • For both: select both PNG and TIFF
  • For PDF: select PDF together with one or more image formats, or select only PDF to generate the PDF document exclusively, without separate image files

STEP 2: SELECT OUTPUT FOLDERS

──────────────────────────────────────

1. The folder window opens automatically after you select the formats (when you load an input file)

2. Alternatively: Click Menu → "Settings" → "Select Output Folders"

3. Choose the folder organization MODE:

⬤ One folder for all → a single folder for all records (documents and registers)

⬤ Separate document/register folders → one folder for all documents and one for all registers

⬤ One folder for each record → a separate folder for each record in the input file

4. After choosing the mode, select the required folders (1, 2, or N dialog windows)

5. Once completed, a summary of the selected folders is displayed

✅ The mode and folders are saved. The next time an input file is opened, they are restored automatically if compatible with the number of records.

⚠️ If the new input file contains a different number of documents or registers than the saved folder configuration, a warning is displayed and the selection is reset in order to request new folders.

📌 MODE SUMMARY:

  • Single folder: Simple, everything in one place. Suitable for quick processing or testing
  • Separate doc/reg: Organization by type. Default: output/doc/ and output/reg/
  • For each record: Maximum flexibility. You can use different drives, NAS, custom folders

STEP 3: START PROCESSING

─────────────────────────────

1. Click Menu → "Output" → "Process"

2. Verify that:

✓ At least 1 image format is selected

✓ At least 1 record is loaded

If these requirements are not met, an error message appears:

❌ "No format selected" → Go to STEP 1

❌ "No records loaded" → Go to Input Loading (Section 1)

📺 PROCESSING WINDOW

As soon as you click "Process," a modal window opens with:

📊 VISIBLE ELEMENTS:

1️⃣ WINDOW TITLE: "Processing in progress"

  • It remains in the foreground until processing is complete
  • You cannot interact with the rest of the GUI

2️⃣ PROGRESS LABEL: "Processing record: 2/5 — File Name"

  • Shows: record currently being processed (2) out of the total (5)
  • Also shows the name of the file/register being processed
  • It updates in real time as the records are processed
  • Example: "Processing record: 1/3 — Marriage Register 1850"

3️⃣ PROGRESS BAR: Visual progress indicator

  • Numeric format: "2/5" (current number / total)
  • Colored bar that advances from left to right
  • Reaches 100% (maximum width) when complete
  • Does NOT show a percentage, only the number

4️⃣ [CANCEL] BUTTON

  • Clickable during processing
  • Requests cancellation of the entire batch and closes the progress window
  • Cancellation is cooperative: it may wait for the single network request already in progress to finish
  • No output from the cancelled session is published to the selected folder; pre-existing files remain unchanged

🔄 DURING PROCESSING

In the background, the program:

├─ Downloads images from IIIF servers
├─ Reads manifests to obtain canvas IDs
├─ Reconstructs tiles into complete images
├─ Converts them to the selected formats (PNG, JPG, TIFF)
└─ Saves them in the selected folders

The GUI displays real-time progress:

  • Updates the record count every 2-3 seconds
  • No freezing: the interface remains responsive
  • You can cancel at any time

⚠️ WHAT HAPPENS IF YOU CLICK CANCEL:

1. Cooperative cancellation of the entire batch is requested

2. All temporary outputs produced by the cancelled batch are removed

3. Files that existed in the output folders before processing began remain unchanged

4. You can restart from Menu → Output → Process

📋 PDF — AUTOMATIC GENERATION DURING PROCESSING

If you selected PDF in the format selection dialog (STEP 1), the PDF is generated automatically after each register or document has finished downloading, without any additional confirmation dialog.

📌 BEHAVIOR:

  • ✅ PDF selected in the format dialog: the PDF is generated automatically after the download is complete; no additional confirmation is requested
  • ❌ PDF not selected: only images in the selected formats, with no PDF

Features of the generated PDF:

  • File name: [name].pdf, without additional suffixes (e.g. Marriage Register 1920.pdf)
  • Saved in the selected output folder, at the same level as the images
  • Pages in ascending numerical order (canvas 1 → canvas 2 → … → canvas N)
  • If a canvas cannot be downloaded, a placeholder page in the selected language is inserted, with a direct link to the original canvas on Antenati
  • No temporary files remain in the output folder after generation is complete

⚠️ WHAT NOT TO DO DURING PROCESSING:

  • ❌ Do not close the program (partial files will be lost)
  • ❌ Do not disconnect the external drive (save error)
  • ❌ Do not shut down the PC/laptop
  • ❌ Do not disconnect from the internet (this stops the download)

✅ WHAT YOU CAN DO:

  • ✓ Wait for it to finish (this is the normal procedure)
  • ✓ Click Cancel if urgent
  • ✓ Use the PC normally for other tasks (just minimize the window)

🎉 PROCESSING COMPLETE

When all records have been processed:

1. The progress window closes automatically

2. A message appears: "Operation completed"

3. Click OK to close the message

4. The progress window disappears completely

Afterwards:

  • View the output files in the folders you selected in STEP 2
  • Each document/register has its own subfolder within the folder you selected
  • The images are ready for use (viewing, printing, archiving, PDF)

✅ OUTPUT GENERATED:

For each processed record, you will find:

  • Images in the selected formats (PNG, JPG, TIFF)
  • manifest_[ID]_[name].json → Original IIIF manifest with structured metadata
  • [name]_genealogico.json → Genealogical metadata (dates, places, names, municipalities, provinces)
  • [name]_tecnico.json → Technical metadata (canvas count, canvas ID list, rights, generated files)
  • [name].json → Sidecar JSON for each image (embedded EXIF metadata)

📝 NOTE ON FILE NAMES:

  • The base [name] is taken directly from the input.txt file (user-entered line)
  • If you enter "Marriage Register 1920" in the input file, the files will be:
    • Marriage Register 1920_canvas_1.jpg
    • Marriage Register 1920_genealogico.json
    • Marriage Register 1920_tecnico.json
  • The JSON suffixes _genealogico and _tecnico remain unchanged for compatibility
  • You can use names in any language in the input file (IT, EN, or mixed)

3. PDF FOR REGISTERS AND DOCUMENTS

────────────────────────────────────────────────────────────────────────────────

HOW TO ENABLE PDF GENERATION

PDF generation is enabled by selecting the PDF checkbox in the format selection dialog (Menu → Settings → "Select image formats").

You can combine PDF with one or more image formats (e.g. PDF + PNG), or select only PDF to obtain exclusively the document, without separate image files.

📄 FEATURES OF THE GENERATED PDF

  • File name: the PDF is simply named [name].pdf, without any additional suffixes — for example Marriage Register 1920.pdf
  • Location: saved in the selected output folder, at the same level as the images: [selected_folder]\[name].pdf
  • Page order: pages are always arranged in ascending numerical order (canvas 1 → canvas 2 → … → canvas N), regardless of the order in which the tiles are downloaded
  • Placeholder pages: if a canvas is unavailable (due to a network error or a temporarily unreachable resource), a placeholder page localized in the selected language is automatically inserted in its place. The placeholder page contains:
    • A localized warning message (e.g. "Image unavailable")
    • The direct link to the original canvas on Antenati (https://antenati.cultura.gov.it/ark:/…), so the source can be easily consulted
    This ensures that the PDF is always generated, with all the information needed to complete it if any images were not downloaded.
  • Automatic cleanup: the temporary files used to generate the PDF are automatically deleted when the process is complete. The output folder retains only the images in the selected formats, the final PDF, the manifests, and the metadata

🚫 If PDF is not selected:

  • Only the images are downloaded in the selected formats
  • No PDF is generated

5. OUTPUT FOLDERS AND FILES

────────────────────────────────────────────────────────────────────────────────

📂 OUTPUT STRUCTURE

When you process an IIIF record, ATK-Pro saves the files in the folder you selected in STEP 2 (Select output folder).

STRUCTURE ORGANIZED BY RECORD:

[output_folder]/
├─ manifest_[ID]_[name].json         ← Original IIIF manifest
├─ [name]_canvas_1.jpg/.png/.tif     ← Reconstructed images (one per page)
├─ [name]_canvas_2.jpg/.png/.tif
├─ [name]_canvas_N.jpg/.png/.tif     ← (N = total number of pages/canvases)
├─ [name].json                       ← JSON sidecar for each image (EXIF)
├─ [name].pdf                        ← Complete PDF (only if requested)
└─ [name]/                           ← Subfolder ONLY for metadata
   ├─ [name]_genealogico.json        ← Genealogical metadata
   └─ [name]_tecnico.json            ← Technical metadata

MULTIPLE RECORDS IN THE SAME FOLDER:

If you process 3 records in the same folder, the structure becomes:

[output_folder]/
├─ manifest_[ID1]_Register1.json
├─ Register1_canvas_1.jpg
├─ Register1_canvas_2.jpg
├─ Register1.json (sidecar)
├─ Register1.pdf
├─ Register1/
│  ├─ Register1_genealogico.json
│  └─ Register1_tecnico.json
├─ manifest_[ID2]_Document2.json
├─ Document2_canvas_1.jpg
├─ Document2.json (sidecar)
├─ Document2.pdf
├─ Document2/
│  ├─ Document2_genealogico.json
│  └─ Document2_tecnico.json
├─ manifest_[ID3]_Register3.json
├─ Register3_canvas_1.jpg
├─ Register3_canvas_2.jpg
├─ Register3.json (sidecar)
├─ Register3.pdf
└─ Register3/
    ├─ Register3_genealogico.json
    └─ Register3_tecnico.json

📌 NOTES ON THE STRUCTURE:

  • IIIF manifest, images, PDF, JSON sidecar: at the top level
  • ONLY technical and genealogical metadata: in [name]/ subfolders (one per record)
  • Temporary folders (tiles_canvas_X/) and temporary files used to generate the PDF are automatically deleted when processing is complete: no intermediate working files remain in the output folder
  • This organization makes it possible to manage multiple records in the same folder without confusion between files

📋 NAMING CONVENTION:

  • Manifest: manifest_[ID]_[name].json
  • Images: [name]_canvas_1, [name]_canvas_2, ... [name]_canvas_N
  • Metadata JSON: [name]_genealogico.json, [name]_tecnico.json
  • Image JSON: [name].json (for each canvas)
  • PDF: [name].pdf
