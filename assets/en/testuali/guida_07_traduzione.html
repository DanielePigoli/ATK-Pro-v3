📌 Overview

The AI-Assisted Paleographic Translation (LLM) module translates transcriptions, paleographic texts, research notes, or .txt files into a modern language selected by the user.

It opens from the Services → OCR Translation menu. The module uses the AI providers configured in ATK-Pro and can retrieve credentials from the shared key vault.

Translation is intended as a reading aid: the result must always be reviewed, especially when the source text contains archaic spellings, Latin, notarial formulas, abbreviations, dialects, or proper names.

🖥️ Interface

The window is organized into a configuration bar, a source text area, a contextual instructions field, and a results area.

Configuration Bar

  • AI provider: choose the service to use from those available in the installation, such as Gemini, OpenAI, Claude, Mistral, xAI, DeepSeek, Groq, HuggingFace, or Ollama.
  • Model: optional field for specifying a particular model supported by the provider. If left blank, ATK-Pro uses the default model set in the configuration.
  • Document Type: select the type of document or text to translate. You can create and remove custom document types; for built-in types, you can edit the prompt through an override but cannot delete the type.
  • API Key and Key Safe: enter the key for the selected provider or open the Key Safe file to view or edit the CSV vault.
  • Target language: choose the modern language in which you want the translation.

Source text

  • Source Text: paste the transcription to be translated or load a file .txt generated previously.
  • Load TXT File: opens a text file and inserts it into the source area.
  • Glossary & Context: allows you to give the model instructions before translation.

Translated result

  • Click Translate Text NOW to start processing.
  • During processing, the results panel displays a waiting message.
  • The result is editable: correct the translation directly before saving it.
  • Save Translation (TXT) exports plain text.
  • Export to Word (DOCX) creates an editable Word document.

📝 The Glossary & Context Field — User Guide

This optional field allows you to instruct the model about the characteristics of the text before processing begins. It is the right place to clarify abbreviations, set phrases, source language, translation criteria, and words that must not be translated.

When to Use It

The field is particularly useful when the text contains:

  • Archaisms and obsolete words that a modern translator might interpret differently
  • Dialect terms (Sicilian, Venetian, Tuscan, etc.) not found in standard dictionaries
  • Recurring legal or notarial formulas with a specific technical meaning
  • Proper names or place names that must not be translated but faithfully transcribed
  • Abbreviations with a conventional meaning in the document corpus

Practical Examples

Example 1 — Nineteenth-century parish record in Sicilian dialect:

f. = son/daughter of
fu = already deceased
q. = quondam (already deceased)
vid. = widow/widower
The months are written in dialect (Jinnaru, Frivaru, Marzu...).
Do not translate proper names (Nunzio, Rosaria, Salvatore...).
The forms of address 'don' and 'donna' indicate people of high rank; retain them.

Example 2 — Notarial deed in medieval Latin:

The text is in notarial Latin. Translate it into modern Italian.
Retain standard legal formulas (rogatio, instrumentum, actum...).
'lib.' = pounds (currency, not weight). 'sol.' = soldi.
Place names in the Latin genitive must always be rendered using their current Italian names.

Example 3 — Personal letter in nineteenth-century Italian:

Text in formal nineteenth-century Italian. Translate it into modern English.
Maintain the formal tone; do not make it colloquial.
'Pregiatissimo' and 'Esimio' are courtesy formulas: render them using appropriate English equivalents.
Do not translate proper names.

Recommended Strategy

  • Build the glossary progressively: produce an initial translation, identify recurring errors, add instructions, and try again.
  • For different registers, keep separate glossaries and paste them into the field before processing.
  • Always specify the language of the source text, especially for Latin, dialects, regional languages, or multilingual documents.
  • Indicate when proper names, place names, titles, or formulas must be retained and not modernized.

📝 Operational Notes

  • Processing is asynchronous: Translate Text NOW is disabled while the request is running, but the window remains responsive. Changes made to the fields while waiting do not alter the request already sent.
  • Long or complex texts may require more time and more manual revisions.
  • The API key may come from the shared vault; provider, model, language, and context are saved as translation-specific preferences.
  • Translation produces text output in TXT or DOCX: it does not generate images, metadata, family trees, or GEDCOM files.
  • Do not send confidential or restricted texts to external providers unless you have verified the terms of use, privacy provisions, and authorizations.
