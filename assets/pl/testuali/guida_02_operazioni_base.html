1. WCZYTANIE REKORDÓW – FORMATY WPROWADZANIA

──────────────────── ──────────────────── ──────────────────── ────────────────────

📥 STRUKTURA WEJŚCIOWA I OBSŁUGIWANE PORTALE

ATK-Pro akceptuje pliki wejściowe o określonym formacie w oparciu o PARY: Dla KAŻDEGO rekordu, który ma zostać przetworzony, podaj Tryb + URL.

Obsługiwane portale: skopiuj i wklej publiczny URL strony, przeglądarki, manifestu lub kompatybilnego PDF. ATK-Pro rozpoznaje portal i stosuje odpowiednią metodę techniczną i ostrożnościową.

Obsługiwane oznacza zweryfikowaną zgodność techniczną, a nie masową autoryzację pobierania. Zasób musi być publicznie dostępny, a użytkownik musi szanować prawa, licencje, warunki korzystania i ograniczenia danego portalu. ATK-Pro nie omija loginów, loginów partnerskich, paywallów ani znaczników nodownload.

1. WIERSZ 1: Tryb + Nazwa (opcjonalnie)

  • D = Pojedynczy dokument (pojedynczy obraz/pagina)
  • R = Rejestr (pełny zbiór stron/documenti)

2. WIERSZ 2: Publiczny URL rekordu lub zasobu

Przykład poprawnego pliku input.txt:

# Commenti iniziano con #

RECORD 1 (coppia di righe):
D - Lettera Importante
https://biblioteca.example.org/iiif/doc123/manifest.json

RECORD 2 (coppia di righe):
R - Registro Amministrativo 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

RECORD 3 (coppia di righe):
D - Fotografia Singola
https://collections.example.org/iiif/foto789/manifest.json

📝 ZASADY FORMATU WPROWADZANIA:

  • Puste linie: ignorowane (można ich użyć dla zwiększenia czytelności)
  • Linie z #: Ignorowane jako komentarze
  • Tryby D/d lub R/r: są obowiązkowe; wielkie i małe litery są równoważne
  • Nazwa pliku: opcjonalna po trybie (np. „D - Nazwa” lub po prostu „D”)
  • URL: musi zaczynać się od http:// lub https://
  • Pary: mode + URL muszą znajdować się w kolejnych liniach

⚙️JAK WCZYTAĆ WEJŚCIE - 3 OPCJE Z MENU:

OPCJA 1: Wyświetl przykładowe dane wejściowe ───────────────────────────────────────

1. Kliknij Menu → „Plik wejściowy” → „Przykład wejściowy”

2. Otworzy się okno pokazujące zlokalizowany plik przykładowy

3. Możesz skopiować zawartość jako szablon pliku wejściowego

4. Przykładowy plik: aktywa/[lingua]/testuali/input_link_base.txt

Uwaga dotycząca nazwy pliku: nazywa się rozpowszechniany plik input_link_base.txt. Nazwa została znormalizowana w wersji 3, aby uniknąć odniesień do poprzednich wersji; format pozostaje zgodny z ładowaniem rekordów IIIF.

OPCJA 2: Otwórz gotowy plik wejściowy ───────────────────────────────────────

1. Kliknij Menu → „Plik wejściowy” → „Otwórz wejście”

2. Otworzy się okno dialogowe wyboru pliku

3. Wybierz plik input.txt (musi przestrzegać formatu par)

4. ATK-Pro automatycznie ładuje i odczytuje wszystkie rekordy

5. Wyświetl liczbę rekordów załadowanych i gotowych do przetworzenia

OPCJA 3: Edytuj dane wejściowe już załadowane ───────────────────── ─────────────────────

1. Po wczytaniu pliku wejściowego (OPCJA 2)

2. Kliknij Menu → „Plik wejściowy” → „Edytuj dane wejściowe”

3. Otworzy się edytor tekstu z aktualnie załadowanym plikiem

4. Edytuj pary (dodaj, usuń, zmień URL)

5. Kliknij „Zapisz”, aby zaktualizować przetwarzane rekordy

6. Program reinterpretuje zaktualizowany plik

📌 RÓŻNICA MIĘDZY D I R:

  • D (Dokument): zarządza pojedynczym obrazem/pagina
  • → Dane wyjściowe: Pojedynczy plik dokumentu
  • R (Rejestr): Zarządza zbiorami wielostronicowymi
  • → Wyjście: folder z uporządkowanymi stronami + PDF (na żądanie użytkownika)

✅WALIDACJA REKORDÓW

Po załadowaniu program sprawdza:

  • ✓ URL dostępny i osiągalny
  • ✓ Zgodny zasób: manifest IIIF v2/v3, obsługiwana strona, obraz lub bezpośredni PDF według portalu
  • ✓ Liczba dostępnych obrazów i płócien
  • ✓ Metadane (tytuł, autor, data)

❌ CZĘSTE BŁĘDY

  • „URL nieprawidłowy”: Sprawdź kopię/incolla URL
  • „Nie znaleziono manifestu (404)”: URL wygasło lub jest nieprawidłowe
  • „Format IIIF nie jest obsługiwany”: Serwer nie używa standardu IIIF
  • „Przekroczono limit czasu połączenia”: Wolne połączenie internetowe/assente

💾 REKORDOWA OSZCZĘDNOŚĆ

Po załadowaniu manifestu program automatycznie zapisuje metadane IIIF. GDZIE: W wybranym przez Ciebie folderze wyjściowym (patrz Sekcja 2, KROK 2) STRUKTURA FOLDERÓW PO WŁADOWANIU (przed obróbką):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale (livello principale)
 └─ [nome]/                            ← Sottocartella SOLO per metadati
    ├─ [nome]_genealogico.json        ← Metadati genealogici estratti
    └─ [nome]_tecnico.json            ← Metadati tecnici (canvas ID, numero pagine)

PO PRZETWARZANIU (po kliknięciu Menu → Wyjście → Proces): Przetworzone pliki dodawane są na poziom główny:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifest IIIF originale
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Immagini ricostruite dai tile IIIF (una per pagina)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (formato dipende da quello selezionato)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = numero totale di pagine/canvas)
 ├─ [nome].json                        ← Sidecar JSON per ogni immagine (metadati EXIF)
 └─ [nome].pdf                         ← PDF completo (vedi spiegazione sotto)

Metadane pozostają w podfolderze [nazwa]/, tak jak zostały zapisane po przesłaniu.

WAŻNA UWAGA: Organizacja plików

  • Manifest IIIF: poziom główny folderu wyjściowego
  • Obrazy (płótno), PDF, Sidecar JSON: poziom główny folderu wyjściowego
  • TYLKO metadane techniczne i genealogiczne: zapisane w podfolderze [nazwa]/
  • Foldery tymczasowe (tiles_canvas_X/) są automatycznie usuwane po zakończeniu
  • Ta struktura pozwala na zarządzanie wieloma rekordami w tym samym folderze bez zamieszania

Przykład: Jeśli przetworzysz „Register1”, znajdziesz:

  • manifest_[ID1]_Registro1.json (najwyższy poziom)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (poziom główny)
  • Registro1.pdf (poziom główny)
  • Registro1/ (podfolder TYLKO z metadanymi genealogicznymi i technicznymi)

2. PRZETWARZANIE I POBIERANIE OBRAZÓW

──────────────────── ──────────────────── ──────────────────── ────────────────────

🎯 PRZEPŁYW PRZETWARZANIA

Proces przetwarzania składa się z 3 kroków:

KROK 1: WYBIERZ FORMATY OBRAZU

─────────────────────────────────────

1. Załaduj plik wejściowy (Plik wejściowy → Otwórz wejście): okno formatów otwiera się automatycznie

2. Alternatywnie: Kliknij Menu → „Ustawienia” → „Wybierz formaty obrazów”

3. Otworzy się okno dialogowe z 3 opcjami:

☐ PNG → Format bezstratny, lepsza jakość, większe pliki

☐ JPG → Format skompresowany (stratny), kompromis dobrej jakości/dimensione

☐ TIFF → Format archiwalny, najwyższa jakość, bardzo duże pliki

Dokument PDF

☐ PDF → Wygeneruj kompletny PDF ze wszystkimi stronami dziennika lub dokumentu, oprócz wybranych formatów obrazu (lub jako jedyny wynik, jeśli nie wybrano żadnego formatu obrazu)

4. Wybierz przynajmniej jeden format obrazu lub PDF (możesz wybrać więcej niż jeden)

5. Kliknij „Potwierdź”

✅ Wybrane formaty zostaną zapisane i automatycznie wybrane przy następnym otwarciu programu.

📝 WSKAZÓWKI:

  • Do podglądu/consultazione: JPG (szybkie otwieranie, mniej miejsca)
  • Dla archiwum konserwatywnego: PNG (bezstratny, kompromis w zakresie przestrzeni) lub TIFF (maksymalna jakość)
  • Dla obu: wybierz zarówno PNG, jak i TIFF
  • Dla PDF: Wybierz PDF wraz z jednym lub kilkoma formatami obrazu lub wybierz sam PDF, aby wygenerować tylko dokument PDF bez oddzielnych plików obrazów

KROK 2: WYBIERZ FOLDERY WYJŚCIOWE

───────────────────────────────────────

1. Okno folderu otwiera się automatycznie po wybraniu formatów (po wczytaniu pliku wejściowego)

2. Alternatywnie: Kliknij Menu → „Ustawienia” → „Wybierz foldery wyjściowe”

3. Wybierz TRYB organizacji folderów:

⬤ Jeden folder dla wszystkich → jeden folder dla wszystkich akt (dokumentów i rejestrów)

⬤ Oddzielne foldery doc/reg → jeden folder na wszystkie dokumenty, jeden na wszystkie rejestry

⬤ Folder dla każdego rekordu → osobny folder dla każdego rekordu w pliku wejściowym

4. Po wybraniu trybu wybierz wymagane foldery (1, 2 lub N okien dialogowych)

5. Na koniec wyświetli się podsumowanie wybranych folderów

✅ Tryby i foldery są przechowywane. Przy następnym otwarciu pliku wejściowego zostaną one automatycznie przywrócone, jeśli są zgodne z liczbą rekordów.

⚠️ Jeśli nowy plik wejściowy zawiera inną liczbę dokumentów /Registri niż liczba zapisanych folderów, wyświetli się ostrzeżenie, a wybór zostanie zresetowany w celu zażądania nowych folderów.

🛡️ Kontrola prewencyjna tras: Przed utworzeniem folderów lub plików ATK-Pro sprawdza oczekiwane nazwy i ścieżki. Nazwy niezgodne z Windows i zbyt długie segmenty blokują tylko dany rekord; Ostrzeżenia dotyczące zgodności są wyświetlane w końcowym podsumowaniu.

☁️ OneDrive/SharePoint nie jest zakładany jako domyślne miejsce docelowe. Jego ograniczenia są stosowane tylko wtedy, gdy wybrany folder faktycznie znajduje się w katalogu głównym OneDrive. W pozostałych ścieżkach historyczny próg Windows wynoszący 260 znaków traktowany jest jako ostrzeżenie ostrożnościowe, a nie automatyczna blokada.

📌 PODSUMOWANIE TRYBU:

  • Pojedynczy folder: Proste, wszystko w jednym miejscu. Nadaje się do szybkiego przetwarzania lub testowania
  • Oddzielny dokument/reg: Organizacja według rodzaju. Wartości domyślne: output/doc/ tj output/reg/
  • Dla każdego rekordu: Maksymalna elastyczność. Możesz używać różnych dysków, NAS, niestandardowych folderów

KROK 3: ROZPOCZNIJ PRZETWARZANIE

─────────────────────────────

1. Kliknij Menu → „Wyjście” → „Proces”

2. Sprawdź, czy:

✓ Wybrano co najmniej 1 format obrazu

✓ Przesłano co najmniej 1 rekord

Jeśli brakuje tych wymagań, pojawi się komunikat o błędzie:

❌ „Nie wybrano formatu” → Przejdź do KROKU 1

❌ „Nie załadowano żadnych rekordów” → Przejdź do Ładowanie danych wejściowych (sekcja 1)

📺 OKNO PRZETWARZANIA

Po kliknięciu „Przetwarzaj” otwiera się okno modalne z:

📊 WIDOCZNE ELEMENTY:

1️⃣ TYTUŁ OKNA: „Przetwarzanie”

  • Pozostaje na pierwszym planie aż do zakończenia przetwarzania
  • Nie możesz wchodzić w interakcję z resztą GUI

2️⃣ ETYKIETA POSTĘPU: „Przetwarzanie rekordów: 2/5 — nazwa pliku”

  • Pokaż: aktualnie przetwarzany rekord (2) z całości (5)
  • Pokazuje także nazwę przetwarzanego pliku /registro
  • Aktualizuje się w czasie rzeczywistym podczas przetwarzania zapisów
  • Np.: „Przetwarzanie rekordu: 1/3 — Rejestr małżeństw 1850”

3️⃣ PASEK POSTĘPU: Postęp wizualny

  • Format liczb: „2/5” (liczba bieżąca/całkowita)
  • Pasek kolorów przesuwający się od lewej do prawej
  • Osiąga 100% (maksymalna szerokość) po zapełnieniu
  • NIE pokazuje procentu, tylko liczbę

PRZYCISK 4️⃣ [ANULUJ].

  • Możliwość kliknięcia podczas przetwarzania
  • Monituje o przerwanie całej partii i zamyka okno postępu
  • Zamknięcie ma charakter kooperacyjny: może poczekać na zakończenie trwającego już pojedynczego żądania sieciowego
  • Żadne dane wyjściowe z anulowanej sesji nie są publikowane w wybranym folderze; istniejące pliki pozostają niezmienione

🔄 PODCZAS PRZETWARZANIA

Program w tle:

├─ Scarica immagini dai server IIIF
├─ Legge manifest per canvas ID
├─ Ricostruisce tile in immagini complete
├─ Converte nei formati selezionati (PNG, JPG, TIFF)
└─ Salva nelle cartelle scelte

GUI pokazuje postęp w czasie rzeczywistym:

  • Co 2-3 sekundy aktualizuje numer rekordu
  • Brak zawieszeń: interfejs pozostaje responsywny
  • Możesz anulować w dowolnym momencie

⚠️ ZACHOWANIE W PRZYPADKU KLIKNIĘCIA ANULUJ:

1. Wnioskuje się o wspólne wyłączenie całej partii

2. Wszystkie tymczasowe wyniki wytworzone przez anulowaną partię zostaną usunięte

3. Pliki znajdujące się już w folderach wyjściowych przed uruchomieniem pozostają niezmienione

4. Możesz zacząć od nowa, wybierając Menu → Wyjście → Proces

📋 PDF — AUTOMATYCZNE GENEROWANIE PODCZAS PRZETWARZANIA

Jeśli wybrałeś PDF w masce wyboru formatu (KROK 1) PDF jest generowany automatycznie na koniec pobierania każdego rejestru lub dokumentu, bez dodatkowego okna potwierdzenia.

📌 ZACHOWANIE:

  • ✅ W masce formatu wybrano PDF: PDF jest generowany automatycznie po zakończeniu pobierania; nie jest wymagane żadne dodatkowe potwierdzenie
  • ❌ Nie wybrano PDF: tylko obrazy w wybranych formatach, bez PDF

Charakterystyka wygenerowanego PDF:

  • Nazwa pliku: [nome].pdf, bez dodatkowych przyrostków (np. Registro Matrimoni 1920.pdf)
  • Zapisane w wybranym folderze wyjściowym, na tym samym poziomie co obrazy
  • Strony w rosnącej kolejności numerycznej (płótno 1 → płótno 2 → … → płótno N)
  • Jeśli płótna nie można pobrać, wstawiana jest strona symbol zastępczy zlokalizowane z bezpośrednim linkiem do oryginalnego płótna na Ancestors
  • Po zakończeniu generowania w folderze wyjściowym nie pozostają żadne pliki tymczasowe

⚠️ CZEGO NIE ROBIĆ PODCZAS PRZETWARZANIA:

  • ❌ Nie zamykaj programu (utrata częściowych plików)
  • ❌ Nie wyjmuj dysku zewnętrznego (błąd zapisu)
  • ❌ Nie wyłączaj PC/laptop
  • ❌ Nie odłączaj Internetu (zatrzymaj pobieranie)

✅ CO MOŻESZ ZROBIĆ:

  • ✓ Poczekaj, aż się zakończy (jest to normalna procedura)
  • ✓ Kliknij Anuluj, jeśli jest to pilne
  • ✓ Normalnie używaj komputera do innych celów (po prostu minimalizuj okno)

🎉 KONIEC PRZETWARZANIA

Po przetworzeniu wszystkich rekordów:

1. Okno postępu zamyka się automatycznie

2. Pojawia się komunikat: „Operacja zakończona”

3. Kliknij OK, aby zamknąć komunikat

4. Okno postępu znika całkowicie

Po:

  • Wyświetl pliki wyjściowe w folderach wybranych w KROKU 2
  • Każdy dokument/registro ma swój własny podfolder w wybranym folderze
  • Obrazy są gotowe do użycia (przeglądanie, drukowanie, archiwizacja, PDF)

✅ WYGENEROWANY WYJŚCIE:

Dla każdego przetworzonego rekordu znajdziesz:

  • Obrazy w wybranych formatach (PNG, JPG, TIFF)
  • manifest_[ID]_[nazwa].json → Oryginalny manifest IIIF z metadanymi strukturalnymi
  • [nazwa]_genealogico.json → Metadane genealogiczne (daty, miejsca, nazwy, gminy, województwa)
  • [nazwa]_tecnico.json → Metadane techniczne (numer płótna, lista identyfikatorów płótna, prawa, wygenerowane pliki)
  • [nazwa].json → Sidecar JSON dla każdego obrazu (osadzone metadane EXIF)

📝 UWAGA DOTYCZĄCA NAZW PLIKÓW:

  • Baza [nazwa] jest pobierana bezpośrednio z pliku input.txt (linia użytkownika)
  • Jeśli w pliku wejściowym wpiszesz „Spis małżeństwa 1920”, plikami będą:
    • Rejestr małżeństw 1920_canvas_1.jpg
    • Rejestr małżeństw 1920_genealogico.json
    • Rejestr małżeństw 1920_tecnico.json
  • Przyrostki JSON pozostają w języku EN (_genealogiczne, _technical) ze względu na kompatybilność
  • W pliku wejściowym możesz używać nazw w dowolnym języku (IT, EN, mieszany)

3. PDF DLA ZAPISÓW I DOKUMENTÓW

──────────────────── ──────────────────── ──────────────────── ────────────────────

JAK AKTYWOWAĆ GENERACJĘ PDF

Generowanie PDF aktywuje się poprzez zaznaczenie pola PDF w masce wyboru formatu (Menu → Ustawienia → „Wybierz formaty obrazu”).

Możesz połączyć PDF z jednym lub większą liczbą formatów obrazu (np. PDF + PNG) lub wybrać tylko PDF, aby otrzymać wyłącznie dokument bez oddzielnych plików graficznych.

📄 FUNKCJE WYGENEROWANEGO PDF

  • Nazwa pliku: PDF nazywa się po prostu [nome].pdf, bez dodatkowych przyrostków – np Registro Matrimoni 1920.pdf
  • Lokalizacja: zapisane w wybranym folderze wyjściowym, na tym samym poziomie co obrazy: [cartella_scelta]\[nome].pdf
  • Kolejność stron: strony są zawsze ułożone w rosnącej kolejności numerycznej (płótno 1 → płótno 2 → … → płótno N), niezależnie od kolejności pobierania kafelków
  • Strony zastępcze: jeśli płótno nie jest dostępne (błąd sieci lub zasób chwilowo nieosiągalny), w jego miejsce automatycznie wstawiana jest strona symbol zastępczy zlokalizowane w wybranym języku. Strona zastępcza zawiera:
    • Zlokalizowany tekst ostrzeżenia (np. „Obraz niedostępny”)
    • Bezpośredni link do oryginalnego płótna na Ancestors (https://antenati.cultura.gov.it/ark:/…), dzięki czemu można łatwo sprawdzić źródło
    W ten sposób zawsze generowany jest PDF ze wszystkimi informacjami niezbędnymi do jego uzupełnienia w przypadku niepobranych obrazów.
  • Automatyczne czyszczenie: pliki tymczasowe użyte do wygenerowania PDF są automatycznie usuwane na końcu procesu. Tylko obrazy w wybranych formatach, ostateczny PDF, manifesty i metadane pozostają w folderze wyjściowym

🚫 Jeśli nie wybrano PDF:

  • Pobierane są tylko obrazy w wybranych formatach
  • Nie wygenerowano PDF

4. 📌 DOSTĘPNE FUNKCJE

Menu „Usługi” zawiera funkcje operacyjne v3: wyszukiwanie wspomagane AI, przeglądanie obrazów, przeglądanie metadanych JSON, OCR Advanced, tłumaczenie OCR i eksport GEDCOM.

1️⃣ WYSZUKIWANIE WSPOMAGANE AI ✅

Asystent przy ustalaniu strategii badań genealogicznych:

  • Przekształcaj nazwiska, miejsca, okresy i cele w leady badawcze
  • Sugeruje portale, filtry i przykładowe zapytania do sprawdzenia ręcznie
  • Obsługuje scenariusze włoskie, włoskojęzyczne, migracyjne i międzynarodowe
  • Umożliwia tworzenie osobistych notatek, porównywanie wielu dostawców i zapisywanie wyników

Stan: ✅ Dostępne – Zobacz Przewodnik wyszukiwania wspomaganego AI

2️⃣ OGLĄDANIE OBRAZU ✅

Zintegrowana przeglądarka obrazów genealogicznych:

  • Obsługiwane formaty: JPG, PNG, TIFF (w tym wielostronicowa nawigacja do przodu TIFF/indietro)
  • Zoom za pomocą kółka myszy i dedykowanych przycisków
  • Przesuwaj, przeciągając myszką
  • Tryby „Dopasuj do okna” i „Piksel 1:1”.
  • Sidecar JSON obok obrazu (EXIF i metadane techniczne)

Stan: ✅ Dostępne – Patrz Przewodnik oglądania zdjęć

3️⃣ WYŚWIETL METADANE JSON ✅

Przeglądarka drzewa metadanych strukturalnych:

  • Bezpośrednie otwieranie plików _genealogico.json tj _tecnico.json
  • Rozszerzalny widok drzewa
  • Sekcje: dane genealogiczne, metadane techniczne, EXIF ​​z obrazów
  • Dopasowany podgląd obrazu obok siebie w panelu metadanych

Stan: ✅ Dostępne – Patrz Przewodnik przeglądania metadanych JSON

4️⃣ OCR ZAAWANSOWANY ✅

Zaawansowane leczenie OCR poprzez wizję LLM:

  • Ekstrakcja tekstu z dokumentów starożytnych (w tym rękopisów w XIX-wiecznym języku włoskim i łacińskim)
  • Utrzymanie struktury układu i referencji (TEI XML)
  • Automatyczne rozpoznawanie i czyszczenie danych strukturalnych (np. tabele, role)
  • Ekstrakcja jednostek (nazw, dat, relacji) w nawigacyjnym formacie JSON

Stan: ✅ Dostępne – Zobacz Zaawansowany podręcznik OCR

5️⃣ TŁUMACZENIE OCR ✅

Tłumaczenie kontekstowe wyodrębnionych lub transkrybowanych tekstów:

  • Tłumaczenie tekstów OCR, transkrypcje ręczne i pliki TXT
  • Stosowanie typów dokumentów, glosariusza i kontekstu
  • Konfigurowalny dostawca AI, opcjonalny szablon i Key Vault
  • Edytowalne wyjście TXT lub DOCX

Stan: ✅ Dostępne – Zobacz Przewodnik tłumaczeń OCR

6️⃣ EKSPORT GEDCOM ✅

Wspomagana analiza genealogiczna i eksport GEDCOM:

  • Uniwersalne wejście z metodą Auto-Discovery, Vision AI lub Refinery LLM
  • Możliwość rozbudowy istniejącej bazy GEDCOM lub CSV
  • Notatki paleograficzne i typologie dokumentów pomagające w ekstrakcji
  • Generowanie pliku genealogia_*.ged należy sprawdzić przed użyciem

Stan: ✅ Dostępne – Patrz Poradnik GEDCOM
