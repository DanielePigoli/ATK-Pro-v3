1. ÎNCĂRCARE ÎNREGISTRĂRI - FORMATE DE INTRARE

──────────────────── ──────────────────── ──────────────────── ────────────────────

📥 STRUCTURA INTRĂRII ȘI PORTALE ACCEPTATE

ATK-Pro acceptă fișiere de intrare cu un format specific bazat pe PERECHI: Pentru fiecare înregistrare de procesat, furnizați Mod + URL.

Portaluri acceptate: copiați și inserați adresa URL publică a paginii, vizualizatorului, manifestului sau PDF compatibil. ATK-Pro recunoaște portalul și aplică modul tehnic și prudențial relevant.

Compatibil indică o compatibilitate tehnică verificată, nu permisiunea de a descărca fără discernământ. Resursa trebuie să fie accesibilă public, iar utilizatorul trebuie să respecte drepturile, licențele, condițiile de utilizare și limitele fiecărui portal. ATK-Pro nu ocolește autentificarea, accesul instituțional, sistemele cu plată sau marcajele nodownload.

1. RÂNDUL 1: Mod + Nume (opțional)

  • D = Document unic (o singură imagine/pagină)
  • R = Registru (colecție completă de pagini/documente)

2. RÂNDUL 2: URL-ul public al înregistrării sau al resursei

Exemplu de fișier input.txt corectat:

# Comentariile încep cu #

ÎNREGISTRAREA 1 (pereche de linii):
D - Scrisoare importantă
https://biblioteca.example.org/iiif/doc123/manifest.json

ÎNREGISTRAREA 2 (pereche de linii):
R - Registrul administrativ 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

ÎNREGISTRAREA 3 (pereche de linii):
D - o singură fotografie
https://collections.example.org/iiif/foto789/manifest.json

📝 REGULI DE FORMAT DE INTRARE:

  • Linii goale: ignorate (le puteți folosi pentru lizibilitate)
  • Rânduri cu #: ignorat ca comentarii
  • Mod D/d sau R/r: acestea sunt obligatorii; majuscule și litere mici sunt echivalente
  • Nume fișier: opțional după modul (de exemplu, „D - Nume” sau doar „D”)
  • URL: trebuie să înceapă cu http:// sau https://
  • Perechi: mod + URL trebuie să fie pe linii consecutive

⚙️ CUM SE ÎNCARCĂ INTRAREA - 3 OPȚIUNI DIN MENIU:

OPȚIUNEA 1: Vedeți exemplu de intrare ───────────────────────────────────────

1. Faceți clic pe Meniu → „Fișier de intrare” → „Exemplu de input”

2. Se deschide o fereastră care arată fișierul exemplu localizat

3. Puteți copia conținutul ca șablon pentru fișierul de intrare

4. Exemple de fișiere: assets/[lingua]/testuali/input_link_base.txt

Notă despre numele fișierului: fișierul distribuit este numit input_link_base.txt. Numele a fost normalizat în v3 pentru a evita referințele la versiunile anterioare; formatul rămâne cel compatibil cu încărcarea înregistrărilor IIIF.

OPȚIUNEA 2: Deschideți un fișier de intrare pregătit ───────────────────────────────────────

1. Faceți clic pe Meniu → „Fișier de intrare” → „Deschide input”

2. Se deschide un dialog de selectare a fișierelor

3. Alegeți fișierul input.txt (trebuie să respecte formatul de perechi)

4. ATK-Pro încarcă și citește automat toate înregistrările

5. Vizualizați numărul de înregistrări încărcate și pregătite pentru procesare

OPȚIUNEA 3: Editați intrarea deja încărcată ───────────────────── ─────────────────────

1. După încărcarea unui fișier de intrare (OPȚIUNEA 2)

2. Faceți clic pe Meniu → „Fișier de intrare” → „Modifică input”

3. Se deschide un editor de text cu fișierul încărcat curent

4. Editați perechi (adăugați, eliminați, schimbați adresa URL)

5. Faceți clic pe „Salvează” pentru a actualiza înregistrările în curs de procesare

6. Programul reinterpretează fișierul actualizat

📌 DIFERENȚA DINTRE D ȘI R:

  • D (Document): Gestionează o singură imagine/pagină
  • → Ieșire: un singur fișier pentru document
  • R (Registry): Gestionează colecțiile cu mai multe pagini
  • → Ieșire: folder cu pagini organizate + PDF (dacă este solicitat de utilizator)

✅ VALIDARE ÎNREGISTRARE

După încărcare, programul verifică:

  • ✓ Adresă URL accesibilă și accesibilă
  • ✓ Resursa compatibila: IIIF v2/v3 manifest, pagina suportata, imagine sau direct PDF conform portalului
  • ✓ Numărul de imagini și canvas-uri disponibile
  • ✓ Metadate (titlu, autor, data)

❌ GREȘELI COMUNE

  • „URL nevalid”: verificați adresa URL copiată și inserată
  • „Manifest negăsit (404)”: adresa URL a expirat sau este incorectă
  • „Format IIIF nu este acceptat”: Serverul nu utilizează standardul IIIF
  • „Expirarea conexiunii”: conexiune lentă sau absentă

💾 SALVARE ÎNREGISTRARE

După încărcarea manifestului, programul salvează automat metadatele IIIF. UNDE: În folderul de ieșire pe care îl alegeți (vezi Secțiunea 2, PASUL 2) STRUCTURA DOSARELOR DUPĂ ÎNCĂRCARE (înainte de procesare):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json ← Manifest original IIIF (nivel principal)
 └─ [nome]/ ← Subfolder NUMAI pentru metadate
    ├─ [nome]_genealogico.json ← Metadatele genealogiei extrase
    └─ [nome]_tecnico.json ← Metadate tehnice (ID-ul canvasului, numărul de pagini)

DUPĂ PROCESARE (când faceți clic pe Meniu → Ieșire → Proces): fișierele procesate sunt adăugate la nivelul principal:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json ← Manifest original IIIF
 ├─ [nome]_canvas_1.jpg/.png/.tif ← Imagini reconstruite din tile-uri IIIF (una pe pagină)
 ├─ [nome]_canvas_2.jpg/.png/.tif (formatul depinde de cel selectat)
 ├─ [nome]_canvas_N.jpg/.png/.tif (N = numărul total de pagini/canvas-uri)
 ├─ [nome].json ← Sidecar JSON pentru fiecare imagine (metadate EXIF)
 └─ [nome].pdf ← PDF complet (a se vedea explicația de mai jos)

Metadatele rămân în subdosarul [nome]/ așa cum au fost salvate la încărcare.

NOTĂ IMPORTANTĂ: Organizarea fișierelor

  • Manifest IIIF: nivelul rădăcină al folderului de ieșire
  • Imagini (canvas-uri), PDF, Sidecar JSON: nivelul rădăcină al folderului de ieșire
  • NUMAI metadate tehnice și genealogice: salvate în subfolderul [nome]/
  • Dosarele temporare (tiles_canvas_X/) sunt șterse automat când ați terminat
  • Această structură vă permite să gestionați mai multe înregistrări în același folder fără confuzie

Exemplu: Dacă procesați „Register1”, veți găsi:

  • manifest_[ID1]_Registro1.json (nivel principal)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (nivel principal)
  • Registro1.pdf (nivel principal)
  • Registro1/ (DOAR subdosarul cu metadate genealogice și tehnice)

2. PROCESAREA ȘI DESCĂRCAREA IMAGINILOR

──────────────────── ──────────────────── ──────────────────── ────────────────────

🎯 FLUXUL DE PROCESARE

Fluxul de lucru de procesare presupune 3 pași:

PASUL 1: SELECTAȚI FORMATELE DE IMAGINE

─────────────────────────────────────

1. Încărcați un fișier de intrare (Fișier de intrare → Deschide input): fereastra de formate se deschide automat

2. Alternativ: faceți clic pe Meniu → „Setări” → „Selectați formate de imagine”

3. Se deschide o casetă de dialog cu 3 opțiuni:

☐ PNG → Format fără pierderi, calitate mai bună, fișiere mai mari

☐ JPG → Format comprimat (cu pierderi), compromis calitate/dimensiune bună

☐ TIFF → Format de arhivă, cea mai înaltă calitate, fișiere foarte mari

Document PDF

☐ PDF → Generați un PDF complet cu toate paginile registrului sau documentului, în plus față de formatele de imagine selectate (sau ca singura ieșire dacă nu este selectat niciun format de imagine)

4. Selectați cel puțin un format de imagine sau PDF (puteți alege mai mult de unul)

5. Faceți clic pe „Confirmă”

✅ Formatele alese sunt stocate și preselectat automat data viitoare când deschideți programul.

📝 SFATURI:

  • Pentru previzualizare/consultare: JPG (se deschide rapid, mai puțin spațiu)
  • Pentru arhiva conservatoare: PNG (fără pierderi, compromis de spațiu) sau TIFF (calitate maximă)
  • Pentru ambele: selectați atât PNG, cât și TIFF
  • Pentru PDF: Selectați PDF împreună cu unul sau mai multe formate de imagine sau selectați PDF singur pentru a genera documentul PDF exclusiv fără fișiere imagine separate

PASUL 2: SELECTAȚI DOSARELE DE IEȘIRE

───────────────────────────────────────

1. Fereastra folderului se deschide automat după alegerea formatelor (când încărcați un fișier de intrare)

2. Alternativ: faceți clic pe Meniu → „Setări” → „Selectați dosarele de ieșire”

3. Alegeți MODUL de organizare a dosarelor:

⬤ Un singur dosar pentru toate înregistrările → un singur folder pentru toate înregistrările (doc și registre)

⬤ Dosare separate: Documente și Registre → un folder pentru toate documentele, unul pentru toate registrele

⬤ Un dosar pentru fiecare înregistrare → un folder separat pentru fiecare înregistrare din fișierul de intrare

4. După alegerea modului, selectați folderele necesare (1, 2 sau N casete de dialog)

5. La final este afișat rezumatul folderelor alese

✅ Modurile și folderele sunt stocate. Data viitoare când un fișier de intrare este deschis, acestea sunt restaurate automat dacă sunt compatibile cu numărul de înregistrări.

⚠️ Dacă noul fișier de intrare are un număr diferit de Documente/Registre decât folderele salvate, este afișat un avertisment și selecția este resetată pentru a solicita noi foldere.

🛡️ Verificarea preventivă a căilor: Înainte de a crea dosare sau fișiere, ATK-Pro verifică numele și căile estimate. Numele incompatibile cu Windows și segmentele excesiv de lungi blochează numai înregistrarea afectată; avertismentele de compatibilitate sunt afișate în rezumatul final.

☁️ OneDrive/SharePoint nu este considerat o destinație implicită. Limitele aferente sunt aplicate numai atunci când dosarul selectat se află efectiv sub o rădăcină OneDrive. Pentru celelalte căi, pragul istoric Windows de 260 de caractere este tratat ca avertisment prudențial, nu ca blocare automată.

📌 REZUMATUL MODURILOR:

  • Dosar unic: Simplu, totul într-un singur loc. Potrivit pentru procesare sau testare rapidă
  • Doc/reg separat: Organizare după tip. Valori implicite: output/doc/ e output/reg/
  • Pentru fiecare înregistrare: Flexibilitate maximă. Puteți utiliza diferite unități, NAS, foldere personalizate

PASUL 3: ÎNCEPEȚI PROCESAREA

─────────────────────────────

1. Faceți clic pe Meniu → „Ieșire” → „Proces”

2. Verificați dacă:

✓ Cel puțin 1 format de imagine selectat

✓ Cel puțin 1 înregistrare încărcată

Dacă aceste cerințe lipsesc, apare un mesaj de eroare:

❌ „Niciun format selectat” → Treceți la PASUL 1

❌ „Nu au fost încărcate înregistrări” → Accesați Încărcarea intrării (Secțiunea 1)

📺 FEREASTRA DE PROCESARE

Imediat ce faceți clic pe „Proces”, se deschide o fereastră modală cu:

📊 ELEMENTE VIZIBILE:

1️⃣ TITLUL FERESTREI: „Procesare”

  • Rămâne în prim-plan până la finalizarea procesării
  • Nu puteți interacționa cu restul interfeței grafice

2️⃣ ETICHETĂ DE PROGRES: „Procesarea înregistrărilor: 2/5 — Nume fișier”

  • Afișați: înregistrarea procesată în prezent (2) din total (5)
  • De asemenea, arată numele fișierului/registrului care este procesat
  • Se actualizează în timp real pe măsură ce procesează înregistrările
  • Ex: „Procesare înregistrări: 1/3 - Registrul căsătoriilor 1850”

3️⃣ BARĂ DE PROGRES: Progres vizual

  • Format de număr: „2/5” (număr curent/total)
  • Bara de culoare progresează de la stânga la dreapta
  • Atinge 100% (lățimea maximă) când este plin
  • NU arata procente, doar numarul

4️⃣ BUTON [ANNULLA]

  • Se poate face clic în timpul procesării
  • Solicită anularea întregului lot și închide fereastra de progres
  • Închiderea este cooperantă: poate aștepta încheierea cererii unice de rețea deja în curs
  • Nicio ieșire din sesiunea anulată nu este publicată în folderul ales; fișierele preexistente rămân neschimbate

📋 PDF — GENERAREA AUTOMATĂ ÎN TIMPUL PRELUCRĂRII

Dacă ați selectat PDF în masca de selecție a formatului (PASUL 1), PDF este generat automat la sfârșitul descărcării fiecărui registru sau document, fără nicio fereastră suplimentară de confirmare.

📌 COMPORTAMENT:

  • ✅ PDF selectat în masca de format: PDF este generat automat la sfârșitul descărcării; nu se cere nicio confirmare suplimentară
  • ❌ PDF nu este selectat: doar imagini în formatele alese, fără PDF

Caracteristici ale PDF generat:

  • Nume fișier: [nome].pdf, fără sufixe suplimentare (de ex. Registro Matrimoni 1920.pdf)
  • Salvat în folderul de ieșire ales, la același nivel cu imaginile
  • Pagini în ordine numerică crescătoare (canvas 1 → canvas 2 → … → canvas N)
  • Dacă un canvas nu poate fi descărcat, este inserată o pagină placeholder localizată, cu un link direct către canvasul original de pe Antenati
  • Nu rămân fișiere temporare în folderul de ieșire după finalizarea generării

⚠️ CE NU ESTE DE FACE ÎN TIMPUL PRELUCRĂRII:

  • ❌ Nu închideți programul (pierderea fișierelor parțiale)
  • ❌ Nu scoateți discul extern (eroare de salvare)
  • ❌ Nu opriți computerul/laptop-ul
  • ❌ Nu deconectați internetul (opriți descărcarea)

✅ CE POȚI FACE:

  • ✓ Așteptați să se termine (aceasta este o procedură normală)
  • ✓ Faceți clic pe Anulare dacă este urgent
  • ✓ Folosiți computerul pentru alte lucruri în mod normal (doar minimizați fereastra)

Când toate înregistrările au fost procesate:

2. Apare un mesaj: „Operațiune finalizată”

Dupa:

  • Fiecare document/registru are propriul său subdosar în folderul pe care îl alegeți

✅ IEȘIRE GENERATĂ:

Pentru fiecare înregistrare procesată veți găsi:

  • [nome]_genealogico.json → Metadate genealogice (date, locuri, nume, municipalități, provincii)

📝 NOTĂ PRIVIND NUMELE DE FIȘIERE:

  • [nome] de bază este preluat direct din fișierul input.txt (linia utilizator)
  • Dacă scrieți în fișierul de intrare „Marriage Registry 1920”, fișierele vor fi:
    • Registrul căsătoriilor 1920_canvas_1.jpg
    • Registrul căsătoriilor 1920_genealogico.json
    • Registrul căsătoriilor 1920_tecnico.json
  • Sufixele JSON rămân în EN (_genealogic, _technical) pentru compatibilitate
  • Puteți folosi nume în orice limbă în fișierul de intrare (IT, EN, mixt)

3. PDF PENTRU ÎNREGISTRĂRI ȘI DOCUMENTE

──────────────────── ──────────────────── ──────────────────── ────────────────────

CUM SE ACTIVEAZĂ GENERAREA PDF

Generarea PDF este activată prin selectarea casetei PDF în masca de selecție a formatului (Meniu → Setări → „Selectați formate de imagine”).

Puteți combina PDF cu unul sau mai multe formate de imagine (de exemplu, PDF + PNG) sau selectați numai PDF pentru a obține exclusiv documentul fără fișiere imagine separate.

📄 CARACTERISTICILE PDF-ULUI GENERAT

  • Nume fișier: PDF este numit pur și simplu [nome].pdf, fără sufixe suplimentare — de ex Registro Matrimoni 1920.pdf
  • Locație: salvate în folderul de ieșire ales, la același nivel cu imaginile: [cartella_scelta]\[nome].pdf
  • Ordinea paginilor: paginile sunt întotdeauna în ordine numerică crescătoare (canvas 1 → canvas 2 → … → canvas N), indiferent de ordinea în care sunt descărcate tile-urile
  • Pagini placeholder: dacă un canvas nu este disponibil (eroare de rețea sau resursă temporar inaccesibilă), în locul său este inserată automat o pagină placeholder localizată în limba selectată. Pagina placeholder conține:
    • Un text de avertizare localizat (de exemplu, „Imaginea nu este disponibilă”)
    • Legătura directă către canvasul original din Antenati (https://antenati.cultura.gov.it/ark:/…), astfel încât să puteți consulta cu ușurință sursa
    În acest fel se generează întotdeauna PDF, cu toate informațiile necesare pentru a-l completa în cazul imaginilor nedescărcate.
  • Curățare automată: fișierele temporare utilizate pentru generarea PDF sunt șterse automat la sfârșitul procesului. Doar imaginile în formatele alese, PDF final, manifestele și metadatele rămân în folderul de ieșire

🚫 Dacă PDF nu este selectat:

  • Doar imaginile sunt descărcate în formatele selectate
  • Nu a fost generat PDF

4. 📌 CARACTERISTICI DISPONIBILE

Meniul „Servicii” conține funcțiile operaționale ale v3: căutare asistată de IA, vizualizare imagini, vizualizare metadate JSON, OCR avansat, traducere OCR și export GEDCOM.

1️⃣ CĂUTARE ASISTATĂ DE IA ✅

Asistent pentru stabilirea strategiilor de cercetare genealogică:

  • Transformă nume de familie, locuri, perioade și obiective în piste de cercetare
  • Sugerează portaluri, filtre și exemple de interogări de verificat manual
  • Susține scenarii italiene, italofone, migratorii și internaționale
  • Permite note personale, compararea cu mai mulți furnizori și salvarea rezultatelor

Stare: ✅ Disponibil - Consultați Ghidul de căutare asistată de IA

2️⃣ VIZUALIZARE IMAGINI ✅

Vizualizator de imagini de genealogie integrat:

  • Formate acceptate: JPG, PNG, TIFF (inclusiv TIFF cu mai multe pagini cu navigare înainte/înapoi)
  • Zoom cu rotița mouse-ului și butoane dedicate
  • Deplasați cu mouse-ul
  • Modurile „Adaptați la fereastră” și „1:1 pixel”.
  • Sidecar JSON alăturat cu imaginea (EXIF și metadate tehnice)

Stare: ✅ Disponibil - Consultați Ghidul de vizualizare a imaginilor

3️⃣ VIZUALIZARE METADATE JSON ✅

Vizualizator arbore pentru metadate structurate:

  • Deschiderea directă a fișierelor _genealogico.json e _tecnico.json
  • Vedere arborescentă extensibilă
  • Secțiuni: date genealogice, metadate tehnice, EXIF din imagini
  • Previzualizarea imaginilor potrivite una lângă alta în panoul de metadate

Stare: ✅ Disponibil - Consultați Ghidul de vizualizare a metadatelor JSON

4️⃣ OCR AVANZAT ✅

Procesare avansată OCR prin LLM Vision:

  • Extragerea textului din documente antice (inclusiv manuscrise în italiană și latină din secolul al XIX-lea)
  • Menținerea structurii aspectului și a referințelor (TEI XML)
  • Recunoașterea și curățarea automată a datelor structurate (de exemplu, tabele, roluri)
  • Extragerea entităților (nume, date, relații) în format navigabil JSON

Stare: ✅ Disponibil - Consultați Ghidul OCR avansat

5️⃣ TRADUCERE OCR ✅

Traducerea contextuală a textelor extrase sau transcrise:

  • Traducerea textelor OCR, transcripții manuale și fișiere TXT
  • Utilizarea tipurilor de documente, a glosarului și a contextului
  • Furnizor AI configurabil, șablon opțional și Key Vault
  • Ieșire TXT sau DOCX editabilă

Stare: ✅ Disponibil - Consultați Ghidul de traducere OCR

6️⃣ EXPORT GEDCOM ✅

Analiză genealogică asistată și export GEDCOM:

  • Intrare universală cu metoda Auto-Discovery, Vision AI sau Refinery LLM
  • Posibilitatea de a mări o bază GEDCOM sau CSV existentă
  • Note paleografice și tipologii documentare pentru a ghida extragerea
  • Generarea unui fișier genealogia_*.ged a fi verificat înainte de utilizare

Stare: ✅ Disponibil - Consultați Ghidul GEDCOM

5. DOSARE ȘI FIȘIERE DE IEȘIRE

──────────────────── ──────────────────── ──────────────────── ────────────────────

📂 STRUCTURA DE IEȘIRE

Când procesați o înregistrare IIIF, ATK-Pro salvează fișierele în folderul pe care l-ați ales în PASUL 2 (Selectați folderul de ieșire).

STRUCTURĂ ORGANIZATĂ PE ÎNREGISTRĂRI:

[cartella_output]/
├─ manifest_[ID]_[nome].json ← Manifest original IIIF
├─ [nome]_canvas_1.jpg/.png/.tif ← Imagini reconstruite (una pe pagină)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif ← (N = numărul total de pagini/canvas-uri)
├─ [nome].json ← Sidecar JSON pentru fiecare imagine (EXIF)
├─ [nome].pdf ← PDF complet (doar dacă este solicitat)
└─ [nome]/ ← Subfolder NUMAI pentru metadate
   ├─ [nome]_genealogico.json ← Metadatele genealogiei
   └─ [nome]_tecnico.json ← Metadate tehnice

MAI MULTE ÎNREGISTRĂRI ÎN ACELAȘI DOSAR:

Dacă procesați 3 înregistrări în același folder, structura devine:

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (autocar)
├─ Registro1.pdf
├─ Înregistrare1/
│ ├─ Registro1_genealogico.json
│ └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (autocar)
├─ Documento2.pdf
├─ Document2/
│ ├─ Documento2_genealogico.json
│ └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (sidecar)
├─ Registro3.pdf
└─ Înregistrare3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

📌 NOTE PRIVIND STRUCTURA:

  • Manifest IIIF, Imagini, PDF, Sidecar JSON: la nivelul principal
  • NUMAI metadate tehnice și genealogice: în [nome]/ subfoldere (unul pe înregistrare)
  • foldere temporare (tiles_canvas_X/) și fișierele temporare utilizate pentru generarea PDF sunt șterse automat la sfârșitul procesării: niciun fișier de lucru intermediar nu rămâne în folderul de ieșire
  • Această organizare vă permite să gestionați mai multe înregistrări în același folder fără confuzie cu fișierele

📋 CONVENȚIA DE DENUMIRE:

  • Manifest: manifest_[ID]_[nome].json
  • Imagini: [nome]_canvas_1, [nome]_canvas_2, ... [nome]_canvas_N
  • Metadatele JSON: [nome]_genealogico.json, [nome]_tecnico.json
  • Imagini JSON: [nome].json (pentru fiecare canvas)
  • PDF: [nome].pdf
