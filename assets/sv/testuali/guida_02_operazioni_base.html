1. LÄSA IN POSTER – INDATAFORMAT

────────────────────────────────────────────────────────────────────────────────

📥 INDATASTRUKTUR OCH PORTALER SOM STÖDS

ATK-Pro accepterar indatafiler i ett specifikt format baserat på PAIR: För VARJE post som ska behandlas, ange State + URL.

Portaler som stöds: kopiera och klistra in den offentliga webbadressen till sidan, visningsprogrammet, manifestet eller kompatibel PDF. ATK-Pro känner igen portalen och tillämpar relevant teknisk och försiktig metod.

Stöds indikerar verifierad teknisk kompatibilitet, inte en obegränsad nedladdningsbehörighet. Resursen ska vara allmänt tillgänglig och användaren måste följa rättigheter, licenser, användarvillkor och begränsningar för den enskilda portalen. ATK-Pro kringgår inte inloggning, institutionell åtkomst, betalväggar eller markörer nodownload.

1. RAD 1: Läge + namn (valfritt)

  • D = Enstaka dokument (en bild/en sida)
  • R = Register (komplett samling av sidor/dokument)

2. RAD 2: Postens eller resursens offentliga URL

Exempel på en korrekt input.txt-fil:

# Kommentarer börjar med #

POST 1 (radpar):
D - Viktigt brev
https://biblioteca.example.org/iiif/doc123/manifest.json

POST 2 (par rader):
R - Förvaltningsregistret 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

POST 3 (radpar):
D - Enstaka fotografi
https://collections.example.org/iiif/foto789/manifest.json

📝 REGLER FÖR INDATAFORMAT:

  • Tomma rader: ignoreras (du kan använda dem för bättre läsbarhet)
  • Rader med #: ignoreras som kommentarer
  • Läge D/d eller R/r: är obligatoriskt; stora och små bokstäver behandlas på samma sätt
  • Filnamn: valfritt efter läge (t.ex. endast "D - Namn" eller "D")
  • URL: måste börja med http:// eller https://
  • Par: läge + URL måste finnas på två på varandra följande rader

📌 SKILLNADEN MELLAN D OCH R:

  • D (Dokument): Hanterar en enda bild/en sida
  • → Utdata: en enda fil för dokumentet
  • R (Register): Hanterar samlingar med flera sidor
  • → Utdata: mapp med organiserade sidor + PDF (om användaren vill ha det)

✅ VALIDERING AV REKORD

Efter laddning kontrollerar programmet:

  • ✓ Att webbadressen är tillgänglig och kan nås
  • ✓ Kompatibel resurs: IIIF v2/v3-manifest, sida som stöds, bild eller direkt PDF beroende på portalen
  • ✓ Antal tillgängliga bilder och dukar
  • ✓ Metadata (titel, författare, datum)

❌ VANLIGA FEL

  • "Ogiltig URL": Kontrollera den kopierade/klistrade webbadressen
  • "Manifest hittades inte (404)": URL har löpt ut eller är felaktig
  • "IIIF-format stöds inte": Servern använder inte standard IIIF
  • "Timeout för anslutning": Internetanslutningen är långsam eller saknas

💾 SPARA POSTER

Efter att ha laddat manifestet sparar programmet automatiskt IIIF-metadata. VAR: I önskad utdatamapp (se avsnitt 2, STEG 2) MAPPSTRUKTUR EFTER LADNING (före bearbetning):

[cartella_output]/
 ├─ manifest_[ID]_[nome].json ← Original IIIF-manifest (översta nivå)
 └─ [nome]/ ← Undermapp ENDAST för metadata
    ├─ [nome]_genealogico.json ← Extraherade genealogiska metadata
    └─ [nome]_tecnico.json ← Teknisk metadata (canvas ID, antal sidor)

EFTER BEHANDLING (när du klickar på Meny → Utdata → Process): På den översta nivån läggs de bearbetade filerna till:

[cartella_output]/
 ├─ manifest_[ID]_[nome].json ← Original IIIF-manifest
 ├─ [nome]_canvas_1.jpg/.png/.tif ← Bilder rekonstruerade från IIIF-brickor (en per sida)
 ├─ [nome]_canvas_2.jpg/.png/.tif (format beror på valt)
 ├─ [nome]_canvas_N.jpg/.png/.tif (N = totalt antal sidor/canvas)
 ├─ [nome].json ← JSON sidovagn för varje bild (EXIF-metadata)
 └─ [nome].pdf ← Komplett PDF (se förklaring nedan)

Metadata finns kvar i undermappen [nome]/ eftersom den sparades vid laddning.

VIKTIG ANMÄRKNING: Filorganisation

  • IIIF-manifest: toppnivå i utdatakatalog
  • Bilder (canvas), PDF, JSON sidovagn: översta nivån i utdatamappen
  • ENDAST teknisk och genealogisk metadata: lagras i undermappen [nome]/
  • Tillfälliga mappar (tiles_canvas_X/) raderas automatiskt när bearbetningen är klar
  • Denna struktur tillåter hantering av flera poster i samma katalog utan förvirring

Exempel: Om du bearbetar "Registro1" hittar du:

  • manifest_[ID1]_Registro1.json (översta nivå)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (översta nivå)
  • Registro1.pdf (översta nivå)
  • Registro1/ (undermapp ENDAST med genealogisk och teknisk metadata)

2. BEHANDLING OCH NEDLADDNING AV BILDER

────────────────────────────────────────────────────────────────────────────────

🎯 ARBETSFLÖDE

Bearbetningsarbetsflödet består av tre steg:

STEG 1: VÄLJ BILDFORMAT

─────────────────────────────────────

1. Ladda en indatafil (Indatafil → Öppna inmatning): formatfönstret öppnas automatiskt

2. Alternativt: Klicka på Meny → "Inställningar" → "Välj bildformat"

3. En dialogruta öppnas med 3 alternativ:

☐ PNG → Förlustfritt format, bästa kvalitet, större filer

☐ JPG → Komprimerat format (förlustig), bra kompromiss mellan kvalitet och filstorlek

☐ TIFF → Arkivformat, högsta kvalitet, mycket stora filer

PDF-dokument

☐ PDF → Genererar en komplett PDF med alla sidor i registret eller dokumentet utöver de valda bildformaten (eller som enda utdata om inget bildformat är valt)

4. Välj minst ett bildformat eller PDF (du kan välja fler)

5. Klicka på "Bekräfta"

✅ De valda formaten sparas och är automatiskt förvald nästa gång programmet öppnas.

📝 REKOMMENDATIONER:

  • För förhandsvisning/konsultation: JPG (snabb att öppna, mindre utrymmesförbrukning)
  • För bevarande arkiv: PNG (förlustfri, bra utrymme kompromiss) eller TIFF (högsta kvalitet)
  • För båda ändamålen: välj både PNG och TIFF
  • För PDF: välj PDF tillsammans med ett eller flera bildformat, eller välj endast PDF för att generera endast PDF-dokumentet utan separata bildfiler

STEG 2: VÄLJ UTDATAMAPP

──────────────────────────────────────

1. Mappfönstret öppnas automatiskt efter val av format (när en indatafil laddas)

2. Alternativt: Klicka på Meny → "Inställningar" → "Välj utdatamappar"

3. Välj LÄGE för att organisera mappar:

⬤ En gemensam mapp för alla → en gemensam mapp för alla poster (dokument och register)

⬤ Separata mappar för doc./reg. → en mapp för alla dokument och en för alla register

⬤ En mapp för varje post → en separat mapp för varje post i inmatningsfilen

4. När läget är valt, välj önskade mappar (1, 2 eller N dialogrutor)

5. Slutligen visas en översikt över de valda mapparna

✅ Status och mappar sparas. Nästa gång en indatafil öppnas återställs de automatiskt om de är kompatibla med antalet poster.

⚠️ Om den nya indatafilen har ett annat antal dokument/register än de sparade mapparna, visas en varning och valet återställs för att tillåta att nya mappar kan väljas.

🛡️ Förhandskontroll av sökväg: innan mappar eller filer skapas kontrollerar ATK-Pro de planerade namnen och sökvägarna. Namn som är inkompatibla med Windows och segment som är för långa blockerar endast den berörda posten; kompatibilitetsvarningar visas i den slutliga sammanfattningen.

☁️ OneDrive/SharePoint antas inte vara standarddestinationen. De associerade begränsningarna tillämpas endast när den valda mappen faktiskt är under en OneDrive-rot. På andra vägar behandlas Windows historiska gräns på 260 tecken som en varning och inte som en automatisk blockering.

📌 ÖVERSIKT ÖVER VILLKOR:

  • Delad mapp: Enkelt, allt på ett ställe. Lämplig för snabba behandlingar eller tester
  • Separat dokument/reg.: Organisation efter typ. Standard: output/doc/ och output/reg/
  • För varje post: Maximal flexibilitet. Du kan använda olika enheter, NAS och anpassade mappar

📋 PDF — AUTOMATISK GENERERING VID BEHANDLING

Om du har valt PDF i formatvalsdialogrutan (STEG 1), skapas PDF-filen automatiskt när nedladdningen av varje post eller dokument är klar, utan ytterligare bekräftelsefönster.

📌 FUNKTION:

  • ✅ PDF vald i dialogrutan för val av format: PDF-filen genereras automatiskt när nedladdningen är klar; ingen ytterligare bekräftelse begärs
  • ❌ PDF inte vald: endast bilder i de valda formaten, ingen PDF

Egenskaper för den genererade PDF-filen:

  • Filnamn: [nome].pdf, utan ytterligare suffix (t.ex Registro Matrimoni 1920.pdf)
  • Lagras i den valda utdatamappen på samma nivå som bilderna
  • Sidor i stigande numerisk ordning (duk 1 → duk 2 → … → duk N)
  • Om en duk inte kan laddas ner, infogas en platshållare ligger med direktlänk till originalduk på Antenati
  • Inga temporära filer finns kvar i utdatamappen efter att genereringen är klar

⚠️ VAD DU INTE BÖR GÖRA UNDER BEHANDLINGEN:

  • ❌ Stäng inte programmet (delfiler går förlorade)
  • ❌ Avmontera inte en extern disk (misslyckande att spara)
  • ❌ Stäng inte av PC/bärbar dator
  • ❌ Koppla inte från internetanslutningen (nedladdningen slutar)

✅ VAD DU KAN GÖRA:

  • ✓ Vänta tills processen är klar (detta är den normala proceduren)
  • ✓ Klicka på Avbryt om det behövs
  • ✓ Använd datorn normalt för andra saker (minimera bara fönstret)

🎉 BEHANDLING AVSLUTAD

När alla poster har bearbetats:

1. Förloppsfönstret stängs automatiskt

2. Ett meddelande visas: "Åtgärd slutförd"

3. Klicka på OK för att stänga meddelandet

4. Förloppsfönstret försvinner helt

Sedan:

  • Visa utdatafilerna i de mappar du valde i STEG 2
  • Varje dokument/register har sin egen undermapp i den mapp du valt
  • Bilderna är redo att användas (visa, skriv ut, arkivera, PDF)

✅ GENERERAD UTDATA:

För varje bearbetad artikel hittar du:

  • Bilder i de valda formaten (PNG, JPG, TIFF)
  • manifest_[ID]_[nome].json → Original IIIF-manifest med strukturerad metadata
  • [nome]_genealogico.json → Genealogisk metadata (datum, platser, namn, kommuner, provinser)
  • [nome]_tecnico.json → Teknisk metadata (antal canvas, lista över canvas-ID, rättigheter, genererade filer)
  • [nome].json → JSON sidovagn för varje bild (inbäddad EXIF-metadata)

📝 NOTERA OM FILNAMN:

  • Basnamnet [nome] tas direkt från filen input.txt (användarens rad)
  • Om du skriver "Registro Matrimoni 1920" i indatafilen blir filerna:
    • Registro Matrimonio 1920_canvas_1.jpg
    • Registro Matrimoni 1920_genealogico.json
    • Registro Matrimoni 1920_tecnico.json
  • JSON-suffix finns kvar på EN (_genealogico,_tecnico) av kompatibilitetsskäl
  • Du kan använda namn på vilket språk som helst i inmatningsfilen (IT, EN, blandad)

3. PDF FÖR REGISTER OCH DOKUMENT

────────────────────────────────────────────────────────────────────────────────

HUR MAN AKTIVERAR PDF-GENERERING

PDF-generering aktiveras genom att markera rutan PDF i dialogrutan Formatval (→Menyalternativ → "Välj bildformat").

Du kan kombinera PDF med ett eller flera bildformat (t.ex. PDF + PNG) eller bara välja PDF för att få dokumentet utan separata bildfiler.

📄 EGENSKAPER FÖR DEN GENERERADE PDF-FILEN

  • Filnamn: PDF-filen heter helt enkelt [nome].pdf, utan ytterligare suffix — till exempel Registro Matrimoni 1920.pdf
  • Placering: sparas i den valda utdatamappen på samma nivå som bilderna: [cartella_scelta]\[nome].pdf
  • Sidordning: sidorna är alltid i stigande numerisk ordning (canvas 1 → canvas 2 → … → canvas N), oavsett i vilken ordning tiles laddas ned
  • Platshållarsidor: om en canvas inte är tillgänglig (nätverksfel eller en tillfälligt otillgänglig resurs) infogas automatiskt en platshållare på det valda språket. Platshållarsidan innehåller:
    • En lokaliserad varningstext (t.ex. "Bild ej tillgänglig")
    • Direktlänken till den ursprungliga canvasen på Antenati (https://antenati.cultura.gov.it/ark:/…), så att källan lätt kan konsulteras
    På detta sätt genereras alltid PDF-filen med all information som behövs för att komplettera den om några bilder inte kunde laddas ned.
  • Automatisk rensning: de temporära filerna som används för PDF-generering raderas automatiskt när processen är klar. I utdatamappen finns bara bilderna i de valda formaten, den slutliga PDF-filen, manifesten och metadata kvar

🚫 Om PDF inte är valt:

  • Endast bilderna laddas ner i de valda formaten
  • Ingen PDF genereras

4️⃣ AVANCERAD OCR ✅

Status: ✅ Tillgänglig – Se instruktionerna för avancerad OCR

5️⃣ OCR-ÖVERSÄTTNING ✅

  • Konfigurerbar AI-leverantör, valfri modell och nyckellåda
  • Utdata som TXT eller redigerbar DOCX

Status: ✅ Tillgänglig – Se instruktionerna för OCR-översättning

6️⃣ GEDCOM-EXPORT ✅

Assisterad genealogisk analys och GEDCOM-export:

📂 UTDATASTRUKTUR

När du bearbetar en IIIF-post sparar ATK-Pro filerna i den mapp du valde i STEG 2 (Välj utmatningsmapp).

STRUKTUR ORGANISERAD PER POST:

├─ manifest_[ID]_[nome].json ← Original IIIF-manifest
├─ [nome]_canvas_1.jpg/.png/.tif ← Rekonstruerade bilder (en per sida)

📌 STRUKTURANMÄRKNINGAR:

  • IIIF-manifest, bilder, PDF, JSON sidovagn: på huvudnivån
  • ENDAST teknisk och genealogisk metadata: i undermapparna [nome]/ (en per post)
  • De tillfälliga mapparna (tiles_canvas_X/) och de temporära filerna som används för PDF-genereringen raderas automatiskt när bearbetningen är klar: inga mellanliggande arbetsfiler finns kvar i utdatamappen
