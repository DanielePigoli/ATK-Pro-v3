1. CARGA DE REGISTROS - FORMATOS DE ENTRADA

────────────────────────────────────────────────────────────────────────────────

📥 ESTRUCTURA DE LA ENTRADA Y PORTALES COMPATIBLES

ATK-Pro acepta archivos de entrada con un formato específico basado en PARES: para CADA registro que se vaya a procesar, proporciona Modalidad + URL.

Portales compatibles: copia y pega la URL pública de la página, del visor, del manifiesto o del PDF compatible. ATK-Pro reconoce el portal y aplica la modalidad técnica y de precaución correspondiente.

Compatible indica una compatibilidad técnica verificada, no una autorización indiscriminada para la descarga. El recurso debe ser de acceso público y el usuario debe respetar los derechos, las licencias, las condiciones de uso y los límites de cada portal. ATK-Pro no elude inicios de sesión, accesos de afiliados, muros de pago ni marcadores nodownload.

Antenati (Italia), Gallica (Francia), DigiVatLib (Vaticano), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Südtirol), e-codices/e-rara/e-manuscripta (Suiza), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo e Internet Archive.

1. LÍNEA 1: Modalidad + Nombre (opcional)

  • D = Documento único (una sola imagen/página)
  • R = Registro (colección completa de páginas/documentos)

2. LÍNEA 2: URL pública del registro o del recurso

Ejemplo de archivo input.txt correcto:

# Los comentarios comienzan con #

REGISTRO 1 (par de líneas):
D - Carta importante
https://biblioteca.example.org/iiif/doc123/manifest.json

REGISTRO 2 (par de líneas):
R - Registro administrativo 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

REGISTRO 3 (par de líneas):
D - Fotografía individual
https://collections.example.org/iiif/foto789/manifest.json

📝 REGLAS DEL FORMATO DE ENTRADA:

  • Líneas vacías: se ignoran (puedes utilizarlas para facilitar la lectura)
  • Líneas con #: se ignoran como comentarios
  • Modalidades D/d o R/r: son obligatorias; las mayúsculas y minúsculas son equivalentes
  • Nombre de archivo: opcional después de la modalidad (p. ej., "D - Nombre" o solo "D")
  • URL: debe comenzar por http:// o https://
  • Pares: la modalidad y la URL deben aparecer en líneas consecutivas

⚙️ CÓMO CARGAR LA ENTRADA - 3 OPCIONES DEL MENÚ:

OPCIÓN 1: Ver ejemplo de entrada ──────────────────────────────────────

1. Haz clic en Menú → "Archivo de entrada" → "Ejemplo de entrada"

2. Se abre una ventana que muestra el archivo de ejemplo localizado

3. Puedes copiar el contenido como plantilla para tu archivo de entrada

4. Archivo de ejemplo: assets/[idioma]/testuali/input_link_base.txt

Nota sobre el nombre del archivo: el archivo distribuido se llama input_link_base.txt. El nombre se normalizó en la v3 para evitar referencias a versiones anteriores; el formato sigue siendo compatible con la carga de registros IIIF.

OPCIÓN 2: Abrir un archivo de entrada preparado ──────────────────────────────────────

1. Haz clic en Menú → "Archivo de entrada" → "Abrir entrada"

2. Se abre un cuadro de diálogo para seleccionar archivos

3. Elige tu archivo input.txt (debe respetar el formato de pares)

4. ATK-Pro carga y lee automáticamente todos los registros

5. Muestra el número de registros cargados y listos para su procesamiento

OPCIÓN 3: Modificar entrada ya cargada ──────────────────────────────────────────

1. Después de cargar un archivo de entrada (OPCIÓN 2)

2. Haz clic en Menú → "Archivo de entrada" → "Modificar entrada"

3. Se abre un editor de texto con el archivo cargado actualmente

4. Modifica los pares (añade, elimina o cambia URL)

5. Haz clic en "Guardar" para actualizar los registros que se van a procesar

6. El programa vuelve a interpretar el archivo actualizado

📌 DIFERENCIA ENTRE D Y R:

  • D (Documento): Gestiona una única imagen/página
  • → Salida: un único archivo para el documento
  • R (Registro): Gestiona colecciones de varias páginas
  • → Salida: carpeta con páginas organizadas + PDF (si el usuario lo solicita)

✅ VALIDACIÓN DE REGISTROS

Después de la carga, el programa verifica:

  • ✓ URL accesible y alcanzable
  • ✓ Recurso compatible: manifiesto IIIF v2/v3, página compatible, imagen o PDF directo según el portal
  • ✓ Número de imágenes y lienzos disponibles
  • ✓ Metadatos (título, autor, fecha)

❌ ERRORES COMUNES

  • "URL no válida": Comprueba que hayas copiado y pegado correctamente la URL
  • "Manifiesto no encontrado (404)": La URL ha caducado o es incorrecta
  • "Formato IIIF no compatible": El servidor no utiliza el estándar IIIF
  • "Tiempo de espera de conexión": La conexión a Internet es lenta o no está disponible

💾 GUARDADO DE REGISTROS

Después de cargar el manifiesto, el programa guarda automáticamente los metadatos IIIF. DÓNDE: En la carpeta de salida que elijas (consulta la Sección 2, PASO 2) ESTRUCTURA DE CARPETAS DESPUÉS DE LA CARGA (antes del procesamiento):

[carpeta_salida]/
 ├─ manifest_[ID]_[nombre].json         ← Manifiesto IIIF original (nivel principal)
 └─ [nombre]/                            ← Subcarpeta SOLO para metadatos
    ├─ [nombre]_genealogico.json        ← Metadatos genealógicos extraídos
    └─ [nombre]_tecnico.json            ← Metadatos técnicos (ID del lienzo, número de páginas)

DESPUÉS DEL PROCESAMIENTO (cuando haces clic en Menú → Salida → Procesar): Los archivos procesados se añaden al nivel principal:

[carpeta_salida]/
 ├─ manifest_[ID]_[nombre].json         ← Manifiesto IIIF original
 ├─ [nombre]_canvas_1.jpg/.png/.tif     ← Imágenes reconstruidas a partir de los mosaicos IIIF (una por página)
 ├─ [nombre]_canvas_2.jpg/.png/.tif       (el formato depende del seleccionado)
 ├─ [nombre]_canvas_N.jpg/.png/.tif       (N = número total de páginas/lienzos)
 ├─ [nombre].json                        ← Archivo JSON auxiliar para cada imagen (metadatos EXIF)
 └─ [nombre].pdf                         ← PDF completo (consulta la explicación siguiente)

Los metadatos permanecen en la subcarpeta [nombre]/ tal como se guardaron durante la carga.

NOTA IMPORTANTE: Organización de los archivos

  • Manifiesto IIIF: nivel principal de la carpeta de salida
  • Imágenes (lienzos), PDF y archivos JSON auxiliares: nivel principal de la carpeta de salida
  • SOLO los metadatos técnicos y genealógicos: se guardan en la subcarpeta [nombre]/
  • Las carpetas temporales (tiles_canvas_X/) se eliminan automáticamente al finalizar
  • Esta estructura permite gestionar varios registros en la misma carpeta sin confusiones

Ejemplo: Si procesas "Registro1", encontrarás:

  • manifest_[ID1]_Registro1.json (nivel principal)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (nivel principal)
  • Registro1.pdf (nivel principal)
  • Registro1/ (subcarpeta SOLO con metadatos genealógicos y técnicos)

2. PROCESAMIENTO Y DESCARGA DE IMÁGENES

────────────────────────────────────────────────────────────────────────────────

🎯 FLUJO DE PROCESAMIENTO

El flujo de trabajo de procesamiento consta de 3 pasos:

PASO 1: SELECCIONAR FORMATOS DE IMAGEN

─────────────────────────────────────

1. Carga un archivo de entrada (Archivo de entrada → Abrir entrada): la ventana de formatos se abre automáticamente

2. Como alternativa: haz clic en Menú → "Configuración" → "Seleccionar formatos de imagen"

3. Se abre un cuadro de diálogo con 3 opciones:

☐ PNG → Formato sin pérdida (lossless), mejor calidad, archivos más grandes

☐ JPG → Formato comprimido (con pérdida), buen compromiso entre calidad y tamaño

☐ TIFF → Formato de archivo, máxima calidad, archivos muy grandes

Documento PDF

☐ PDF → Genera un PDF completo con todas las páginas del registro o documento, además de los formatos de imagen seleccionados (o como única salida si no se selecciona ningún formato de imagen)

4. Selecciona al menos un formato de imagen o PDF (puedes elegir más de uno)

5. Haz clic en "Confirmar"

✅ Los formatos elegidos se guardan y se preseleccionan automáticamente la próxima vez que se abre el programa.

📝 CONSEJOS:

  • Para vista previa/consulta: JPG (rápido de abrir, ocupa menos espacio)
  • Para archivo de conservación: PNG (sin pérdida, compromiso de espacio) o TIFF (máxima calidad)
  • Para ambos: selecciona tanto PNG como TIFF
  • Para PDF: selecciona PDF junto con uno o varios formatos de imagen, o selecciona solo PDF para generar exclusivamente el documento PDF sin archivos de imagen separados

PASO 2: SELECCIONAR CARPETAS DE SALIDA

──────────────────────────────────────

1. La ventana de carpetas se abre automáticamente después de elegir los formatos (cuando cargas un archivo de entrada)

2. Como alternativa: haz clic en Menú → "Configuración" → "Seleccionar carpeta de salida"

3. Elige el MODO de organización de las carpetas:

⬤ Una sola carpeta para todos → una única carpeta para todos los elementos (documentos y registros)

⬤ Carpetas separadas para documentos/registros → una carpeta para todos los documentos y otra para todos los registros

⬤ Una carpeta para cada elemento → una carpeta distinta para cada elemento del archivo de entrada

4. Después de elegir el modo, selecciona las carpetas solicitadas (1, 2 o N cuadros de diálogo)

5. Al finalizar, se muestra un resumen de las carpetas elegidas

✅ Los modos y las carpetas se guardan. La próxima vez que se abra un archivo de entrada, se restaurarán automáticamente si son compatibles con el número de registros.

⚠️ Si el nuevo archivo de entrada tiene un número de documentos/registros distinto del correspondiente a las carpetas guardadas, se muestra una advertencia y se restablece la selección para solicitar nuevas carpetas.

🛡️ Comprobación preventiva de rutas: antes de crear carpetas o archivos, ATK-Pro comprueba los nombres y las rutas previstos. Los nombres incompatibles con Windows y los segmentos de ruta excesivamente largos bloquean únicamente el registro afectado; las advertencias de compatibilidad se muestran en el resumen final.

☁️ No se presupone que OneDrive/SharePoint sea el destino predeterminado. Sus límites específicos solo se aplican cuando la carpeta seleccionada se encuentra realmente bajo una raíz de OneDrive. En las demás rutas, el umbral histórico de Windows de 260 caracteres se considera una advertencia preventiva y no un bloqueo automático.

📌 RESUMEN DE MODOS:

  • Carpeta única: Sencillo, todo en un mismo lugar. Adecuado para procesamientos rápidos o pruebas
  • Documentos/registros separados: Organización por tipo. Valor predeterminado: output/doc/ y output/reg/
  • Para cada registro: Máxima flexibilidad. Puedes usar unidades distintas, NAS y carpetas personalizadas

PASO 3: INICIAR PROCESAMIENTO

─────────────────────────────

1. Haz clic en Menú → "Salida" → "Procesar"

2. Verifica que:

✓ Al menos 1 formato de imagen seleccionado

✓ Al menos 1 registro cargado

Si faltan estos requisitos, aparece un mensaje de error:

❌ "Ningún formato seleccionado" → Ve al PASO 1

❌ "Ningún registro cargado" → Ve a Carga de entrada (Sección 1)

📺 VENTANA DE PROCESAMIENTO

En cuanto hagas clic en "Procesar", se abrirá una ventana modal con:

📊 ELEMENTOS VISIBLES:

1️⃣ TÍTULO DE LA VENTANA: "Procesamiento en curso"

  • Permanece en primer plano hasta que finaliza el procesamiento
  • No puedes interactuar con el resto de la GUI

2️⃣ ETIQUETA DE PROGRESO: "Procesando registro: 2/5 — Nombre del archivo"

  • Muestra: el registro que se está procesando actualmente (2) del total (5)
  • También muestra el nombre del archivo/registro que se está procesando
  • Se actualiza en tiempo real a medida que se procesan los registros
  • Ej.: "Procesando registro: 1/3 — Registro de matrimonios de 1850"

3️⃣ BARRA DE PROGRESO: Avance visual

  • Formato numérico: "2/5" (número actual / total)
  • Barra de color que avanza de izquierda a derecha
  • Alcanza el 100% (anchura máxima) cuando se completa
  • NO muestra un porcentaje, solo el número

4️⃣ BOTÓN [CANCELAR]

  • Se puede pulsar durante el procesamiento
  • Solicita la interrupción de todo el lote y cierra la ventana de progreso
  • La detención es cooperativa: puede esperar a que finalice la solicitud de red individual que ya esté en curso
  • No se publica ningún resultado de la sesión cancelada en la carpeta seleccionada; los archivos preexistentes permanecen sin cambios

🔄 DURANTE EL PROCESAMIENTO

El programa en segundo plano:

├─ Descarga imágenes de los servidores IIIF
├─ Lee los manifiestos por ID de canvas
├─ Reconstruye las teselas para formar imágenes completas
├─ Convierte las imágenes a los formatos seleccionados (PNG, JPG, TIFF)
└─ Las guarda en las carpetas elegidas

La GUI muestra el progreso en tiempo real:

  • Cada 2-3 segundos actualiza el número de registros
  • Sin bloqueos: la interfaz permanece receptiva
  • Puedes cancelar en cualquier momento

⚠️ COMPORTAMIENTO SI HACES CLIC EN CANCELAR:

1. Se solicita la detención cooperativa de todo el lote

2. Se eliminan todos los archivos temporales de salida generados por el lote cancelado

3. Los archivos que ya estaban en las carpetas de salida antes del inicio permanecen sin cambios

4. Puedes volver a empezar desde Menú → Salida → Procesar

📋 PDF — GENERACIÓN AUTOMÁTICA DURANTE EL PROCESAMIENTO

Si has seleccionado PDF en la pantalla de selección de formatos (PASO 1), el PDF se genera automáticamente al finalizar la descarga de cada registro o documento, sin ninguna ventana de confirmación adicional.

📌 COMPORTAMIENTO:

  • ✅ PDF seleccionado en la pantalla de formatos: el PDF se genera automáticamente al finalizar la descarga; no se solicita ninguna confirmación adicional
  • ❌ PDF no seleccionado: solo se generan las imágenes en los formatos elegidos, sin ningún PDF

Características del PDF generado:

  • Nombre del archivo: [nombre].pdf, sin sufijos adicionales (p. ej. Registro Matrimonios 1920.pdf)
  • Se guarda en la carpeta de salida elegida, al mismo nivel que las imágenes
  • Páginas en orden numérico ascendente (canvas 1 → canvas 2 → … → canvas N)
  • Si no se puede descargar un canvas, se inserta una página marcador de posición localizada, con un enlace directo al canvas original en Antenati
  • Al finalizar la generación, no queda ningún archivo temporal en la carpeta de salida

⚠️ QUÉ NO HACER DURANTE EL PROCESAMIENTO:

  • ❌ No cierres el programa (se perderán los archivos parciales)
  • ❌ No desconectes el disco externo (se producirá un error al guardar)
  • ❌ No apagues el PC/portátil
  • ❌ No desconectes la conexión a internet (se interrumpirá la descarga)

✅ QUÉ PUEDES HACER:

  • ✓ Esperar a que termine (es el procedimiento normal)
  • ✓ Hacer clic en Cancelar si es urgente
  • ✓ Usar el PC normalmente para otras tareas (solo tienes que minimizar la ventana)

🎉 FIN DEL PROCESAMIENTO

Cuando se hayan procesado todos los registros:

1. La ventana de progreso se cierra automáticamente

2. Aparece un mensaje: "Operación completada"

3. Haz clic en Aceptar para cerrar el mensaje

4. La ventana de progreso desaparece por completo

Después:

  • Visualiza los archivos de salida en las carpetas que seleccionaste en el PASO 2
  • Cada documento/registro conserva una subcarpeta dedicada a sus metadatos dentro de la carpeta que elegiste; las imágenes y el PDF permanecen en el nivel principal
  • Las imágenes están listas para su uso (visualización, impresión, archivado, PDF)

✅ SALIDA GENERADA:

Por cada registro procesado encontrarás:

  • Imágenes en los formatos seleccionados (PNG, JPG, TIFF)
  • manifest_[ID]_[nombre].json → Manifiesto IIIF original con metadatos estructurados
  • [nombre]_genealogico.json → Metadatos genealógicos (fechas, lugares, nombres, municipios, provincias)
  • [nombre]_tecnico.json → Metadatos técnicos (número de canvas, lista de ID de canvas, derechos, archivos generados)
  • [nombre].json → Archivo complementario JSON para cada imagen (metadatos EXIF integrados)

📝 NOTA SOBRE LOS NOMBRES DE ARCHIVO:

  • El [nombre] base se toma directamente del archivo input.txt (línea introducida por el usuario)
  • Si escribes "Registro Matrimonios 1920" en el archivo de entrada, los archivos serán:
    • Registro Matrimonios 1920_canvas_1.jpg
    • Registro Matrimonios 1920_genealogico.json
    • Registro Matrimonios 1920_tecnico.json
  • Los sufijos JSON _genealogico y _tecnico permanecen sin cambios por compatibilidad
  • Puedes usar nombres en cualquier idioma en el archivo de entrada (IT, EN, mixto)

3. PDF PARA REGISTROS Y DOCUMENTOS

────────────────────────────────────────────────────────────────────────────────

CÓMO ACTIVAR LA GENERACIÓN DE PDF

La generación del PDF se activa marcando la casilla PDF en la pantalla de selección de formatos (Menú → Configuración → "Seleccionar formatos de imagen").

Puedes combinar PDF con uno o varios formatos de imagen (p. ej., PDF + PNG), o seleccionar únicamente PDF para obtener exclusivamente el documento, sin archivos de imagen independientes.

📄 CARACTERÍSTICAS DEL PDF GENERADO

  • Nombre del archivo: el PDF se denomina simplemente [nombre].pdf, sin sufijos adicionales; por ejemplo, Registro Matrimonios 1920.pdf
  • Ubicación: se guarda en la carpeta de salida elegida, al mismo nivel que las imágenes: [carpeta_elegida]\[nombre].pdf
  • Orden de las páginas: las páginas siempre aparecen en orden numérico ascendente (canvas 1 → canvas 2 → … → canvas N), independientemente del orden en que se descarguen las teselas
  • Páginas de sustitución: si un canvas no está disponible (por un error de red o porque el recurso no está accesible temporalmente), se inserta automáticamente en su lugar una página marcador de posición localizada al idioma seleccionado. La página de sustitución contiene:
    • Un texto de aviso localizado (p. ej., "Imagen no disponible")
    • El enlace directo al canvas original en Antenati (https://antenati.cultura.gov.it/ark:/…), para poder consultar la fuente fácilmente
    De este modo, siempre se genera el PDF, con toda la información necesaria para completarlo en caso de que las imágenes no se hayan descargado.
  • Limpieza automática: los archivos temporales utilizados para generar el PDF se eliminan automáticamente al finalizar el proceso. En la carpeta de salida solo permanecen las imágenes en los formatos elegidos, el PDF final, los manifiestos y los metadatos

🚫 Si no se selecciona PDF:

  • Solo se descargan las imágenes en los formatos seleccionados
  • No se ha generado ningún PDF

4. 📌 FUNCIONALIDADES DISPONIBLES

El menú “Servicios” contiene las funciones operativas de la v3: búsqueda asistida por IA, visualización de imágenes, visualización de metadatos JSON, OCR avanzado, traducción de OCR y exportación GEDCOM.

1️⃣ BÚSQUEDA ASISTIDA POR IA ✅

Asistente para definir estrategias de investigación genealógica:

  • Convierte apellidos, lugares, períodos y objetivos en líneas de investigación
  • Sugiere portales, filtros y consultas de ejemplo que deben verificarse manualmente
  • Admite escenarios italianos, italófonos, migratorios e internacionales
  • Permite añadir notas personales, comparar varios proveedores y guardar los resultados

Estado: ✅ Disponible – Véase la Guía de búsqueda asistida por IA

2️⃣ VISUALIZACIÓN DE IMÁGENES ✅

Visor integrado de imágenes genealógicas:

  • Formatos compatibles: JPG, PNG, TIFF (incluidos archivos TIFF de varias páginas con navegación hacia delante y hacia atrás)
  • Zoom mediante la rueda del ratón y botones específicos
  • Desplazamiento panorámico arrastrando con el ratón
  • Modos “Ajustar a la ventana” y “1:1 píxel”
  • Archivo JSON complementario junto a la imagen (EXIF y metadatos técnicos)

Estado: ✅ Disponible – Véase la Guía de visualización de imágenes

3️⃣ VISUALIZACIÓN DE METADATOS JSON ✅

Visor en árbol de metadatos estructurados:

  • Apertura directa de archivos _genealogico.json e _tecnico.json
  • Visualización en árbol desplegable
  • Secciones: datos genealógicos, metadatos técnicos y EXIF de las imágenes
  • Vista previa de la imagen asociada junto al panel de metadatos

Estado: ✅ Disponible – Véase la Guía de visualización de metadatos JSON

4️⃣ OCR AVANZADO ✅

Procesamiento OCR avanzado mediante LLM Vision:

  • Extracción de texto de documentos antiguos (incluidos manuscritos en italiano del siglo XIX y en latín)
  • Conservación de la estructura y de las referencias de maquetación (TEI XML)
  • Reconocimiento y depuración automáticos de datos estructurados (p. ej., tablas y roles)
  • Extracción de entidades (nombres, fechas y relaciones) en un formato JSON navegable

Estado: ✅ Disponible – Véase la Guía de OCR avanzado

5️⃣ TRADUCCIÓN OCR ✅

Traducción contextual de los textos extraídos o transcritos:

  • Traducción de textos OCR, transcripciones manuales y archivos TXT
  • Uso de tipos de documentos, glosario y contexto
  • Proveedor de IA configurable, modelo opcional y almacén seguro de claves
  • Salida en TXT o DOCX editable

Estado: ✅ Disponible – Ver la Guía de traducción OCR

5. CARPETAS Y ARCHIVOS DE SALIDA

────────────────────────────────────────────────────────────────────────────────

📂 ESTRUCTURA DE SALIDA

Cuando procesas un registro IIIF, ATK-Pro guarda los archivos en la carpeta que elegiste en el PASO 2 (Seleccionar carpeta de salida).

ESTRUCTURA ORGANIZADA POR REGISTROS:

[carpeta_salida]/
├─ manifest_[ID]_[nombre].json         ← Manifiesto IIIF original
├─ [nombre]_canvas_1.jpg/.png/.tif     ← Imágenes reconstruidas (una por página)
├─ [nombre]_canvas_2.jpg/.png/.tif
├─ [nombre]_canvas_N.jpg/.png/.tif     ← (N = número total de páginas/canvas)
├─ [nombre].json                       ← Archivo complementario JSON (sidecar) para cada imagen (EXIF)
├─ [nombre].pdf                        ← PDF completo (solo si se solicita)
└─ [nombre]/                           ← Subcarpeta SOLO para metadatos
   ├─ [nombre]_genealogico.json        ← Metadatos genealógicos
   └─ [nombre]_tecnico.json            ← Metadatos técnicos

MÚLTIPLES REGISTROS EN LA MISMA CARPETA:

Si procesas 3 registros en la misma carpeta, la estructura pasa a ser:

[carpeta_salida]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (archivo complementario)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (archivo complementario)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (archivo complementario)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

📌 NOTAS SOBRE LA ESTRUCTURA:

  • Manifiesto IIIF, imágenes, PDF y archivos complementarios JSON (sidecar): en el nivel principal
  • SOLO metadatos técnicos y genealógicos: en subcarpetas [nombre]/ (una por registro)
  • Las carpetas temporales (tiles_canvas_X/) y los archivos temporales utilizados para generar el PDF se eliminan automáticamente al finalizar el procesamiento: no queda ningún archivo de trabajo intermedio en la carpeta de salida
  • Esta organización permite gestionar múltiples registros en la misma carpeta sin confundir los archivos

📋 CONVENCIÓN DE NOMENCLATURA:

  • Manifiesto: manifest_[ID]_[nombre].json
  • Imágenes: [nombre]_canvas_1, [nombre]_canvas_2, ... [nombre]_canvas_N
  • Metadatos JSON: [nombre]_genealogico.json, [nombre]_tecnico.json
  • JSON de imágenes: [nombre].json (para cada canvas)
  • PDF: [nombre].pdf
