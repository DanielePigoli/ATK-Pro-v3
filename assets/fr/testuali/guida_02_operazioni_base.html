1. CHARGEMENT DES ENREGISTREMENTS - FORMATS D’ENTRÉE

────────────────────────────────────────────────────────────────────────────────

📥 STRUCTURE DE L’ENTRÉE ET PORTAILS PRIS EN CHARGE

ATK-Pro accepte des fichiers d’entrée dans un format spécifique fondé sur des PAIRES : pour CHAQUE enregistrement à traiter, fournissez le mode + l’URL.

Portails pris en charge : copiez et collez l’URL publique de la page, du visualiseur, du manifeste ou du PDF compatible. ATK-Pro reconnaît le portail et applique le mode technique et les précautions correspondantes.

Pris en charge indique une compatibilité technique vérifiée, et non une autorisation générale de téléchargement. La ressource doit être accessible au public et l’utilisateur doit respecter les droits, les licences, les conditions d’utilisation et les limites propres à chaque portail. ATK-Pro ne contourne pas les connexions, les accès affiliés, les paywalls ou les marqueurs nodownload.

Antenati (Italie), Gallica (France), DigiVatLib (Vatican), Bodleian Libraries (Oxford), Europeana IIIF, Matricula Online, Findbuch (Tyrol du Sud), e-codices/e-rara/e-manuscripta (Suisse), Heidelberg UB, Internet Culturale/Estense, Brixiana, Memooria, BNC Roma, BNCF Teca, Museo Galileo et Internet Archive.

1. LIGNE 1 : Mode + Nom (facultatif)

  • D = Document unique (une seule image/page)
  • R = Registre (collection complète de pages/documents)

2. LIGNE 2 : URL publique de la notice ou de la ressource

Exemple de fichier input.txt correctement formaté :

# Les commentaires commencent par #

ENREGISTREMENT 1 (paire de lignes) :
D - Lettre importante
https://biblioteca.example.org/iiif/doc123/manifest.json

ENREGISTREMENT 2 (paire de lignes) :
R - Registre administratif 1920-1925
https://archives.example.org/iiif/reg456/manifest.json

ENREGISTREMENT 3 (paire de lignes) :
D - Photographie unique
https://collections.example.org/iiif/foto789/manifest.json

📝 RÈGLES DE FORMATAGE DES DONNÉES D’ENTRÉE :

  • Lignes vides : ignorées (vous pouvez les utiliser pour améliorer la lisibilité)
  • Lignes contenant # : ignorées en tant que commentaires
  • Modes D/d ou R/r : obligatoires ; les majuscules et les minuscules sont équivalentes
  • Nom du fichier : facultatif après le mode (par exemple « D - Nom » ou simplement « D »)
  • URL : doit commencer par http:// ou https://
  • Paires : le mode et l’URL doivent figurer sur deux lignes consécutives

⚙️ COMMENT CHARGER LES DONNÉES D’ENTRÉE — 3 OPTIONS DU MENU :

OPTION 1 : Afficher un exemple de données d’entrée ──────────────────────────────────────

1. Cliquez sur Menu → « Fichier d’entrée » → « Exemple d’entrée »

2. Une fenêtre s’ouvre et affiche le fichier d’exemple localisé

3. Vous pouvez copier son contenu et l’utiliser comme modèle pour votre fichier d’entrée

4. Fichier d’exemple : assets/[lingua]/testuali/input_link_base.txt

Remarque concernant le nom du fichier : le fichier distribué s’appelle input_link_base.txt. Son nom a été normalisé dans la v3 afin d’éviter toute référence aux versions précédentes ; le format reste compatible avec le chargement des notices IIIF.

OPTION 2 : Ouvrir un fichier d’entrée prêt à l’emploi ──────────────────────────────────────

1. Cliquez sur Menu → « Fichier d’entrée » → « Ouvrir l’entrée »

2. Une boîte de dialogue de sélection de fichier s’ouvre

3. Sélectionnez votre fichier input.txt (il doit respecter le format par paires)

4. ATK-Pro charge et lit automatiquement toutes les notices

5. Affiche le nombre de notices chargées et prêtes à être traitées

OPTION 3 : Modifier une entrée déjà chargée ──────────────────────────────────────────

1. Après avoir chargé un fichier d’entrée (OPTION 2)

2. Cliquez sur Menu → « Fichier d’entrée » → « Modifier l’entrée »

3. Un éditeur de texte s’ouvre avec le fichier actuellement chargé

4. Modifiez les paires (ajoutez, supprimez ou changez les URL)

5. Cliquez sur « Enregistrer » pour mettre à jour les enregistrements en cours de traitement

6. Le programme réinterprète le fichier mis à jour

📌 DIFFÉRENCE ENTRE D ET R :

  • D (Document) : Gère une seule image/page
  • → Sortie : un seul fichier pour le document
  • R (Registre) : Gère les collections de plusieurs pages
  • → Sortie : dossier contenant les pages organisées + PDF (si l’utilisateur le demande)

✅ VALIDATION DES ENREGISTREMENTS

Après le chargement, le programme vérifie :

  • ✓ URL accessible et joignable
  • ✓ Ressource compatible : manifeste IIIF v2/v3, page prise en charge, image ou PDF direct selon le portail
  • ✓ Nombre d’images et de canevas disponibles
  • ✓ Métadonnées (titre, auteur, date)

❌ ERREURS COURANTES

  • « URL non valide » : Vérifiez que l’URL a été correctement copiée et collée
  • « Manifeste introuvable (404) » : L’URL a expiré ou est incorrecte
  • « Format IIIF non pris en charge » : Le serveur n’utilise pas le standard IIIF
  • « Délai de connexion dépassé » : Connexion Internet lente ou absente

💾 ENREGISTREMENT DES ENREGISTREMENTS

Après le chargement du manifeste, le programme enregistre automatiquement les métadonnées IIIF. EMPLACEMENT : dans le dossier de sortie que vous choisissez (voir Section 2, ÉTAPE 2) STRUCTURE DES DOSSIERS APRÈS LE CHARGEMENT (avant le traitement) :

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifeste IIIF original (niveau principal)
 └─ [nome]/                            ← Sous-dossier réservé UNIQUEMENT aux métadonnées
    ├─ [nome]_genealogico.json        ← Métadonnées généalogiques extraites
    └─ [nome]_tecnico.json            ← Métadonnées techniques (ID du canevas, nombre de pages)

APRÈS LE TRAITEMENT (lorsque vous cliquez sur Menu → Sortie → Traiter) : les fichiers traités sont ajoutés au niveau principal :

[cartella_output]/
 ├─ manifest_[ID]_[nome].json         ← Manifeste IIIF original
 ├─ [nome]_canvas_1.jpg/.png/.tif     ← Images reconstituées à partir des tuiles IIIF (une par page)
 ├─ [nome]_canvas_2.jpg/.png/.tif       (le format dépend de celui qui a été sélectionné)
 ├─ [nome]_canvas_N.jpg/.png/.tif       (N = nombre total de pages/canevas)
 ├─ [nome].json                        ← Fichier JSON associé à chaque image (métadonnées EXIF)
 └─ [nome].pdf                         ← PDF complet (voir l’explication ci-dessous)

Les métadonnées restent dans le sous-dossier [nome]/ telles qu’elles ont été enregistrées lors du chargement.

REMARQUE IMPORTANTE : organisation des fichiers

  • Manifeste IIIF : niveau principal du dossier de sortie
  • Images (canevas), PDF, fichiers JSON associés : niveau principal du dossier de sortie
  • UNIQUEMENT les métadonnées techniques et généalogiques : enregistrées dans le sous-dossier [nome]/
  • Les dossiers temporaires (tiles_canvas_X/) sont automatiquement supprimés à la fin
  • Cette structure permet de gérer plusieurs enregistrements dans le même dossier sans confusion

Exemple : Si vous traitez « Registro1 », vous trouverez :

  • manifest_[ID1]_Registro1.json (niveau principal)
  • Registro1_canvas_1.jpg, Registro1_canvas_2.jpg, ... (niveau principal)
  • Registro1.pdf (niveau principal)
  • Registro1/ (sous-dossier contenant UNIQUEMENT les métadonnées généalogiques et techniques)

2. TRAITEMENT ET TÉLÉCHARGEMENT DES IMAGES

────────────────────────────────────────────────────────────────────────────────

🎯 FLUX DE TRAITEMENT

Le processus de traitement comprend 3 étapes :

ÉTAPE 1 : SÉLECTIONNER LES FORMATS D’IMAGE

─────────────────────────────────────

1. Chargez un fichier d’entrée (Fichier d’entrée → Ouvrir l’entrée) : la fenêtre des formats s’ouvre automatiquement

2. Autre possibilité : cliquez sur Menu → « Paramètres » → « Sélectionner les formats d’image »

3. Une boîte de dialogue s’ouvre avec 3 options :

☐ PNG → Format sans perte (lossless), meilleure qualité, fichiers plus volumineux

☐ JPG → Format compressé (avec perte), bon compromis entre qualité et taille

☐ TIFF → Format d’archivage, qualité maximale, fichiers très volumineux

Document PDF

☐ PDF → Génère un PDF complet contenant toutes les pages du registre ou du document, en plus des formats d’image sélectionnés (ou comme seule sortie si aucun format d’image n’est sélectionné)

4. Sélectionnez au moins un format d’image ou PDF (vous pouvez en choisir plusieurs)

5. Cliquez sur « Confirmer »

✅ Les formats choisis sont mémorisés et automatiquement présélectionnés lors de la prochaine ouverture du programme.

📝 CONSEILS :

  • Pour l’aperçu/la consultation : JPG (ouverture rapide, moins d’espace occupé)
  • Pour l’archivage à long terme : PNG (sans perte, bon compromis en matière d’espace) ou TIFF (qualité maximale)
  • Pour les deux : sélectionnez à la fois PNG et TIFF
  • Pour PDF : sélectionnez PDF avec un ou plusieurs formats d’image, ou sélectionnez uniquement PDF pour générer exclusivement le document PDF, sans fichiers image distincts

ÉTAPE 2 : SÉLECTIONNER LES DOSSIERS DE SORTIE

──────────────────────────────────────

1. La fenêtre des dossiers s’ouvre automatiquement après le choix des formats (lorsque vous chargez un fichier d’entrée)

2. Autre possibilité : cliquez sur Menu → « Paramètres » → « Sélectionner les dossiers de sortie »

3. Choisissez le MODE d’organisation des dossiers :

⬤ Dossier unique pour tous → un seul dossier pour tous les enregistrements (documents et registres)

⬤ Dossiers séparés pour les documents/registres → un dossier pour tous les documents et un autre pour tous les registres

⬤ Un dossier pour chaque enregistrement → un dossier distinct pour chaque enregistrement du fichier d’entrée

4. Après avoir choisi le mode, sélectionnez les dossiers requis (1, 2 ou N boîtes de dialogue)

5. À la fin, un récapitulatif des dossiers choisis s’affiche

✅ Le mode et les dossiers sont mémorisés. Lors de la prochaine ouverture d’un fichier d’entrée, elles sont automatiquement restaurées si elles sont compatibles avec le nombre d’enregistrements.

⚠️ Si le nouveau fichier d’entrée comporte un nombre de Documents/Registres différent de celui des dossiers enregistrés, un avertissement s’affiche et la sélection est réinitialisée afin de demander de nouveaux dossiers.

🛡️ Vérification préalable des chemins : avant de créer des dossiers ou des fichiers, ATK-Pro vérifie les noms et les chemins prévus. Les noms incompatibles avec Windows et les segments de chemin excessivement longs bloquent uniquement l’enregistrement concerné ; les avertissements de compatibilité sont affichés dans le récapitulatif final.

☁️ OneDrive/SharePoint n’est pas considéré comme la destination par défaut. Les limites qui lui sont propres ne sont appliquées que lorsque le dossier sélectionné se trouve effectivement sous une racine OneDrive. Pour les autres chemins, le seuil Windows historique de 260 caractères est traité comme un avertissement de prudence et non comme un blocage automatique.

📌 RÉCAPITULATIF DES MODES :

  • Dossier unique : Simple, tout au même endroit. Adapté aux traitements rapides ou aux tests
  • Documents/registres séparés : Organisation par type. Par défaut : output/doc/ et output/reg/
  • Pour chaque enregistrement : Flexibilité maximale. Vous pouvez utiliser différents lecteurs, des NAS ou des dossiers personnalisés

ÉTAPE 3 : LANCER LE TRAITEMENT

─────────────────────────────

1. Cliquez sur Menu → « Sortie » → « Traiter »

2. Vérifiez que :

✓ Au moins 1 format d’image est sélectionné

✓ Au moins 1 enregistrement est chargé

Si ces conditions ne sont pas remplies, un message d’erreur s’affiche :

❌ « Aucun format sélectionné » → Allez à l’ÉTAPE 1

❌ « Aucun enregistrement chargé » → Allez à Chargement des données d’entrée (Section 1)

📺 FENÊTRE DE TRAITEMENT

Dès que vous cliquez sur « Traiter », une fenêtre modale s’ouvre avec les éléments suivants :

📊 ÉLÉMENTS VISIBLES :

1️⃣ TITRE DE LA FENÊTRE : « Traitement en cours »

  • Elle reste au premier plan jusqu’à la fin du traitement
  • Vous ne pouvez pas interagir avec le reste de l’interface graphique

2️⃣ LIBELLÉ DE PROGRESSION : « Traitement de l’enregistrement : 2/5 — Nom du fichier »

  • Affiche : l’enregistrement en cours de traitement (2) sur le total (5)
  • Affiche également le nom du fichier/registre en cours de traitement
  • Se met à jour en temps réel à mesure que les enregistrements sont traités
  • Ex. : « Traitement de l’enregistrement : 1/3 — Registre des mariages 1850 »

3️⃣ BARRE DE PROGRESSION : progression visuelle

  • Format numérique : « 2/5 » (numéro actuel / total)
  • Barre colorée progressant de gauche à droite
  • Atteint 100 % (largeur maximale) une fois le traitement terminé
  • N’affiche PAS de pourcentage, uniquement le nombre

4️⃣ BOUTON [ANNULER]

  • Cliquable pendant le traitement
  • Demande l’interruption de l’ensemble du lot et ferme la fenêtre de progression
  • L’arrêt est coopératif : il peut attendre la fin de la requête réseau individuelle déjà en cours
  • Aucune sortie de la session annulée n’est publiée dans le dossier choisi ; les fichiers préexistants restent inchangés

🔄 PENDANT LE TRAITEMENT

Le programme en arrière-plan :

├─ Télécharge des images depuis les serveurs IIIF
├─ Lit les manifestes pour obtenir les identifiants des canevas
├─ Reconstitue les tuiles en images complètes
├─ Convertit les images dans les formats sélectionnés (PNG, JPG, TIFF)
└─ Les enregistre dans les dossiers choisis

L’interface graphique affiche la progression en temps réel :

  • Le nombre d’enregistrements est mis à jour toutes les 2-3 secondes
  • Aucun blocage : l’interface reste réactive
  • Vous pouvez annuler à tout moment

⚠️ COMPORTEMENT SI VOUS CLIQUEZ SUR ANNULER :

1. L’arrêt coopératif de l’ensemble du lot est demandé

2. Tous les fichiers de sortie temporaires produits par le lot annulé sont supprimés

3. Les fichiers déjà présents dans les dossiers de sortie avant le démarrage restent inchangés

4. Vous pouvez recommencer depuis Menu → Sortie → Traiter

📋 PDF — GÉNÉRATION AUTOMATIQUE PENDANT LE TRAITEMENT

Si vous avez sélectionné PDF dans la fenêtre de sélection des formats (ÉTAPE 1), le PDF est généré automatiquement à la fin du téléchargement de chaque registre ou document, sans aucune fenêtre de confirmation supplémentaire.

📌 COMPORTEMENT :

  • ✅ PDF sélectionné dans la fenêtre des formats : le PDF est généré automatiquement à la fin du téléchargement ; aucune confirmation supplémentaire n’est demandée
  • ❌ PDF non sélectionné : uniquement les images dans les formats choisis, aucun PDF

Caractéristiques du PDF généré :

  • Nom du fichier : [nome].pdf, sans suffixes supplémentaires (par ex. Registro Matrimoni 1920.pdf)
  • Enregistré dans le dossier de sortie choisi, au même niveau que les images
  • Pages classées par ordre numérique croissant (canevas 1 → canevas 2 → … → canevas N)
  • Si un canevas ne peut pas être téléchargé, une page de remplacement localisée est insérée, avec un lien direct vers le canevas original sur Antenati
  • Aucun fichier temporaire ne reste dans le dossier de sortie une fois la génération terminée

⚠️ CE QU’IL NE FAUT PAS FAIRE PENDANT LE TRAITEMENT :

  • ❌ Ne fermez pas le programme (les fichiers partiels seraient perdus)
  • ❌ Ne débranchez pas le disque externe (erreur d’enregistrement)
  • ❌ N’éteignez pas le PC/ordinateur portable
  • ❌ Ne coupez pas la connexion Internet (cela interrompt le téléchargement)

✅ CE QUE VOUS POUVEZ FAIRE :

  • ✓ Attendre la fin du traitement (c’est la procédure normale)
  • ✓ Cliquer sur Annuler en cas d’urgence
  • ✓ Utiliser normalement le PC pour d’autres tâches (il suffit de réduire la fenêtre)

🎉 FIN DU TRAITEMENT

Lorsque tous les enregistrements ont été traités :

1. La fenêtre de progression se ferme automatiquement

2. Un message apparaît : « Opération terminée »

3. Cliquez sur OK pour fermer le message

4. La fenêtre de progression disparaît complètement

Après :

  • Consultez les fichiers de sortie dans les dossiers que vous avez sélectionnés à l’ÉTAPE 2
  • Chaque document/registre possède son propre sous-dossier dans le dossier que vous avez choisi
  • Les images sont prêtes à l’emploi (visualisation, impression, archivage, PDF)

✅ SORTIE GÉNÉRÉE :

Pour chaque enregistrement traité, vous trouverez :

  • Des images dans les formats sélectionnés (PNG, JPG, TIFF)
  • manifest_[ID]_[nome].json → Manifeste IIIF original avec des métadonnées structurées
  • [nome]_genealogico.json → Métadonnées généalogiques (dates, lieux, noms, communes, provinces)
  • [nome]_tecnico.json → Métadonnées techniques (nombre de canevas, liste des ID de canevas, droits, fichiers générés)
  • [nome].json → Fichier JSON annexe pour chaque image (métadonnées EXIF intégrées)

📝 REMARQUE SUR LES NOMS DE FICHIERS :

  • Le [nome] de base est directement repris du fichier input.txt (ligne saisie par l’utilisateur)
  • Si vous écrivez « Registro Matrimoni 1920 » dans le fichier d’entrée, les fichiers seront :
    • Registro Matrimoni 1920_canvas_1.jpg
    • Registro Matrimoni 1920_genealogico.json
    • Registro Matrimoni 1920_tecnico.json
  • Les suffixes JSON restent en anglais (_genealogico, _tecnico) pour des raisons de compatibilité
  • Vous pouvez utiliser des noms dans n’importe quelle langue dans le fichier d’entrée (IT, EN ou mixte)

3. PDF POUR LES REGISTRES ET LES DOCUMENTS

────────────────────────────────────────────────────────────────────────────────

COMMENT ACTIVER LA GÉNÉRATION DU PDF

La génération du PDF s’active en cochant la case PDF dans la fenêtre de sélection des formats (Menu → Paramètres → « Sélectionner les formats d’image »).

Vous pouvez combiner le PDF avec un ou plusieurs formats d’image (par ex. PDF + PNG), ou sélectionner uniquement PDF afin d’obtenir exclusivement le document, sans fichiers image distincts.

📄 CARACTÉRISTIQUES DU PDF GÉNÉRÉ

  • Nom du fichier : le PDF porte simplement le nom [nome].pdf, sans suffixes supplémentaires — par exemple Registro Matrimoni 1920.pdf
  • Emplacement : enregistré dans le dossier de sortie choisi, au même niveau que les images : [cartella_scelta]\[nome].pdf
  • Ordre des pages : les pages sont toujours classées par ordre numérique croissant (canevas 1 → canevas 2 → … → canevas N), quel que soit l’ordre dans lequel les tuiles sont téléchargées
  • Pages de substitution : si un canevas n’est pas disponible (erreur réseau ou ressource temporairement inaccessible), une page est automatiquement insérée à sa place de remplacement localisée dans la langue sélectionnée. La page de substitution contient :
    • Un message d’avertissement localisé (par ex. « Image indisponible »)
    • Le lien direct vers le canevas original sur Antenati (https://antenati.cultura.gov.it/ark:/…), afin de pouvoir consulter facilement la source
    De cette manière, le PDF est toujours généré, avec toutes les informations nécessaires pour le compléter si certaines images n’ont pas été téléchargées.
  • Nettoyage automatique : les fichiers temporaires utilisés pour générer le PDF sont automatiquement supprimés à la fin du processus. Le dossier de sortie ne contient plus que les images dans les formats choisis, le PDF final, les manifestes et les métadonnées

🚫 Si PDF n’est pas sélectionné :

  • Seules les images sont téléchargées dans les formats sélectionnés
  • Aucun PDF généré

4. 📌 FONCTIONNALITÉS DISPONIBLES

Le menu « Services » contient les fonctions opérationnelles de la v3 : recherche assistée par IA, visualisation des images, visualisation des métadonnées JSON, OCR avancé, traduction OCR et exportation GEDCOM.

1️⃣ RECHERCHE ASSISTÉE PAR IA ✅

Assistant permettant de définir des stratégies de recherche généalogique :

  • Transforme les noms de famille, les lieux, les périodes et les objectifs en pistes de recherche
  • Suggère des portails, des filtres et des exemples de requêtes à vérifier manuellement
  • Prend en charge les contextes italiens, italophones, migratoires et internationaux
  • Permet d’ajouter des notes personnelles, de comparer plusieurs fournisseurs et d’enregistrer les résultats

Statut : ✅ Disponible – Voir le guide de la recherche assistée par IA

2️⃣ VISUALISATION DES IMAGES ✅

Visionneuse intégrée pour les images généalogiques :

  • Formats pris en charge : JPG, PNG, TIFF (y compris les fichiers TIFF multipages, avec navigation avant/arrière)
  • Zoom à l’aide de la molette de la souris et de boutons dédiés
  • Déplacement panoramique en faisant glisser la souris
  • Modes « Ajuster à la fenêtre » et « 1:1 pixel »
  • Fichier annexe JSON affiché à côté de l'image (EXIF et métadonnées techniques)

Statut : ✅ Disponible – Voir le guide de visualisation des images

3️⃣ VISUALISATION DES MÉTADONNÉES JSON ✅

Visionneuse arborescente pour les métadonnées structurées :

  • Ouverture directe des fichiers _genealogico.json et _tecnico.json
  • Affichage sous forme d’arborescence déployable
  • Sections : données généalogiques, métadonnées techniques, données EXIF extraites des images
  • Aperçu de l’image associée affiché à côté du panneau des métadonnées

Statut : ✅ Disponible – Voir le guide de visualisation des métadonnées JSON

4️⃣ OCR AVANCÉ ✅

Traitement OCR avancé au moyen d’un LLM doté de capacités visuelles :

  • Extraction de texte à partir de documents anciens (y compris des manuscrits en italien du XIXe siècle et en latin)

5. DOSSIERS ET FICHIERS DE SORTIE

────────────────────────────────────────────────────────────────────────────────

📂 STRUCTURE DE SORTIE

Lorsque vous traitez un enregistrement IIIF, ATK-Pro enregistre les fichiers dans le dossier que vous avez choisi à l'ÉTAPE 2 (Sélectionner le dossier de sortie).

STRUCTURE ORGANISÉE PAR ENREGISTREMENT :

[cartella_output]/
├─ manifest_[ID]_[nome].json         ← Manifeste IIIF d'origine
├─ [nome]_canvas_1.jpg/.png/.tif     ← Images reconstituées (une par page)
├─ [nome]_canvas_2.jpg/.png/.tif
├─ [nome]_canvas_N.jpg/.png/.tif     ← (N = nombre total de pages/canevas)
├─ [nome].json                       ← Fichier sidecar JSON pour chaque image (EXIF)
├─ [nome].pdf                        ← PDF complet (uniquement sur demande)
└─ [nome]/                           ← Sous-dossier réservé UNIQUEMENT aux métadonnées
   ├─ [nome]_genealogico.json        ← Métadonnées généalogiques
   └─ [nome]_tecnico.json            ← Métadonnées techniques

PLUSIEURS ENREGISTREMENTS DANS LE MÊME DOSSIER :

Si vous traitez 3 enregistrements dans le même dossier, la structure devient :

[cartella_output]/
├─ manifest_[ID1]_Registro1.json
├─ Registro1_canvas_1.jpg
├─ Registro1_canvas_2.jpg
├─ Registro1.json (sidecar)
├─ Registro1.pdf
├─ Registro1/
│  ├─ Registro1_genealogico.json
│  └─ Registro1_tecnico.json
├─ manifest_[ID2]_Documento2.json
├─ Documento2_canvas_1.jpg
├─ Documento2.json (sidecar)
├─ Documento2.pdf
├─ Documento2/
│  ├─ Documento2_genealogico.json
│  └─ Documento2_tecnico.json
├─ manifest_[ID3]_Registro3.json
├─ Registro3_canvas_1.jpg
├─ Registro3_canvas_2.jpg
├─ Registro3.json (sidecar)
├─ Registro3.pdf
└─ Registro3/
    ├─ Registro3_genealogico.json
    └─ Registro3_tecnico.json

📌 REMARQUES SUR LA STRUCTURE :

  • Manifeste IIIF, images, PDF et fichiers sidecar JSON : au niveau principal
  • UNIQUEMENT les métadonnées techniques et généalogiques : dans des sous-dossiers [nome]/ (un par enregistrement)
  • Les dossiers temporaires (tiles_canvas_X/) et les fichiers temporaires utilisés pour générer le PDF sont automatiquement supprimés à la fin du traitement : aucun fichier de travail intermédiaire ne subsiste dans le dossier de sortie
  • Cette organisation permet de gérer plusieurs enregistrements dans le même dossier sans confusion entre les fichiers

📋 CONVENTION DE NOMMAGE :

  • Manifeste : manifest_[ID]_[nome].json
  • Images : [nome]_canvas_1, [nome]_canvas_2, ... [nome]_canvas_N
  • Métadonnées JSON : [nome]_genealogico.json, [nome]_tecnico.json
  • JSON des images : [nome].json (pour chaque canevas)
  • PDF : [nome].pdf
